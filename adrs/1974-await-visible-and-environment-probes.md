# ADR 1974: `awaitVisible` — wait for GitHub to reflect a harness write through the engine's own read path; environment probes before live spend

## Status

Accepted (#1974). Builds on ADR-1973 (the INCONCLUSIVE outcome, whose audit table this extends), ADR-1972 (the per-leg archive the probe results join) and ADR-1994 (the Go gate runner's `Preflight` and `Commander` seams). Consistent with ADR-1454: nothing here moves live coverage to the sim, and the pre-gate-spends-nothing rule is kept, not relaxed.

## Context

Most live-e2e races in the 0.0.83 gate were GitHub's eventual consistency. The harness wrote something — a board add, a PR opened with `Closes #N`, a Status move — and carried on as if every reader could already see it, while the engine reads through different paths that lag independently. `TestMergeTrainColdCacheBaseMember` seeded two members while the bed was down, and the bootstrap board fetch listed neither (the ProjectV2 item listing lagged the adds), so the cold-cache state it targets never existed; `TestCommentLandingGateHolds` placed its item while the PR's `mergeable` was still `null`. #1961, #1964 and #1982 each added a one-off wait of the same shape. A partial outage on 2026-09-30 stretched listing lag past five minutes, and the harness could not tell "not visible yet" from "the engine did something wrong".

The other environmental cause was host load (15–40 on the gate host: other projects' CI runners, and orphaned `sim.test` trees from killed workers, #1989), which produced sim timeouts and `-race` crashes. The run started anyway, with nothing reporting the load.

## Decision

### 1. One family, one loop, in an untagged package

`awaitvisible.Poll(Spec, Probe)` in `tests/e2e/awaitvisible` is the single polling and timeout implementation. Every file under `tests/e2e/` carries the `e2e` build tag and CI only compiles it, so a unit test placed there would never run on a PR; the loop and the pure classifiers (`ParseClosingLinkage`, `ClassifyMergeable`) live in an untagged package, as `tests/e2e/inconclusive` and `tests/e2e/registry` do. `Timeout` and `Interval` are explicit per call — the family hides no default, since the right bound differs by read path. A probe's read **error** is retried and never counted as "not visible"; the last observation and last error are kept for the timeout reason. `Abort(err)` stops at once for a state that will not resolve by waiting.

The tagged wrappers (`tests/e2e/await_visible.go`) bind `ghOutput` to a probe per fact and read through **the surface the engine consults**: the ProjectV2 `items(first:100)` connection for board item and Status; GraphQL `issue.closedByPullRequestsReferences` for the issue-side closing link; REST `/pulls/N` `.mergeable_state` for mergeability; the REST issue read for labels; REST `/pulls?head=` (as `FetchLinkedPR`) for the harness-opened PR. For the closing link the wrapper waits on **both** sides in one GraphQL call: the issue side is the engine's real read, and the PR side is GitHub's computed `pullRequest.closingIssuesReferences` the spec names. (The engine's own PR-side read, `FetchPRClosingIssues`, regex-parses the PR body and so cannot lag.) GraphQL waits poll every 10 s and REST waits every 5 s, because the suite and the bed engine share one GraphQL budget (#1695).

### 2. Lag versus engine effect: only lag is Inconclusive

Waiting for a **harness write** to become visible is lag: a timeout ends the test through `Inconclusive` (ADR-1973), and the reason names what was waited for, how long, how many reads and the last observation or error — never a silent pass. Waiting for the **engine** to do something is an assertion about engine behaviour and stays `t.Fatalf` (ADR-1973 §2): `WaitForProjectStatus` after the engine moves an item, `WaitForIssueLabel` for an engine-applied label, `LinkedPRNumber` for an engine-created PR, `WaitForCheckConclusion`, the `waitForLogMatch*` family. A blanket "any timeout → Inconclusive" would blur that line and let a retry turn an engine regression green.

Mergeability layers the #1982 verdict on a primitive: `AwaitPRMergeableComputed` waits for a computed (non-null) `mergeable`; `AwaitPRMergeableSettled` additionally accepts only `clean`/`unstable`, keeps waiting on `blocked`/`unknown`, and **fails fast** on `dirty`/`behind` with `t.Fatalf`, because that is a real statement about the scenario, not lag. Only the timeout is Inconclusive.

`Inconclusive` must end a top-level test from its own goroutine; from a subtest it is a loud `t.Fatalf` (ADR-1973 §1). Seed helpers called inside `t.Run` (`auto_merge_test.go`, `convergence_race_test.go`) therefore fail loudly on an await timeout rather than leaving an invisible marker; the decision is to document "seed at the top level" rather than restructure those tests, which this issue does not need.

### 3. Adoption is structural and pinned

`createMemberPR` is the single chokepoint every seed path reaches, so the closing-linkage wait lives there. The seeders (`QueueMember*`, `PrepareMemberExactPath`, `seedReviewGateItemImpl`, `seedLandingCandidate`) additionally await the harness-opened PR, the labels they apply and the board item they place. Against a **running** bed the seeders await the item's *presence* in the listing (`AwaitBoardItemVisible`), never a Status: the engine may move the item on within a poll, a lagging first read would then never see the awaited Status, and the wait would burn its whole timeout and end Inconclusive for a legitimate engine action. A listed item stays listed. `AwaitStatusVisible` is reserved for a bed that is down (ColdCache) or a Status the engine will not act on. `waitForClosingLinkage` and `WaitForPRMergeableSettled` are deleted, not kept as parallel copies. `tests/e2e/inconclusive/guards_test.go` pins statically that they stay gone, that each seed path calls the family and has no loop or sleep of its own, and that the new wrappers obey `Inconclusive`'s no-goroutine/no-subtest rule. The ColdCache test now awaits every seeded member (in `Queued`) and the primer in the board listing **before** starting the bed, so a cold-cache start is genuine; CommentLanding waits for settled mergeability before placing the item. Both keep their assertions after their guards. The neutralised-wait check (with the await stubbed out, both reproduce their old vacuous outcome, now Inconclusive) needs a live bed and is a manual note in the PR.

### 4. Environment probes in the gate runner's preflight

**Ordering.** The load probe is host-only and joins `DefaultPreflights` ahead of the pre-gate whose load-sensitive sim suite it protects. The lag probe is a **live GitHub write**, which ADR-1454 and `TestRunExitCode5PregateFailureSpendsNothing` forbid before the pre-gate passes, so it cannot join `Preflights`. A second ordered list, `Gate.LivePreflights`, runs in `run()` immediately after `RunPregate` and before `PrepareBedAndReset` — still before any bed build or start. The rule is preserved, not relaxed.

**Load probe.** Reuses `Gate.loadAvg` (the reading the leg archive already takes; no second parser) against `E2E_LOAD_PROBE_THRESHOLD`, else `E2E_LOAD_PROBE_FACTOR` (default 2) × CPU count. It also lists orphaned `sim.test`/`e2e.test`/`fabrik.test` processes whose parent is init, with their working directory through the existing `ResolvePIDCwd`. The listing is best-effort per OS (a Linux orphan may re-parent to a per-user subreaper; `comm` may be truncated; an unresolvable cwd is `unknown`) and informational — it never gates.

**Lag probe.** Adds a temporary **draft** project item to the bed's own board, times it until it appears in the same `items` listing, and removes it on success, timeout, error and cancel (on a context detached from the cancelled one). Rejected: a real issue — it cannot be deleted with the bed PAT, so each run would leave a closed issue behind, and a probe must not leave an artifact the next run's stale-artifact checks (`staleQueuedMembers`, `WaitForNoStaleTrainArtifacts`, which look at Queued *issues*) could trip on. A draft is fully self-cleaning and creates no repository issue. Items carry a title prefix, and a leftover from a SIGKILL mid-probe is swept at the start of the next run. Every `gh` call follows `budget.go`'s required routing shape (`Commander`, `Session`, `Timeout: GHAPITimeout`, `GH_TOKEN` scoped to the bed token), and the project comes from `resetConfig()` through the now-shared `resolveProjectNodeID`, so the probe and `Reset` name the same board.

**Waiting and bounds.** A reading above its threshold (default 30 s lag; 2 × CPU load) pauses `E2E_PROBE_INTERVAL` (30 s) and re-probes, at most `E2E_PROBE_WAIT_MAX` (10 min) / interval times — counted in attempts, not wall-clock, so the bound is deterministic under a stubbed `Sleep`. Still above at the bound → preflight fails with `ExitPreflightFailed` (4) and **names the probe**, rather than starting a run likely to be flaky; `cut-release.sh` already maps 4. A probe that cannot take a reading (no load source, no bed token, add or listing failing) reports `unavailable` and never blocks, matching the existing load-archive behaviour. A zero threshold disables a probe (so a hand-built `Config` — the runner tests' — probes nothing) and `E2E_SKIP_PROBES` skips both, recorded as skipped. The thresholds are judgement calls: too tight blocks preflight on a healthy host, too loose stops catching the 0.0.83 conditions; both are overridable.

**Never kills.** The probes report; the operator decides. The `Commander` has no kill method, `probes.go` carries no signalling code path (no `syscall`/`os/signal`/`sessionreap` import, no `Kill`/`Signal`/`termPID`, no string naming a kill program — pinned on its AST by `TestProbeSourceHasNoSignallingCodePath`), and the runner tests assert the fake never sees a kill invocation. Reaping orphans is #1989/#1957's territory.

**Archive.** Both results are recorded on the `Gate` (the preflights run before the ledger exists) and `beginArchive` writes them as `probes.json` beside `load.json` in every leg's directory: structured, so easy to assert on, and `preflight.txt` stays unchanged for all legs. Each probe also prints its result, so preflight output shows both.

## Consequences

- A harness-side visibility lag now costs an Inconclusive retry (bounded, ADR-1973) instead of a failed or vacuous scenario; an engine that never observes a write still surfaces — as Inconclusive that stays uncovered and exits 8, never as a pass.
- Seed paths do a few more reads (GraphQL for the board and closing link, REST otherwise); intervals are conservative to stay inside the shared budget.
- A run on a loaded host or during listing lag now stops at preflight (exit 4) with the reading and the orphan list in front of the operator, instead of starting a flaky ten-hour run.
- The lag probe is a bed write; it is a draft item that is always removed. A bed engine ignores it (its board query selects on `Issue` content).
- Out of scope, unchanged: the poll-boundary race in `TestMergeTrainQueuedDeeperThanBatchCap` (#1978), the sparse matrix and parallelism (#1975, #1977), orphan reaping (#1989, #1957), and any engine behaviour.

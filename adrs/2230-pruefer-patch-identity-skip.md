# ADR 2230: Pruefer does not re-review a head whose change was already reviewed

## Status

Accepted

## Context

Pruefer reviews every `synchronize`. Since 2026-10-10 the fabrik installation ran 331 reviews, with single PRs reviewed 9 to 13 times, and a large share of those heads carried no new change: rebases onto main (the Validate skill and an engine comment pass both rebase), merge-train work while an item is Queued, and trial/integration PRs that only recombine PRs already reviewed. Each repeat costs a full Claude review and quota, produces a review body a human must read, and posts a review that can perturb the item: a `COMMENTED` body can trigger a review reinvoke, and a finding on a Queued member ejects it (ADR 1208).

ADR 2066's skip covers only an engine-authored pure catch-up merge, needs a verified marker from a login on the operator-only `catch_up_marker_authors` list, and that list was empty on every installation, so it never fired. It covers nothing else.

Baseline measured with `scripts/pruefer-reviews-per-pr.sh handarbeit/fabrik 2026-10-10 2026-10-14 'handarbeit-pruefer[bot]'`: 116 merged PRs, 418 reviews, **3.60 reviews per merged PR**. The after-rollout figure is to be quoted from the same command over a comparable window once the release is in use.

## Decision

1. **Patch identity, computed from diff text** (`pruefer/patchid.go`, `patchskip.go`). A head is skipped when the PR's whole change against its merge base equals the change at the last head Pruefer completed a review of on the same PR. The current diff is `FetchPRDiff`, already fetched for the review; the earlier one is re-derived from GitHub with the new `FetchCompareDiff` (`compare/{base}...{head}`, diff media type). Nothing is stored (ADR 1113: review state is derived from GitHub). No marker, commit message or trailer is read, so nothing the PR author controls can make a changed patch look unchanged.
2. **A Go fingerprint, not `git patch-id`.** The fingerprint drops only `index` lines and the numbers and function-context heading of `@@` lines, hashes per file in path order, and keeps everything else exactly (context, added/removed lines, whitespace, CRLF, `\ No newline at end of file`, rename and mode lines). `git patch-id --stable` ignores whitespace, which would call a whitespace-only edit identical (a real change in Python or YAML); `--verbatim` needs a git binary and a clone with the base, and Pruefer's review clone is depth 1 with no base ref. Binary content (the `index` line is the only thing naming it), an empty diff, a preamble before the first file header and duplicate paths are "not comparable" and mean *review*.
3. **The whole diff, before `excluded_paths` and trimming.** A change confined to an excluded path is still a change and gets reviewed.
4. **Only a completed prior review counts (FR-008).** The last Pruefer review of the earlier head must end with `PRUEFER_COVERAGE: complete` (ADR 2190). A partial review, a review from before the contract or a malformed line never suppresses a review of an identical patch. `appendCoverage` already moves model-written lookalikes off the start of a line, so a line-anchored match can only be Pruefer's. `FetchPRReviews` collapses to the latest review per author; the check fails closed on whatever that entry is.
5. **Fail toward reviewing; degraded is not memoised.** Skip only on positive equality of two fingerprints. A deterministic "cannot compare" (404/422/406 from the compare call: the earlier head is gone or too large) is a conclusive review; a transient failure (5xx, transport, 403/429) reviews and marks the outcome degraded so the daemon never memoises it (ADR 1952 discipline).
6. **Chain bound.** At most `maxPatchSkipChain = 4` consecutive skips over the same reviewed head, then a real review. Nothing in GitHub records a silent skip, so the run length lives in `ReviewTracker` (in memory, reset by any real review; a restart resets it, which at worst allows one extra run per PR per restart; ADR 1631's reasoning). An age bound was rejected: it would put time into a pure-equality check.
7. **Trial and integration PRs, file-granular** (`pruefer/trialpr.go`). Recognised only when the PR author is a login in `catch_up_marker_authors` **and** the head branch matches the engine's naming `fabrik/merge-train/merge-train-<base>-<ts>[-t<n>]`; either alone is an ordinary PR. Members come from the engine-authored body's `Closes #<issue>` lines (trustworthy because of the author check) and are resolved through the `fabrik/issue-<N>` branch (`FindPRByHead`, exactly one open PR). A trial file is covered when exactly one member touches it, Pruefer completed a review of that member's identical patch (current head, or an earlier reviewed head with the same patch), and the trial's patch for the file equals the member's. All covered: skip. Some covered: those files are withheld from the staged diff (so a finding on them cannot be anchored), disclosed to the model through `OmittedReviewedPaths`, and only the rest are reviewed. Any member that cannot be resolved or shown reviewed, a member change absent from the trial, or a failed read: review as today. The engine side has a contract test (`engine/trial_branch_contract_test.go`) pinning the branch grammar and the member lines against the engine's own constructors.
   - *Rejected: a tree-level equivalence via `git merge-tree` replay in a scratch repo.* It would be exact for two members editing one file and would give the precise conflict-resolution diff, but it needs a new credentialed git subprocess with history and base, and the file-granular cut is API-only and fails safe (a file two members share is simply reviewed). Recorded as a follow-up if shared-file trials turn out to matter.
   - A review on a narrowed trial records coverage over what the model was given, as `excluded_paths` already does; the withheld files are covered by their members' own reviews.
   - Trial PRs are opened as drafts and `Eligible` skips drafts, so a trial is reviewable only after the engine marks it ready, just before it lands. This path costs nothing when none arrives; R1 stands alone if R2 proves to save little.
8. **Reuse `catch_up_marker_authors` as the engine-login list.** One operator-only, live-reloadable "logins that author engine-owned artefacts" list; no new trust surface and no rename. Under PAT auth the engine login is a human account, so the author check is only as strong as that account's access (same model as ADR 2066).
9. **Kill switch.** `patch_skip` (`--patch-skip`, `PRUEFER_PATCH_SKIP`, YAML `patch_skip`), default true, `reload:"live"`, operator-only. Off restores the previous behaviour exactly, including never calling the two new client methods (pinned by tests).
10. **Every path, and `/pruefer review`.** The check lives in `ReviewPR` after `FetchPRDiff`, so event dispatch, poll and the reconciliation sweep share it; a pending `/pruefer review` bypasses it.
11. **Visibility (R4).** The daemon counts each saving skip reason (`patch_unchanged`, `trial_equivalent`, `catch_up`), logs the running totals at every skip, and emits a cumulative-total `SkipEvent` the TUI footer shows. Totals, not deltas, so a message lost to backpressure self-heals (the `DropEvent` reasoning). They are in memory only.
12. **R3 — ADR 2066 stays.** The patch-unchanged skip covers a pure catch-up only when the merge adds no patch change against the merge base, which holds for a clean merge of the base. 2066's skip is cheaper (no compare call), does not need the earlier head to be readable, and its code is untouched. Retiring it is deferred until the patch-unchanged skip has run in production and the saving it adds over it can be seen in the counters.
13. **R0 — not silently inert.** Pruefer cannot infer the engine login (it is the App slug or the operator's user), and a default would widen trust to a login nobody nominated. Instead, with `patch_skip` on and `catch_up_marker_authors` empty it logs one `[startup]` line naming the setting; and when it sees a catch-up marker for the head from a login not in the list it logs, once per login, that the marker was ignored. Neither changes a decision. A persistent TUI banner was considered and dropped: it would be permanent noise for installations without a Fabrik engine.

## Consequences

- A rebase or clean catch-up costs one extra GitHub read (the compare diff) instead of a Claude review. A head whose patch changed also pays that one read, only when a completed prior review exists.
- The main risk is a false skip of a changed patch. It is mitigated by the exact normaliser, fail-closed handling of binary and unparseable diffs, and the rule that the only way to skip is two equal fingerprints. A reverted-then-reapplied patch that equals an earlier reviewed one is skipped by design.
- Context lines are part of the patch, so a rebase whose neighbouring base edits change a hunk's context is a different patch and is reviewed. That errs toward reviewing.
- Pruefer serves in-flight projects: ship enabled by default with the kill switch, roll the new binary out in a quiet window, and watch the per-reason counters.
- Related: ADR 2066, ADR 2044, ADR 1208, ADR 2190, #2190.

# ADR 1966-a: A read-only local API on a per-daemon socket, proxied by a stdio MCP server

## Status

Accepted (#1967, the first issue of the Fabrik MCP work proposed in #1966). Builds on ADR-1893 (a daemon's identity is derived from its `fabrikDir`, so per-directory state never collides), ADR-1833 and ADR-1314/ADR-1410 (which fix what the store can and cannot know after a restart), ADR-1978 (the precedent for an engine surface that is inert unless wired, and non-fatal when it fails) and ADR-1953-a (the live "is anything unprocessed" predicate whose vocabulary the attention states reuse). The next issue in the chain pushes events over the transport defined here and reuses the attention definitions and the milestone data.

## Context

An operator often runs a Claude Code session as product manager and overseer of a Fabrik pipeline. That session sees what GitHub shows — labels and a board column — and nothing of what the daemon knows: how close an item is to a pause limit, what the engine will do next and when, whether a worker is alive, how the last invocation ended, whether the pipeline itself is healthy. Polling GitHub for the visible part spends the REST/GraphQL budget the daemon needs and lags; the rest is not on GitHub at all. In one real day an issue lost about 20 hours between states the daemon had already recorded.

All of it is in memory (`internal/itemstate.Store` plus a few engine fields). There was no local read interface.

## Decision

### 1. Transport: stdio MCP per session, proxying to a per-daemon Unix socket

`fabrik mcp` is a stdio MCP server that Claude Code launches per session (`claude mcp add fabrik -- fabrik mcp`). It holds no state; each tool call dials the daemon's socket for its `fabrikDir`, sends one request and renders the result. The daemon serves a small newline-delimited-JSON API on `<fabrikDir>/.fabrik/state/fabrik.sock`.

Rejected: a shared HTTP MCP endpoint. It would be a network listener with an auth surface, one endpoint per machine to collide over, and no natural binding between an MCP session and the daemon whose directory it means. A socket under `fabrikDir` is per-daemon by construction, is not reachable over TCP, and needs no credential beyond filesystem permissions.

**Socket properties.** Mode `0600` (bound under a serialised `umask(0177)` and chmodded explicitly). Bound by `Run()` only after the instance lock is held — that ordering is what makes a socket file already at the path *stale* rather than a live daemon's — and after the webhook manager is assigned (the health view reads it). A pre-existing path is removed only if `Lstat` says it is a socket; a regular file or directory is a bind error, never deleted. A bind failure is non-fatal (logged; the API is simply absent), like the webhook manager. The socket is closed and unlinked when `Run()` returns and explicitly before the SIGHUP re-exec, because an exec runs no deferred cleanup; the self-upgrade exec happens inside the shared `internal/selfupgrade` package with no hook point, so startup's stale-socket replacement is the backstop for it, for crashes and for an exec failure. When `<fabrikDir>/.fabrik/state/fabrik.sock` would exceed `sun_path` (104 bytes on macOS), `SocketPath` falls back to `$TMPDIR/fabrik-<uid>/<12 hex of sha256(abs fabrikDir)>.sock` in a `0700` directory; the daemon and `fabrik mcp --dir` call the same function, so they agree. There is **no authentication beyond filesystem permissions**: any process of the same user can read the daemon's operational state (issue titles, labels, counters). That is the intended trust boundary.

**Framing.** One JSON object per line. A request has an `id` and a `method`; the response echoes the `id` with a `result` or an `error`. A frame with no `id` is server-initiated (`event`, `sub`). Nothing here emits one, but the codec reads and writes them and a `Session` can push one at any time, so the long-lived streaming connection the next issue needs shares a connection with request/response traffic without a framing change. Bounds, so a hung or abusive client cannot affect the poll loop: 32 concurrent connections (extras get a `busy` frame), a 1 MiB request line, a 5 s write deadline per frame, a 10 min idle read deadline, and a recovered panic becomes an `internal` error for that request only.

### 2. Zero GitHub cost

No tool makes a GitHub call. The backend reads the Store only through two new accessors that cannot reach GitHub — `Peek` (no `FallbackFetcher`; `Get` would fetch an unknown issue number live) and `Scan` (an in-memory visit under the read lock, avoiding `All()`'s deep copy of comments, reviews and check runs on every board call) — plus already-guarded engine state and `daemonHealth`. It never uses `e.client`, `e.readClient`, `Store.Get`, or the engine's `labelAppliedAt`, which falls back to a live `FetchLabelAppliedAt` on a miss. An issue the cache has not seen is answered `not_found`, not fetched. This is enforced three ways: a test whose `GitHubClient` panics on any call and whose Store fallback counts calls, a source-scan test in plain `go test` that forbids those identifiers in `engine/localapi*.go`, and the structure above. Failing-check log excerpts are out of scope because they need live fetches.

### 3. Freshness, and the `unknown` rule

Every result carries `as_of` (the daemon's clock when the snapshot was taken), the last poll attempt and success and the time since, daemon uptime, and per item the cache age (`LastDeepFetchAt`). **A field the daemon cannot vouch for is the JSON string `"unknown"` — never a healthy default.** `localapi.Known[T]` makes that structural: its zero value is unknown and marshals as `"unknown"`. It covers, among others: anything derived from `LabelAppliedAt` (record-on-write, empty after a restart, whose live REST fallback R7 forbids), so the CI backstop, review-wait and bot re-prompt deadlines read unknown after a restart; the CI liveness deadline before any CI progress was observed (`LastCIProgressAt` is zero after a restart, ADR-1410); the latest 🏭 comment link when no comments are cached; PR, mergeability, CI and blockers for an item that was never deep-fetched; a cycle limit whose configured value is zero (a test engine), which is `unknown`, never "limit 0"; turns for an in-flight worker (the store keeps turns only for the last completed invocation, and a live counter is out of scope); and the milestone when not captured. A *time in column* is `StatusEnteredAt`, which the store resets on every restart (ADR-1833); results say so (`status_entered_basis`) instead of presenting it as true time-in-column. Consequently nothing is classified `stalled` until one stall threshold has elapsed since the daemon started — a deliberate fail-safe.

The poll loop's own fields (`lastPollAttemptAt`, `backoff*`) are explicitly single-goroutine. They keep their semantics and write sites; each write site also publishes a copy into a mutex-guarded `daemonHealth`, which is all the API goroutines read.

### 4. Milestone is now a cached item field

The milestone filter on `fabrik_board` has no data source otherwise, and the next issue makes milestone a first-class subscription scope. The board query already runs every poll, so `milestone { title number }` is one extra scalar selection on its `Issue` fragment — no new GitHub call. `ProjectItem` and `ItemState` carry `Milestone` plus `MilestoneKnown`, because *none* and *not yet captured* must stay distinguishable (R3): an explicit `null` is known-none, an absent key or a PR card is unknown. The store copies the milestone **only when the incoming item has `MilestoneKnown`**, so write paths that do not carry it (deep fetch, fallback fetch, PR nodes) cannot wipe it — safer than patching each path, which is the shape of the hazard `PreserveBlockedBy` (#1783) exists for. Webhook `issues` `milestoned`/`demilestoned` apply a new `IssueMilestoneUpdated` mutation directly, and `opened` carries the payload's milestone, so a change does not wait for a reconcile. The new field is covered by an `httptest` board-fetch test (set, null, absent) and a wire-contract test pinning `Issue.milestone` (nullable) and the selection against the vendored schema. The recorded `fetch_project_board.json` predates the field and is deliberately not hand-edited (its provenance rule); re-recording it is an operator step.

### 5. Attention is a pure, reusable classification

`internal/attention` maps one item to `needs-human`, `escalated`, `waiting`, `working`, `stalled` or `idle` with a reason, a one-line meaning per label, and what the engine will do next and when. It has no engine, store or GitHub dependency so the push-events issue reuses it unchanged. The mapping, the progress anchor (which deliberately excludes the worker heartbeat — a ticker that stays fresh while Claude hangs — and `UpdatedAt`, which Fabrik's own writes bump) and the 30-minute default stall threshold (`--stall-threshold`) are documented as built in `docs/state-machine.md` §7.13 and pinned by tests. It is label-derived and best effort: labels alone cannot always tell a settle-scan escalation from a stage question, so the split uses `PausedByEngine`, counters at their limit and the specific escalation labels.

## Consequences

- An overseer session gets an accurate, free, fresh-stamped view of what the daemon holds, and an honest `unknown` where the daemon does not hold it.
- The attention states, the stall rule and `Known`'s unknown convention become a contract that later work reuses.
- Merge-train position is a label-based approximation (cached `base:` label, no `WorktreeManager`, no branch-existence fallback), stated in the response.
- The API is read-only; actions are a later issue. It serves only the repos and projects its own daemon manages, because it can only read that daemon's store.
- `go test -race ./...` is the guard for the concurrency contract (API goroutines versus the poll loop).

# ADR 2375: Pruefer resumes the review session until every staged entry is read

## Status

Accepted. Builds on ADR 2190 (diff coverage contract), ADR 2303 (kept transcripts), ADR 2307 (skill fallback) and ADR 2362 (staged-entry batch limit); keeps ADR 1642 (a reviewed repo cannot set operator settings). Names what #2363 (`--no-session-persistence`, transcript purge) must leave room for.

## Context

On a large PR the reviewer can leave staged entries unread and still post. ADR 2362 removed one cause, the CLI cutting a Bash result to a preview. What is left is the reviewer choosing to stop. On #2368 (28 entries, skill 0.1.1, Sonnet at medium effort) three reviews of successive heads left 19, 24 and 2 entries unread, with no turn or time limit hit and no preview involved. Three things led to this: the review skill's "Finish the review" paragraph said to name what could not be checked, which the model read as leave to stop early; the model decides when it is done, and the same model, prompt and PR read 4 entries on one pass and 26 on another; and nothing acted on the unread set, which `computeCoverage` knows exactly.

## Decision

1. **A bounded coverage loop inside `RealClaudeInvoker.Review`.** After a first pass whose output carries a complete contract (summary markers, a findings array in a JSON fence, a coverage block) and whose coverage leaves staged entries unread, Review resumes the same session (`--resume <id>`) with a follow-up that lists the unread entry IDs with their entry paths, repeats the reading rules and the output contract, and asks for the complete review again, revised for everything now read. The loop lives in Review, not in `ReviewPR` or the `ClaudeInvoker` interface, because only Review holds the per-review plugin root, the resolved skill reference, the environment and the session; the interface stays one call and every fake invoker is untouched (they return no session and no `Loop`, so they never loop).
2. **Stop reasons.** Exactly: `complete` (every staged entry is credited), `no progress` (a pass credited no entry that was unread before it), `cap` (the extra-pass cap was reached with entries unread), `resume failure` (a pass errored, returned no complete contract, there was no session id, or the first pass had no complete contract), `disabled` (cap 0). "Unread" is `computeCoverage`'s own answer over the whole session, so it is the same rule that gates the posted coverage. Progress is judged from the transcript, never from the model's claim: an entry reported but not read is not credited, so a reviewer cannot keep the loop alive by claiming reads.
3. **The setting.** `max_coverage_passes` (flag `--max-coverage-passes`, env `PRUEFER_MAX_COVERAGE_PASSES`, YAML key, live reload) counts *extra* passes. Default 2. 0 disables the loop and gives the pre-change arguments, prompt and output (a test compares the first pass's arguments and prompt with the loop on and off). A negative value, or a non-integer env value, is refused by `LoadConfig`. It is operator-only: it is not a field of `yamlRepoConfig`, so a repo's own config cannot set it (ADR 1642), and a test pins that. `ReviewPR` copies it into `ReviewRequest.MaxCoveragePasses`, so a reload cannot change a review already running.
4. **One review per head, from the final pass.** Only the final accepted pass's text is posted; earlier passes post nothing. No findings are merged across passes: a final pass that drops an earlier finding loses it. The follow-up says its answer replaces the last one and to keep every finding that still stands; the risk is accepted.
5. **Coverage is whole-session and Go-owned.** `analyzeTranscript` runs once over the concatenated stdout of the accepted passes, so an entry read half in one pass and half in the next is credited. A resumed pass may report only the entries it opened itself, which would turn the earlier passes' reads into "unread" under ADR 2190's report-and-transcript intersection, so Go replaces the final text's trailing coverage block with the union of every accepted pass's report (`withCoverageReport`). The transcript still gates the posted coverage. With one pass the text is untouched. The transcript kept under ADR 2303 is that concatenation, so it holds the whole session.
6. **Resuming is safe.** A resumed invocation is `buildReviewArgs` of the same `ReviewRequest` plus `--resume <id>`, under the same `reviewProcessEnv`: same tool grant, plugin directories, permission mode (`dontAsk`), `--setting-sources ""`, model, and environment. A test compares the two argument lists and profiles. A failed or incomplete resumed pass ends the loop (`resume failure`) and the last accepted pass's output is posted; the failed pass's stdout is excluded from the transcript, so the posted text and the posted coverage describe the same state. The failed pass's turns and cost are still counted. The first pass's output is posted if no resume was ever accepted. A review is never lost because a later pass failed.
7. **Composition with the skill fallback (ADR 2307).** The fallback is decided from the first pass alone (`checkSkillRan`); it is resolved first, then the loop runs once on the surviving session. The most invocations one review can take is `maxReviewInvocations(cap, fallback)` = `1 + cap`, plus 1 when the selected skill did not run and the default was run instead: 4 at the default cap with a fallback, 3 without, 1 with cap 0. Rejected: disabling the loop on a fallback run (simpler, but leaves exactly those reviews partial) and looping each of the two runs independently (`2 × (1 + cap)`). A test drives the fallback plus a reviewer that reads one entry per pass and asserts exactly four invocations. The resumed passes grant only the surviving skill (`Skill(<ref>)` of the run's reference).
8. **Sessions (R4).** A resume needs the session on disk for the length of the review. With `max_coverage_passes` above 0, Review removes every session it created from the Claude profile when it ends, on every return path (a deferred `removeReviewSessions`), including the session of any first or fallback run that failed (`runReview` records the session id of every run that produced a result object, whatever its outcome, so a review that posts nothing leaves no session behind either; a run that died before emitting a result has no id to record). The profile is the request's `ClaudeConfigDir`, or `~/.claude` when empty. The CLI's directory layout (`projects/<encoded cwd>/<id>.jsonl` and an `<id>/` directory of tool results and subagent transcripts) is not a contract, so the encoded cwd is globbed and the session id is matched exactly, and only after it passes a strict UUID pattern, so nothing but a UUID-named entry is ever removed; removal is best effort and logged, and a review never fails for it. With cap 0 nothing changes: no resume and no cleanup (the session stays where it always did, which is #2363's to settle). Rejected: `--no-session-persistence` only on the last possible pass (it does not remove the earlier passes' files, and nothing guarantees which pass is last); asking #2363 to own deletion (it would tie the two issues' merge order).
9. **What #2363 must leave room for.** `--no-session-persistence` is honoured without `-p` (probe below): a session started with it cannot be resumed. #2363 must therefore not pass it on a review whose cap is above 0, or the loop ends at `resume failure (no session id)`/a failed resume on every large PR. Its transcript purge can cover whatever this cleanup misses. If #2363 lands first the cap-0 test is the one to update.
10. **Record.** `ReviewPR` logs one line per review: passes, the entries each pass added to the credited set, the stop reason (with a short detail for a resume failure) and the turns and cost summed over every invocation, including a failed selected-skill run. Example: `coverage loop: 2 pass(es) (pass 1 opened 9 [0001-0009]; pass 2 opened 19 [0010-0028]); stop: complete; turns 38, cost $0.4210`. Reviews with no staged diff, and invokers without a loop, log none.
11. **Skill wording.** The "Finish the review" paragraph now says that staged entries must all be opened, that naming what was skipped is not a way to finish, and that "say what you could not check" means analysis the reviewer tried and could not complete, never entries it chose not to open. The skill moves to 0.1.2. `TestSkillBodyIsTheOriginalDefaultGuidance` cuts this paragraph out before hashing, as it already does the ADR 2362 paragraph, so it still guards the criteria around them (its digest changed because the cut changed; the bytes covered did not, which was checked against the pre-change body and shown by the test failing on an unrelated edit). `TestFinishTheReviewParagraph` pins the new paragraph's key sentences and the absence of the old excuse.

## Consequences

- A large PR can cost up to `(1 + cap)` times the model work, and a fallback adds one more run. Each invocation keeps its own `max_wall_time` and inactivity limit, so worst-case wall time is `maxReviewInvocations` times that limit, with the concurrency slot held throughout. A resumed pass carries the whole session as context, so it costs more than the first.
- **Cost is reported as the session total on a resumed pass.** The live probe shows `num_turns` and `usage` are per pass while `total_cost_usd` (and `modelUsage`) are running session totals, so summing them would count the first pass again. Review adds turns, and takes the cost as the increase over the session total so far (`sessionCostDelta`), falling back to adding a figure that is smaller than the total so far. If a later CLI reports per-pass cost for a pass bigger than the running total, the cost would be understated; only the log and the TUI figure depend on it.
- Loop-complete is not posted-complete: `TrimmedPaths` (files dropped to fit `max_diff_bytes`) stay partial, and no resume can fix that. The posted coverage line still says so.
- The patch-identity skip (#2230) is unchanged; it should skip more often once coverage is more often complete.
- A session too large to resume fails as a `resume failure` and the first pass's review is posted. The fallback for that case is not built here: keeping the unread list and findings on disk and starting a fresh-context pass over only the unread entries.
- The follow-up embeds entry paths taken from the PR. They are printed through `sanitizeIndexText`, quoted on one line, and labelled as data; a test uses hostile names.

## Verified against the CLI

`TestLiveProbeResume` (`-tags liveprobe`, `PRUEFER_LIVE_PROBE=1`) ran on claude 2.1.302 with `haiku`, through the production argument and environment builders and no `-p`:

- A resumed pass (`--resume <id>` plus the same arguments) kept the tool grant: an attempted `Write` was recorded as a permission denial and created no file.
- The resumed pass returned the **same** session id, and its stream did **not** replay the first pass's events.
- An entry first read in pass 2 was credited by `analyzeTranscript` over the two passes' stdout and not over pass 2's alone, which is why the loop concatenates.
- `num_turns` and `usage.output_tokens` were per pass; `total_cost_usd` and `modelUsage` were session totals (pass costs 0.00232, 0.00369, 0.00409 for passes of 2, 3 and 1 turns).
- `--no-session-persistence` was accepted without `-p`, and a session started with it could not be resumed ("No conversation found with session ID").
- `removeReviewSessions` found and removed the session file the passes created.

Not run in CI: the probe is opt-in and spends model budget.

## Test evidence

Each behaviour has a scripted-CLI test in `pruefer/coverage_loop_test.go` (a fake `claude` that answers call N from a file and records each call's arguments, profile and stdin). Each was shown to fail with its behaviour neutralised, either with a package-level seam (`coverageLoopDisabledForTest`, `coverageUnionDisabledForTest`, `coverageNoProgressCheckDisabledForTest`, `coverageCapIgnoredForTest`, `coverageResumeFailureDropsOutputForTest`, exercised by `TestCoverageLoop_SeamsAreNotVacuous`) or by a one-line mutation of the source, run and reverted:

| Mutation | Test that failed |

| `--dangerously-skip-permissions` added on resume | `ResumedPassKeepsGrantPluginsAndEnv` |
| session cleanup removed | `SessionsRemovedWhenTheReviewEnds` |

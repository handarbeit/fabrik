# ADR 2300: Session Resume Decision for Comment Review and Stage Re-Entry

**Date**: 2026-10-15
**Status**: Accepted
**Issue**: #2300 — a stage option to start a fresh Claude session for comment review and stage re-entry when the saved session is large (from report #1909)

## Context

Every comment-review-family invocation (ordinary comment review, `review-reinvoke`, `ci-fix-reinvoke`, `rebase-reinvoke`) resumed the stage's saved session whenever `.fabrik/sessions/.../<Stage>.session` existed, and a stage dispatch resumed whenever the in-memory `LastAttemptAt` was non-zero. On long stages the resumed context is most of the cost: the reporter measured Implement comment-review runs starting at a median of about 450k tokens against about 72k for a fresh Implement run. Nothing measured or bounded a session's size, and whether a *re-entry* of a stage resumed depended on uptime (`LastAttemptAt` is memory only, and four explicit resets cleared it).

## Decision

1. **Two stage keys, default behaviour unchanged.** `resume_session` (`resume` | `fresh` | `auto`, default `resume`) and `resume_threshold_tokens` (default 250000; `0` = default; negative refused at load). `auto` resumes only while the saved session's measured context is at or below the threshold; an unknown size resumes. The merge-train conflict sites keep `NoResume: true` and never reach the decision.
2. **One decision above the invoker interface.** `decideSessionResume` (`engine/session_resume.go`) returns the stage dispatch's `resume` bool and the comment pass's `InvokeOptions.NoResume`. Deciding above the `ClaudeInvoker` interface keeps the invoker signatures unchanged (about 30 test files would otherwise move) and makes the decision observable to `tests/sim`. It is logged once per governed invocation (R5 wording) by `applySessionDecision`, just before the invoke, so an early return neither logs nor loses a one-shot reset. Comment extension iterations after the first always resume (the loop clears `NoResume`); the extend-turns resume in `runInvocationWithExtension` is untouched.
3. **A durable per-session record.** `<Stage>.session.meta` (JSON, mode 0600, the `.resumefails` precedent) holds `session_id` + `context_tokens`, `closed` and `reset`. The size is the context of the last *main-thread* assistant message of the pointer's own session: input + cache-read + cache-creation tokens, never the run's cumulative total; sub-agent lines, other sessions' lines, lines missing a usage field and all-zero synthetic lines are skipped, so an unusable stream yields *unknown*, never 0. A reader trusts a size only when `session_id` equals the pointer's current ID. The meta is removed next to every `os.Remove(sessFilePath)` (resume-failure abandonment, stale session) and by the session janitor with its `.session` file.
4. **Continuation versus re-entry is the durable `closed` flag, not `LastAttemptAt`.** `processItem` records `closed = completed` beside `StageAttempted`, and `closed = false` on the early-return outcomes that follow a real Claude run (usage-limit, api_error, skill load failure, cancellation); pre-spawn refusals (apiKeyHelper, unresolved skill) touch no session and leave it alone. A session whose last stage run did not end with `FABRIK_STAGE_COMPLETE` (time slice, incomplete, errored, blocked on input) is a *continuation* and always resumes, whatever the option says (R2, building on #2292). A closed session is a *re-entry* and is governed by the option. This is true across a daemon restart. A saved session with no meta, or with a meta that holds no stage-dispatch outcome (`stage_run` unset — created only by a comment-review pass over a session that predates this ADR), falls back to the old rule — continuation iff `LastAttemptAt` is set — until its next run writes a meta, so `auto`/`fresh` only take effect on re-entries of sessions that have one.
5. **The four `LastAttemptAt` clears keep their fresh-start effect, on purpose and durably (R7).** `clearFailedStage`, `reenterValidate`, `handleValidateSHAInvalidation` and `unblockAwaitingInput` are explicit stage resets, so each also sets the one-shot `reset` flag; the next stage dispatch starts fresh whatever the option and uptime, and consumes the flag. Comment review is not affected. This preserves today's in-uptime behaviour exactly; the restart case becomes consistent with it.
6. **R4 context.** A stage dispatch that decides fresh over a saved session also gets `stage-<Current>.md` (`writeContextFilesWithCurrent`). Comment review already writes every stage's output including the current one. For `post_to_pr` stages the issue comment is a summary plus pointer; the worktree and `pr-description.md` carry the detail, so no new file is added.

## Consequences

- **Default behaviour changes in one respect, to remove an uptime dependency:** an unfinished stage (continuation) now resumes after a daemon restart, where before it started fresh because the store was empty. A completed stage re-entered without a reset resumes under the default, as it did within an uptime.
- **A fresh decision drops the discarded pointer up front.** `applySessionDecision` removes the `.session` pointer (not the meta) when the decision is fresh over a saved session. Otherwise a fresh run that dies before the CLI reports a session id (timeout kill, cancel, unparsable output) leaves the pointer on the discarded session, and with `closed=false` the next dispatch would resume it as a "continuation". With the pointer gone the next dispatch simply starts fresh. The meta stays; its size is bound to the old session id and so never applies to a new one.
- **A fresh comment-review session overwrites the stage's `.session` pointer.** `closed` is preserved and the size is rewritten for the new session. A stage continuation after such a comment pass would resume the comment session. Accepted: a separate pointer would be a larger change for a rare path.
- The sim replaces the invoker, so it never runs the real size recording or the `--resume` argv; those are covered by fixture and fake-binary unit tests. The sim seeds a session through `Engine.RecordSessionForTest`.
- `resume_session: fresh` loses the conversation: a comment asking about the agent's earlier reasoning cannot be answered from a fresh session. That is why the default stays `resume`; changing it is left to a later decision informed by the R5 log lines.
- Test seams (per-Engine): `SetSessionDecisionForcedResumeForTest`, `SetContinuationExemptionDisabledForTest`, `SetSessionDirForTest`.

# ADR 2476: Pruefer `event_source: direct` and `tailscale`

## Status

Accepted (#2476). Builds on ADR 2475 (shared `internal/appwebhook` package), ADR 2142 (direct receiver), ADR 2143 (embedded Tailscale Funnel), ADR 2144 (delivery replay) and ADR 2452 (route liveness). Follows ADR 1113 (Pruefer cannot import the engine) and extends ADR 1254 (the `EventSource`/`EventSink` seam) and ADR 1563 (drop accounting and signature drift). Decision of 2026-10-25: one GitHub App per installation.

## Context

After Hookdeck is removed in 0.0.92 Pruefer has only its poll loop. The receiver Fabrik uses now lives in a package Pruefer may import (ADR 2475). A GitHub App has exactly one webhook URL, so the shared `handarbeit-pruefer` App, installed on several accounts with one daemon each, cannot deliver to every daemon. Each daemon therefore gets its own App, webhook URL, secret and Funnel node, and no fan-out component is needed.

## Decisions

1. **One `events.EventSource` adapter, `appWebhookSource` (`pruefer/appsource.go`).** `Daemon.runEventDriven` is unchanged: the startup reconciliation poll, the fallback ticker and the `sourceDone` handling stay exactly as they were, so FR-008 holds by construction. `Run` builds the shared `Receiver`, `Replayer`, `Liveness` and (tailscale) `Funnel` and `HookChecker` in the engine's order (`engine/tailnet.go`, restated because Pruefer cannot import the engine) and blocks on `ctx`. A start failure is reported and `Run` keeps blocking, so the daemon stays on the fallback poll without a misleading "event source exited unexpectedly". Rejected: a second branch in `Daemon.Run`, which would duplicate the fallback logic.
2. **The delivery path is the Hookdeck path.** `appSink.Deliver` converts a verified `appwebhook.Delivery` with `events.NormalizeWebhook`, checks installation ownership, applies the delivery-ID dedupe, and calls the existing `daemonEventSink.Handle`. `normalizeEvent` moved from `internal/events/hookdeck` to an exported `events.NormalizeWebhook` (a pure move; the Hookdeck source calls it). Rejected: a copied parser.
3. **Ownership is checked before dedupe, after the HMAC.** A foreign delivery is therefore never recorded as seen (the replayer would otherwise treat it as handled) and never counts as a signature failure. It is ignored with exactly one log line and counted under the new `events.DropForeignInstallation`, which lands in the footer's "other" bucket. The line is not rate-limited (the spec asks for one per delivery); the counter is the aggregate.
4. **"Own installation" is a set, and unknown means pass.** It is the pinned `github_app_installation_id` (when set) plus every installation and repo-installation of the last derivation, including entries with no token (`Unrecognized`, `MintError`, `NotServingWatchedRepos`): they are still installations of this App. An empty set means ownership cannot be judged yet and nothing is dropped on that ground. A delivery with no `installation.id` against a known set is foreign. Rejected: counting only entries with a token, which would drop events for an installation a transient mint error had just hidden.
5. **`installation` `created` bypasses the filter.** It is the event that tells a daemon holding several installations of its App about a new one, and it only triggers the re-derivation a timer tick would do anyway; the HMAC already shows the App is this daemon's, and re-derivation reads only that App's installations. `installation_repositories` and every other event, and every other `installation` action, use the strict check. This is a deliberate narrowing of "installation events get the same check".
6. **A read-only dedupe view.** `events.Dedupe` gains `Seen`, `Newest` and `ReceivedAt` (the ring's map now stores the record time; `SeenBefore` is unchanged). `pruefer.ledgerView` exposes only those to the replayer and route liveness, so asking whether a delivery was seen never records it (FR-006): if it did, a redelivery the replayer requested, or a route-check copy, would be dropped as a duplicate. The ledger stays in memory (ADR 1113). After a restart the replayer's first pass looks back one hour and a liveness probe has nothing to redeliver (`unknown`); the real idempotency guard remains the review's head-SHA check. The replayer never calls the sink; redelivered copies re-enter through the receiver.
7. **Flat configuration keys, mirroring Fabrik.** `direct_listen`, `app_webhook_path`, `app_webhook_secret_env`, `tailscale_hostname`, `tailscale_auth_key_env`, `tailscale_state_dir`, `replay_failed_deliveries`; flag > `PRUEFER_*` env > YAML; all `reload:"restart"`. Pruefer's Hookdeck keys are nested, but the two daemons share an operator and a receiver, so one vocabulary wins. The secret default equals the Hookdeck default (`PRUEFER_GITHUB_WEBHOOK_SECRET`): a daemon uses one source. `*_env` settings must be variable names (a pasted secret is refused before it can be echoed).
8. **Refusals are Pruefer's own.** `validateAppSourceStatic` runs at config load; `RefuseAppSourceMisconfigured` runs in `Execute` once the environment is read (empty secret; no auth key while `!appwebhook.StateExists`). The engine's equivalents are bound to its `Config`; lifting them into the shared package would mean refactoring the engine for no behavioural gain. Pruefer is always App-authenticated, so the "needs App auth" rule has no counterpart. Messages name variables, never values.
9. **No warnings panel, no local API: a log line plus a footer banner.** `logPanel` implements `appwebhook.Panel`: it logs once per transition and emits `TransportWarningEvent`; it writes no `warnings.json`. `Reconcile` stamps the type on each condition as `warnings.Reconcile` does (the hook-config check builds conditions with no type). A notice-level condition is logged only.
10. **Footer health is sampled.** `Receiver`'s health callback fires only on derived-state changes, while tailnet, Funnel, route and last-delivery change without one, so `sampleLoop` reads `HealthRow()` every 5 s and on each callback and emits a `TransportEvent` only when the row changed. The TUI event carries plain strings and a time (no `internal/localapi` import).
11. **Listen failure keeps the demoted fallback cadence** (`reconciliation.fallback_interval`, default 2 m) rather than switching to `runPollOnly` at `poll_interval_seconds`: the two defaults are equal, and a mode switch would add a code path for no benefit.
12. **The hook-config read is a `Reconciler` method.** `(*githubauth.Reconciler).FetchAppHookConfig` mints the JWT from the Reconciler's own captured identity, so a manifest-created App needs no key-path plumbing. The installation-coverage check is not ported (not required by the spec).
13. **Every `pruefer` build carries the Tailscale node** (via `tsnetnode`), as every `fabrik` build does (ADR 2143). There is no build tag.

## Consequences

- `reconciliation.*` apply to every event-driven source, not only Hookdeck; the README and config comments say so.
- The review environment is an allowlist and drops the new names and values already; tests pin it for default and custom names (FR-003).
- Live verification (a real tailnet, a tagged key, a dedicated App) is operator-assisted and recorded in the PR; CI covers the real handler into the real sink, the foreign-installation case, restart-without-key with a fake node, replay, and the environment.
- Moving the existing instances off the shared App is an operator step (README runbook), not part of this change.

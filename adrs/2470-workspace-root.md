# ADR 2470: Configurable workspace root

## Status

Accepted

## Context

Everything Fabrik writes at runtime lived under `<bed>/.fabrik/`, on the same volume as the bed's checkout (community thread #2070, mentioned for context). The workload is create-and-delete: a worktree plus `node_modules` per issue, build and test output. On macOS, Time Machine's hourly whole-volume local snapshots pinned 133 GB in a day on one host, and excluding a directory does not help because snapshots are whole-volume. Only a separate, excluded volume does, and Fabrik could not write outside `<bed>/.fabrik/`. The same need appears for a faster scratch disk, a quota-capped volume and a volume kept out of Spotlight or a backup agent.

The root was also rebuilt independently at about twenty sites (`engine/engine.go` three times, the janitor, the session, log and debug helpers, `cmd/resume.go`, `tui/commands.go`, `watch/model.go`, the gate reset), so a setting honoured at some sites and missed at others would split a worktree from its clone or its session.

## Decisions

1. **One resolver, an immutable value.** `internal/workspace` (stdlib plus yaml.v3, importable from `engine`, `cmd`, `tui`, `watch`, `tests/gate`) holds `Layout{Bed, Root}`. Every site asks it for `Dir(Worktrees|Repos|Sessions|Logs|Debug)`. It is a value passed down (`Engine.ws`, `RealClaudeInvoker.WS`, `InvokeOptions.Workspace`, `tui.ProjectInfo.Workspace`, `watch.GitHubOptions.Workspace`), not a process-global like `claudeprofile.Set`, because `tests/sim` runs parallel engines in one process (ADR 2210). A zero layout means the in-bed default, so engines built outside `New()` and every existing test are unchanged.
2. **Precedence** is `--workspace-root` > `FABRIK_WORKSPACE_ROOT` > `workspace_root:` > `<bed>/.fabrik`, like the other daemon settings. A relative value resolves against the bed, never the process's working directory; `~` is expanded. `fabrik watch` and `fabrik resume` accept the same flag and use `workspace.Load`, and the TUI passes `--workspace-root` to the `watch` child it launches (the daemon's flag is invisible to a child). The resolved value is held in memory and never exported to the environment, so the SIGHUP and self-upgrade re-execs re-resolve it (the ADR 2293 provenance invariant). `FABRIK_WORKSPACE_ROOT` is `workerenv.Scrubbed`.
3. **What moves:** `worktrees/`, `repos/`, `sessions/` (with the per-stage session sidecars `.session`, `.session.meta`, `.resumefails`, `.dispatches`, which live there), `logs/`, `debug/`. `repos/` and `worktrees/` derive from the same root so `git worktree` stays on one filesystem.
4. **What stays in the bed:** `config.yaml`, `.env`, `fabrik.lock`, the local API socket and all of `state/` (so also `stage-outcomes/`, `engine-decisions/`, `merge-train/`, `workers.json`), plus `fabrik.log`, `history.json` and `warnings.json`. The CLI, TUI and MCP tools find a running daemon through these, and the daemon reads the `state/` files at startup. The issue's "stage state" is read as the session sidecars only; moving `state/` is out of scope.
5. **Migration: refuse rather than move (R6).** A marker `<bed>/.fabrik/state/workspace-root` records the root of the last run (`state/` stays in the bed, so the marker is always findable). At `New()`, before anything is migrated or created under the new root, `CheckMigration` compares the configured root with the marker (absent or corrupt means the in-bed default, so a pre-feature bed with live worktrees is still caught and a corrupt file never bricks a healthy start). If they differ and the previous root holds any `issue-N` worktree directory, startup fails naming the old root, the worktrees and the remedy. Nothing is moved, deleted or rewritten. Refusing is lossless and reversible; an automatic `git worktree move` touches live branches and absolute gitdir links and can be a later feature. The marker is written by `Run()` only after the instance lock is held, so a second instance that loses the lock cannot rewrite it. The unset default records nothing and removes a stale marker. A previous root that cannot be inspected (a read error, or neither the root nor its parent exists, as with an unmounted volume) also refuses: unknown is not treated as empty. A root that was removed but whose parent exists is accepted. A previous root that a run configured and that exists with neither a `worktrees/` directory nor the `.fabrik-workspace` sentinel (written by `Prepare`) is refused as well: with a mount-point root that is the empty directory left on the system disk while the volume is unmounted. The refusal names the sentinel so an operator who knows the volume is mounted and empty can create it.
6. **"Active" is any `issue-N` directory.** The spec's assumption (worktrees of items still in flight, not janitor-eligible leftovers) needs the item Store and GitHub reads, which do not exist at `New()`. The simple test is stricter than the assumption: leftovers the janitor would have reaped also block a root change. The error and User Guide give the remedy (finish, clean up, or set the old root back).
7. **The root must already exist (FR-011).** `Prepare` requires the root to exist as a directory, creates only the five subdirectories inside it, and proves writability with a probe file. It never creates the root. This overrides the spec assumption that a missing root (with its parents) is created, because that contradicts the spec's own unmounted-volume edge case: `MkdirAll /Volumes/X/fabrik` with `X` unmounted silently recreates the workspace on the system disk, and so does creating only the leaf when the root is itself the mount point (`/mnt/fabrik`). An operator creates the directory on the volume first. There is never a fallback to the in-bed location.
8. **The `.env` link (R4).** The unset case keeps the relative `filepath.Rel` target (byte-identical). Under a configured root the target is the absolute path of the bed's `.env`. `symlinkEnvIfEnabled` no longer treats any `Lstat` hit as done: a real file is left alone, a link that resolves is left alone, a dangling link is replaced with a temporary link renamed over it, so a running worker never sees a moment without `.env`.
9. **Path comparisons (R5)** go through `workspace.Same`/`Within`, which resolve symlinks on the deepest existing ancestor and re-append a missing tail. The janitor, `migrateSessions`, `findWorktreeForIssue`, `worktreeExistsForItem` and the issue-to-worktree lookups take their roots from the layout. The cwd reaper (ADR 063) already resolves `wtDir` with `EvalSymlinks` before matching and needed no change; a test proves it attributes a process in a worktree reached through a symlinked root and leaves an unrelated one alone. `checkNotInWorktree` also compares against the layout's worktrees directory, since a relocated worktree has no `.fabrik/worktrees` path segment. Pruefer clones each review into its own `os.MkdirTemp` directory and never reads `.fabrik/worktrees`, so it has no workspace-root dependency; a test pins that finding.
10. **R3 is enforced by a test.** `TestNoHandBuiltWorkspacePaths` parses every non-test Go file and fails on a call joining `".fabrik"` with one of the five names or a string literal naming `.fabrik/<name>`, with an audited exception list (`cmd/init.go`: the git-exclude text of the default in-repo layout). The pure scanner is also run against a deliberate-violation fixture that must fail. Test-only cwd-rooted helpers (`SessionDir`, `LogDir`, `sessionFile`) moved to a `_test.go` file so no production site can call them.
11. **Incidental fix.** `fabrik resume` looked only for the flat `.fabrik/worktrees/issue-N` and never found the per-repo layout Fabrik has used for a long time. It now searches the per-repo directories as well. `fabrik resume` also reads `FABRIK_WORKSPACE_ROOT` from the bed's `.env` as data (never exported into the environment of the claude it execs), as the daemon and `watch` do. Because issue numbers are per repo, a number found under more than one repo is refused with the candidates listed, and `--repo owner/repo` chooses one; the first match in directory order is never picked.

## Consequences

- Operators can move runtime churn off the volume that is snapshotted, with unset behaviour unchanged byte for byte.
- A root change is a deliberate two-step operation on a bed with live work; the cost is occasionally cleaning leftovers by hand.
- Helpers that were `os.Getwd()`-based take a `Layout`; a missed caller is a compile error, and the scan test covers literals.
- Two beds sharing one root are not detected (out of scope); the documentation says each bed needs its own root.
- Not covered: the sim bed injects its worktree manager and never runs the real invoker or clone, so there is no sim twin; the real-invoker, `New()` refusal, janitor and reaper behaviour is pinned by unit tests in `engine/workspace_root_test.go`. A live run against a real separate volume was not performed.

# ADR 2349: Decision state that survives a restart

## Status

Accepted. Amends ADR 2160 (decision 3: the gap budget is no longer "never reset"), ADR 1183 (the label sweep waits for the hold's true state) and the "in memory, a restart resets it" statements of ADR 2045 (auto-repair attempts) and ADR 059 D8 (trial window).

## Context

The 2026-10-15 engine state audit (§4) found four places where engine-private state changes decisions but is memory-only or never reset. All are harmless on a quiet, long-lived daemon and harmful on one that restarts often (self-upgrade, SIGHUP, crashes):

- **Merge-train caps.** The ejection count was described as "consecutive" but only a landing reset it; it was not tied to the PR head it was earned against and started again from zero on every restart. The trial-rate window and the auto-repair attempts also reset on restart, so a restarted daemon could run past the caps that bound expensive loops.
- **Usage-limit hold.** `claudeUsageLimitedUntil` was memory only. After a restart `settleClaudeLimitLabelSweep` found no hold and stripped `fabrik:claude-limit` from every item, every slot dispatched into the limit, and each item's explanatory comment (gated on the label's absence) was posted again.
- **Reinvoke workers could not be stopped.** Only stage-run dispatch registered a cancel handle in `issueCtxs`; a stop on a review, CI-fix or rebase reinvoke paused the item while the worker kept running and pushing.
- **`feedbackGaps`.** The per-gap repair budget was never reset, so a spent budget held the feedback gate until a restart.

## Decision

1. **A small decision-state store, not the train run record.** `engine/decision_state.go` persists JSON files under `.fabrik/state/engine-decisions/` (atomic tmp+rename, mode 0600, `version` field). A missing, unparseable or unknown-version file is renamed to `<file>.corrupt` and treated as absent; a failed write is logged and costs only that update's restart-survival. The issue asked for the counters "with the train run record"; that record is per-episode (deleted when the run ends), nil on synchronous-driver engines and keyed per partition, while the ejection count and auto-repair attempts must outlive episodes — an ejected member stays Queued. The directory is a sibling of `merge-train/` because `trainRunStore.loadDir` quarantines every `*.json` there as a bad run record. `NewWithDeps` engines have no store (existing tests unchanged); tests opt in with `EnableDecisionStateForTest(dir)` and `tests/sim` carries `Env.DecisionStateDir` across `RestartEnv`.
2. **Persist after unlock.** The in-memory maps keep their types. After a mutation, and after releasing the state's own mutex, `persistTrainCaps` / `persistUsageLimit` take `decisionWrite`, snapshot the live state and write it, so concurrent mutations converge last-write-wins and no disk I/O happens under a hot lock.
3. **"Consecutive" means no break.** The ejection count is keyed to the PR head it was earned against: a different non-empty head restarts it (`ejectMemberAtHead`; an unknown head never resets, which errs toward counting). A landing, a green trial verdict for the member (`recordTrialIfCounts` → `resetEjectionCountOnGreen`) and the item closing or leaving the board (`pruneDecisionState`, per poll) also reset it. Leaving Queued does not: an ejection is itself what moves a review-finding ejectee off Queued. `ejectMember` counts and persists before it posts the comment, so a crash between the two cannot grant a free ejection.
4. **Auto-repair stays keyed to the pinned base SHA.** A repair pushes, so keying attempts to the member head would reset the budget after every repair and defeat the cap. Its attempts and spent requeues are persisted; the pending repair context stays an in-memory hand-off.
5. **The trial window is persisted per train key** and pruned by window on load and on record. `recordTrial`, `isRunawayTripped` and every usage-limit time read/write use `e.now()` (R5). The usage-limit sites had to move together: converting only the sweep would leave a real-time hold looking active for the rest of a sim clock that starts in 2026-01-01. The runaway-alert idempotency set (`mergeTrainRunawayAlerted`) stays in memory; paused members are excluded from snapshots, so a restart re-alerts at most the still-unpaused ones.
6. **Usage-limit hold: persist the exact deadline, seed from the label only when there is no file.** `usage-limit.json` holds the deadline; `activateClaudeUsageLimit` writes it and every clear path (`clearClaudeUsageLimit`, hence the operator label and the early clear) deletes it. On load an expired deadline is dropped and a far one clamped to the 8-day horizon. A usable file at startup is authoritative. With no file (state from before this change, or a lost file) and open items carrying `fabrik:claude-limit`, the first poll seeds a hold until the latest label-applied time plus the 1 h fallback (at most five `labelAppliedAt` reads, a read error counts as now, bounded by the 8-day ceiling), persists it and skips the sweep for that poll. The label is thereby the dedupe key for the comment and the seed for the hold, and the sweep never strips it before the hold's true state is known. The cost is at most about an hour of held dispatch after a limit that had actually lifted, the safe direction.
7. **Every worker kind registers a cancel handle.** `dispatchReinvoke` — the single scaffold behind review, CI-fix and rebase reinvokes — registers `issueCtxEntry` in `issueCtxs` at claim time (so a queued reinvoke is cancellable) under a context carrying the kill-reason holder, and deregisters it on exit with the holder-pointer-equality guard stage dispatch uses. `handleStopRequest` and `beginShutdownPause` need no change, and `daemon_shutdown` now reaches reinvokes. Comment review runs inside the stage-run worker and is already covered; merge-train conflict-resolution invocations are not per-item and stay with `trainCancelled`/drain. A pass cancelled by a stop returns the empty kind `processCommentsClassified` uses for an ambiguous charged run, so `dispatchReinvoke` now refunds the cycle and skips `opts.after` when its context is done.
8. **`feedbackGaps` is per item with `{gap IDs, PR head, repairs}`.** The budget (still `feedbackGapRepairBudget` = 2) restarts when the gap IDs or the PR head differ from the recorded ones, and is zeroed when the gate holds on feedback the dispatcher can see or clears. The entry is kept zeroed so `len(feedbackGaps) > 0` stays a valid "a repair happened" signal for `MaskReviewFromCacheForTest`. Entries for closed or absent items are pruned. The state remains memory only: a restart already grants a fresh budget, so its acceptance is "resets on change without a restart", not a restart test.

## Consequences

- A restart cannot grant a fresh ejection, trial or auto-repair budget, and a restart during a usage-limit outage dispatches nothing into the limit, keeps `fabrik:claude-limit` and posts no second comment.
- A stop request or a daemon shutdown cancels a running reinvoke, refunds its cycle charge and runs none of its HEAD-based follow-up.
- New files under `.fabrik/state/engine-decisions/` (`train-caps.json`, `usage-limit.json`). No new flag, environment variable, label or YAML key.
- Existing tests that read `mergeTrainEjectionCounts` / `mergeTrainTrials` keep working: the map types are unchanged, `ejectMember` keeps its signature (it delegates to `ejectMemberAtHead` with the item's linked-PR head).

## Alternatives rejected

- **Fields on the train run record.** Matches R1's wording, but the record is deleted per episode and absent on synchronous engines, so it cannot carry a count across episodes.
- **Keying auto-repair attempts to the PR head.** Resets after every repair push; defeats the cap (decision 4).
- **Seeding the hold from the comment's reset text only.** Local-time, minute resolution and an ambiguous zone abbreviation make it lossy; the persisted exact deadline is primary and the label time is the fallback.

# ADR 2190: Pruefer stages the diff as a directory and records review coverage

**Date**: 2026-10-12
**Status**: Accepted
**Issue**: #2190 — large diffs were reviewed partially and reported as clean
**Amends**: ADR 2192 decisions 1 and 3 (the single-file diff scope), ADR 1456 (fail-open parsing, for coverage only)
**Builds on**: ADR 2192 (tool naming, Task subagents), ADR 1462 (per-file exclusion and trim), ADR 1446 (Go-owned contract half), ADR 1251 (`decideEvent` reads severity only)

## Context

Reviews on handarbeit/fabrik read "the first 556 of 823 diff lines", hit "the tool cap", or had no shell, and still reported no findings. Fabrik's review gate clears on any non-dismissed review, so the PRs that most needed a full review got the least of one. Three causes: the whole diff was one file read through `Read`'s per-call limit (the tail, which holds tests and later files, is what gets dropped); the shell denial that stopped paging was the allowlist working as designed (fixed by ADR 2192); and nothing machine-visible recorded what was unread.

## Decisions

1. **Stage the diff as a directory, not a file.** `stageDiff` (`pruefer/diffstage.go`) writes `INDEX.txt` plus one `NNNN.diff` per changed path, outside the clone. A path larger than `stagedChunkMaxBytes` (16 KiB) or `stagedChunkMaxLines` (600) is cut into numbered chunks, each repeating the file header; a hunk split across chunks gets a synthesized `@@` header with correct old/new starts and counts, so post-change line numbers stay right. A single line larger than the cap is its own chunk, flagged `long-line` in the index. An entry holding a line over `stagedWideLineBytes` (2000 bytes, where `Read` cuts a line mid-line) is flagged `wide-line` and must be opened with `cat`. Chunking is by bytes because a long-line diff hits `Read`'s token cap well before 2000 lines. `diff` is still rebound to `joinDiff(preamble, kept)`, so `validRightAnchors` and finding anchoring do not change.
2. **Names are derived.** Entry files are `NNNN.diff`; PR paths appear only as index text (control characters replaced), never as file names, so traversal, empty, duplicate, very long and non-ASCII paths cannot escape or collide. A non-empty preamble is its own entry.
3. **Scope is the directory.** `Read`/`Grep`/`Glob(//<resolved staging dir>/**)` replace ADR 2192's single-file `Read`/`Grep` rules (decisions 1 and 3 of that ADR otherwise stand). `ReviewRequest.DiffPath` became `Staged *StagedDiff`; `resolveScopePaths` resolves the directory like the clone.
4. **The model reports, Go decides.** The Go-owned prompt halves (not overridable guidance, ADR 1446) require opening every index entry — alone or across subagents, in which case every entry must be opened by some reader — and a `PRUEFER_COVERAGE_BEGIN`/`END` block carrying `{"opened":["0001",…]}`, following ADR 1456's line-anchored marker convention. The block is stripped before the findings are parsed. Entry IDs, not paths, are the unit: a chunked file is covered only when every chunk is opened, and the review names original paths. Unlisted means unread, so a reader that reports nothing is unread, not covered.
5. **Hybrid coverage.** A self-report alone can claim `complete` falsely, which is the failure this issue exists to fix. `Review` therefore also derives the opened set from the stream-json transcript (`deriveOpened`). A successful `Read` is **not** proof: the live probe showed `Read` returning a 32 KiB chunk cut at ~22 KB with no error and no notice. An entry counts as opened by `Read` only when the numbered lines the results returned cover `1..Lines`, across as many calls (subagents' included) as it took; a `wide-line` entry is never credited to `Read`; `cat` of plain staged paths credits an entry only when its output contains the entry's whole text. The transcript is **authoritative** only when it shows all subagent traffic — no Task/Agent call, or every call has events tagged with its `parent_tool_use_id`. When authoritative, opened = reported ∩ transcript. When a subagent ran but is not visible (`ReviewResult.UnobservedSubagents`), the intersection is applied anyway, so entries only an invisible subagent could have read count as unread and the reason says so (fail closed).
6. **Fail closed.** A missing, malformed, or non-`opened` block is `partial`. This deliberately reverses ADR 1456's "never fail to submit" stance *for the coverage value only*: the review is still submitted. Files dropped by `trimToFit` (never reviewed) force `partial`; files removed by the operator's `excluded_paths` are intentional and do not. With nothing staged (the 406 `too_large` fallback, or a staging failure) coverage is `partial` with reason `no staged diff`, and the unread list is the changed-files list.
7. **A fixed line on every review.** Go appends `PRUEFER_COVERAGE: complete` or `PRUEFER_COVERAGE: partial — <reason>` plus up to 50 unread paths as bullets. It is on complete reviews too so absence only ever means a review from before this contract. A model-written imitation of the line is removed first.
8. **R3 gate decision.** Coverage stays out of `decideEvent` (ADR 1251): a partial review is submitted as `COMMENT` exactly as before and recorded in the tracker, so the head is not re-reviewed in a loop (ADR 1631); `/pruefer review` re-runs it. Pruefer does **not** retry inside `ReviewPR` (extra cost and a findings-merge story for little gain). **Fabrik's gate is unchanged in this change.** Making `reviewGateOutstanding` ignore a partial review would hold forever, because Pruefer never re-reviews the same head, so it needs its own design (re-request, hold, or advisory-only). Recommended as a separate chained issue touching `engine/reviews.go`, both gates (advance and landing, which must agree), `docs/state-machine.md` §6.6.6 and `docs/llms-full.txt`. Until it lands this change makes the gap machine-visible but does not close it for `wait_for_reviews`.
9. **ADR 1045 interaction.** A COMMENTED review body is actionable feedback to Fabrik, so the coverage line reaches the review-reinvoke path. It is a status line, not a request, and the no-op cycle exemption bounds the cost; accepted.
10. **Non-vacuity.** `checkStagedCovers` passes the new layout and fails the legacy single-file layout (`legacyStaged`); `coverageFailOpenForTest` flips the fail-closed default so the missing-field assertion is shown to depend on it; the subagent fixture reads `complete` only when every entry was opened by some reader and `partial` naming the unopened paths otherwise, and reads wrongly `complete` when the transcript is ignored.

## Consequences

- Every Pruefer review body changes (one trailing line), and every review without a coverage report is `partial`. This is the intended cost of failing closed.
- More `Read` turns per large review, bounded by `max_diff_bytes` (default 500 KB, at most ~16 full chunks).
- **Live probe results** (`TestLiveProbeStagedCoverage`, run against the installed CLI during Review of this change, 2026-10-12): (a) one `Read` of a 32,085-byte chunk of dense 158-character lines returned 21,968 characters, ending at line 138 (entry line 133 of 199) with no error and no truncation notice — hence the 16 KiB cap and the line-coverage check above; (b) a subagent's tool calls **are** tagged with `parent_tool_use_id` in the parent's stream, and the subagent tool is named `Agent` (the code also accepts `Task`), so the authoritative transcript path applies to delegated reviews on this CLI. The probe's `Agent` call was launched asynchronously by the CLI.
- Transcript derivation under-counts rather than over-counts: a chunk read through an offset window or `head` is not credited, which yields `partial`, never a false `complete`.

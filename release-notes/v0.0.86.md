# Fabrik v0.0.86

## Summary

**A bug-fix release.** Every issue in it came from a report: community reports, our own
production incidents, or the v0.0.85 gate. There are no new features.

**The merge train no longer turns GitHub timing into member failures.** A trial that goes
`dirty` because the base moved during its CI is now rebuilt, not charged to a member (#2298).
A landing that reads `blocked` for a moment right after mark-ready is waited out on the same
PR, and a green trial is kept instead of rebuilt (#2297). A pending-eject signal no longer
leaks from one train run into a later batch (#1557).

**A cancelled or unrecognised CI result is no longer a pass** (#2296). A cancelled, stale or
empty check-run conclusion counted as green, so an item could advance or land without a
passing run. It is now treated as not passed. Each gate re-runs the cancelled jobs once.

**Fabrik stops overwriting work it can't see** (#2295). Before working on an existing issue
branch, Fabrik syncs it from origin. Every push now uses a lease on a remote head it has
verified. A branch that has diverged from its remote pauses the item instead of
force-pushing over the other side.

**Each Claude invocation runs on the account you configured** (#2293, #2294). Fabrik and
Pruefer resolve `CLAUDE_CONFIG_DIR` from one ordered set of sources: flag, environment,
`.env`, `config.yaml`, then the inherited value. They log which account each process uses
and warn when the sources disagree.

**Fewer silent waits.** A merge state GitHub never computes now pauses after 30 minutes,
and a CI-timeout pause names the gate that actually held the item (#2302). A Validate run
that finishes after its PR merged takes the terminal path (#2299). A denied edit that no
`allowed_tools` rule can grant pauses on the first occurrence and names the file (#2301). A
comment-review run can now ask for input (#2280).

**Session handling.** A time-sliced stage resumes its Claude session again (#2292, a
v0.0.85 regression). A new stage option, `resume_session`, can start a fresh session when the
saved one has grown large (#2300).

## Upgrading

No configuration changes are needed. Behaviour changes to know about:

- **Cancelled checks block** (#2296). A PR whose only non-green check run was cancelled used
  to pass the CI gate. Fabrik now re-runs the cancelled jobs once. If a check is still
  cancelled after that, the item waits or goes the CI-fix route like any red run.
  `skipped` and `neutral` still pass.
- **A diverged issue branch pauses** (#2295). If someone pushes to `fabrik/issue-N` and the
  local branch has commits the remote lacks, Fabrik now pauses the item with a comment
  instead of pushing. Resolve the branch and comment to resume.
- **New pause: unknown merge state** (#2302). A PR whose mergeable state stays `unknown` for
  30 minutes, with no worker running, pauses with a comment naming the PR, head and
  check-run state. Change the bound with `--merge-state-unknown-timeout` /
  `FABRIK_MERGE_STATE_UNKNOWN_TIMEOUT` (minutes).
- **New pause: ungrantable denied edit** (#2301). A run that a denied file edit inside the
  worktree stopped (for example under `.claude/`), when the CLI's `--allowedTools` already
  allows that tool on the whole worktree, pauses at once and names the file. It no longer
  burns three tools-denied retries first.
- **`CLAUDE_CONFIG_DIR` precedence** (#2293, #2294). A bare `CLAUDE_CONFIG_DIR` inherited
  from the shell now ranks *below* `.env` and `config.yaml`. To override for one run, use
  `--claude-config-dir` or `FABRIK_CLAUDE_CONFIG_DIR` (Pruefer: `-claude-config-dir` or
  `PRUEFER_CLAUDE_CONFIG_DIR`). Startup logs the winner and warns when sources disagree.
- **Dev self-upgrade needs an exact GitHub remote** (#1209). A source checkout rebuilds
  itself only if its `origin` is exactly `github.com/<owner>/<repo>` over https or ssh. A
  checkout whose remote uses an `~/.ssh/config` host alias, or a token in the URL, now
  reports "not a source checkout" and does not self-upgrade.
- **Restart resumes interrupted stages** (#2300). A stage that a restart interrupted, or
  one that ended incomplete, resumes its saved session after the restart. `resume_session`
  defaults to `resume`, so nothing else changes unless you set it.

```bash
# Auto-upgrade from a running Fabrik instance
# Fabrik checks for new releases each poll cycle and upgrades automatically with --auto-upgrade

# Or download directly (auto-detects OS and architecture)
gh release download --repo handarbeit/fabrik \
  --pattern "fabrik_*_$(uname -s | tr A-Z a-z)_$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/').tar.gz" \
  -O - | tar xz
```

## Engine

- **Stale merge-train trials are rebuilt** (#2298, reported in #2213). A trial PR that reads
  `dirty` is checked with one live read of how far its branch is behind the base. If the base
  moved (or the read fails), the trial is stale: Fabrik re-pins the base and rebuilds the same
  member set, spending one cycle of the run's persisted rebase budget. No member is charged,
  bisected, ejected or paused. When the budget is spent the batch dissolves, naming the old
  and new base SHAs. A `dirty` trial on an unmoved base is still red, with a diagnostic that
  says so. A restart counts and rebuilds once. See ADR 2298.
- **A merge-train landing waits out a transient `blocked`** (#2297, reported in #2237). After
  mark-ready, Fabrik merges only when CI is green and GitHub reports a mergeable state. It
  waits out pending checks under the CI backstop, and an all-green but `blocked` state for up
  to 5 minutes, on one deadline that is never reset. It retries a merge refusal on the same
  PR inside that wait. If the attempt still ends without a merge and the base has not moved,
  the green trial PR and its branch are kept and resumed rather than rebuilt. A waiting landing
  posts nothing; one `merge failure` comment is posted per PR, and only for a real failure.
  See ADR 2297.
- **Pending-eject signals belong to one train run** (#1557). A review or comment eject raised
  for a member while a train run was in flight could survive that run's early returns and be
  applied to a later, unrelated batch. Each signal now carries the run it was raised for, is
  acted on only by that run and is cleared when the run releases its claim. The scan raises
  it again if the finding is still unresolved. See ADR 1557.
- **Cancelled, stale, empty or unknown check-run conclusions are not passing** (#2296,
  reported in #2215). The stage CI gate treats them as a failure, re-runs the cancelled jobs
  on the existing flake budget and says *cancelled* in the CI-fix comment. The merge train's
  fast path declines; admission defers. A trial re-runs once, then is abandoned as an
  infrastructure problem, so no member is charged. A singleton catch-up builds a trial
  instead of ejecting. See ADR 2296.
- **Issue-branch sync and verified-lease push** (#2295, reported in #2058). When Fabrik
  reuses a worktree, it first compares the local `fabrik/issue-N` with origin. It
  fast-forwards when behind, resets when the local branch holds nothing new and keeps the
  local branch when the remote holds nothing new. It changes the branch only on a clean, idle
  tree and never pushes during the sync. A diverged branch pauses the item with one comment.
  Every engine push now uses `--force-with-lease` on a remote head Fabrik has verified. An
  unreadable remote refuses the push. The #2089 zero-ahead guard stays in front. See ADR 2295.
- **A Validate run that ends after its PR merged takes the terminal path** (#2299, reported
  in #1810). Validate completion reads the linked PR live. If it has merged, the item goes to
  Done instead of arming `fabrik:awaiting-ci` on a merged PR. A PR that was closed without
  merging pauses the item. A merge is deferred while a worker for the item is running, and no
  push is attempted for a merged PR. See ADR 2299.
- **Unknown merge state is bounded, and the CI-timeout pause names the real blocker**
  (#2302, reported in #1809). Details are under "Upgrading". A clock starts at the first
  `unknown` reading for a head. It resets when GitHub computes a state or the head changes,
  and it never fires on the first evaluation after a start. The CI backstop pause now reads
  which gate held the item: the CI gate keeps today's text, and any other gate is named with
  its reason and the check-run state. See ADR 2302.
- **First-occurrence pause on an ungrantable denied edit** (#2301, reported in #1981).
  Details are under "Upgrading". Fabrik decides from the `--allowedTools` it actually passed,
  never from prose. The pause comment names the path and gives three options. It is not a
  failure and does not touch `max_retries`. See ADR 2301.
- **The tools-denied exemption requires a causal denial** (#1556). A run that hit any
  permission denial used to be exempt from `max_retries`. It is now exempt only when the
  denial plausibly stopped it: no commit, a denial tied to a write-capable tool call on the
  main thread, and no later successful edit. Other runs count as ordinary failures.
- **A comment-review or reinvoke run can block on input** (#2280). `FABRIK_BLOCKED_ON_INPUT`
  from a comment pass, CI-fix, review or rebase reinvoke now pauses the item as on the stage
  path. The comment is marked processed and the cycle breakers are not charged.
- **Every resume path clears the comment breaker** (#1575). `fabrik:revalidate` (and the
  merge-train auto-repair that reuses it) and a Validate SHA invalidation cleared the cycle
  counters but not the #1089 comment circuit breaker. All four resume paths now reset both.
- **A time-sliced stage resumes its session** (#2292, a v0.0.85 regression from #2232). A
  turn-cap or `max_wall_time` stop skips the retry backoff by design. The same change also
  made the continuation start a fresh Claude session, losing the conversation. The backoff
  exemption is now a separate flag, so the continuation resumes again.
- **`resume_session` and `resume_threshold_tokens`** (#2300, reported in #1909). A stage can
  set `resume_session: fresh` or `auto` to start comment review and stage re-entry in a fresh
  Claude session. `auto` starts fresh only when the saved session's last measured context
  exceeds `resume_threshold_tokens` (default 250000). A continuation always resumes. A fresh
  re-entry gets the stage's previous output as a context file. The decision is logged once per
  invocation. See ADR 2300 and `docs/stage-lifecycle.md`.
- **One resolver for `CLAUDE_CONFIG_DIR`** (#2293, reported in #1807). Details are under
  "Upgrading". The `.env` values are read as data and never exported, so a SIGHUP or
  self-upgrade re-exec cannot mistake them for an inherited value. Startup logs one `Claude
  profile` notice, the warnings panel shows a disagreement, and the TUI footer shows the
  account. See ADR 2293.
- **Spawned child specs start from the base branch** (#1784, reported in #1703). The Plan,
  Review and Validate skills now tell the stage that a child issue starts from the base
  branch, so its spec must not treat the parent's unmerged files as present. Review and
  Validate document `DEPENDS_ON:` for sibling order.
- **Dev self-upgrade matches the remote exactly** (#1209). The source-checkout check behind
  `git pull`, rebuild and re-exec used a substring match on the origin URL, so a look-alike
  remote passed. It now accepts only `github.com/<owner>/<repo>` in https, `ssh://` or scp
  form. Pruefer shares the check. See ADR 1209.
- **No stray startup prints over the TUI under App auth** (PR #2217). The HTTPS credential
  notice and the hourly `installation token refreshed` line now go to the log pane and log
  file.

## Pruefer

- **Claude account resolution** (#2294, reported in #2025). Pruefer uses the same resolver
  as Fabrik. Every review subprocess carries the resolved `CLAUDE_CONFIG_DIR`, a reload
  applies a changed value to the next review, and startup logs the account and its source.
  New: `claude_config_dir` in `.pruefer/config.yaml`, `-claude-config-dir`,
  `PRUEFER_CLAUDE_CONFIG_DIR`. A reviewed repo cannot set it.
- **No re-review of an unchanged patch** (#2230). Pruefer compares a new head's diff with the
  last head it fully reviewed and skips the review when they are identical: a rebase with no
  change, a clean catch-up, or a merge-train trial PR whose files each match one completely
  reviewed member. It still reviews when unsure, and at most 4 skips run in a row before a
  real review. `/pruefer review` bypasses the skip. Kill switch: `patch_skip`
  (`--patch-skip`, `PRUEFER_PATCH_SKIP`), on by default. Skip counts show in the TUI footer.
  See ADR 2230.
- **Transcripts of partial-coverage reviews are kept** (#2303). `keep_transcripts:
  partial|all|off` (default `partial`) saves the raw review stream under
  `.pruefer/transcripts/` (mode 0600, capped at 50 files). The coverage warning names the
  file. Transcripts contain the code the reviewer read and stay local.
- **TUI**: a Fabrik-style status bar with the Claude profile and version (PR #2191). Pane rows
  are truncated by display width, so wide characters no longer break the layout (PR #2189).

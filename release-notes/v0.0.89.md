# Fabrik v0.0.89

## Summary

**The engine stops looping on things it cannot finish.** A community report (#2388)
showed a stage running again and again after it had already finished, while GitHub
writes were failing. Fabrik now refuses to start a worker when it cannot take the issue's
lock. It holds all new work while GitHub is unreachable, and it records a finished stage
and publishes that result later instead of running the stage again. It also caps how many
times one stage of one item is dispatched before pausing for a human.

**State that holds up under webhooks, restarts and concurrent writes.** One ordering
rule now decides between webhook, listing, deep-fetch and live reads: an older read never
overwrites a newer fact. Gates now decide from fresh live reads. Merge-train caps and the
usage-limit hold survive a restart. All webhook transports share one intake that drops
duplicate deliveries. Fabrik now applies more webhook events directly: dependencies,
review threads, label, milestone and sub-issue changes, and comment edits.

**New overseer action:** `fabrik_set_blocked_by` adds or removes blocked-by edges from
an MCP session. It checks for cycles before writing.

## Features
- `fabrik_set_blocked_by` overseer action: add or remove an item's blocked-by edges, guarded against self-blocks, PR blockers and cycles (#2385)
- `max_stage_dispatches` (default 25, `0` disables): pause an item after its stage has been dispatched that many times in one episode. An unchanged re-dispatch of an oversized closed session starts fresh instead of resuming it (#2395)
- A transport-neutral webhook intake: one persisted delivery dedupe and per-item serial apply queue for every transport, with an engine-level echo registry (#2351)
- Webhook events for facts the engine uses: `sub_issues`, `pull_request_review_thread`, `label`, `milestone`, and comment `edited`/`deleted` are applied directly (#2352)
- `issue_dependencies` webhooks wake and re-check the affected items, and a closing blocker refreshes its dependents (#1995)

## Fixes
- A stage worker is never spawned when the `fabrik:editing` lock label can't be written. While GitHub is unreachable, dispatch, reinvokes and conflict resolution hold (#2393)
- A stage that finished is recorded and its output is published by retry, never re-run (#2394)
- The board cache never serves an empty project ID, and every board write defers when the ID is unknown (#2396). A cache started on an empty board now bootstraps on a later poll (#2411)
- A forced Validate re-run is completed only by a Validate stage run, never by a comment-review pass or a catch-up landing (#2378)
- A usage-limit refusal of a reinvoke or comment review now waits until the hold lifts, instead of looping through refused workers (#2407)
- `projects_v2_item` webhooks are decoded from `node_id`, so board column changes are applied from the delivery itself (#2383)
- Hookdeck reconnects log their cause (#2384)
- The self-write freshness baseline is anchored to GitHub's own timestamps, never the daemon clock (#1945)
- Pruefer removes the empty `memory/` directory the Claude CLI leaves in a review's profile folder (#2406)

## Improvements
- One observed-at ordering rule for every write into the item Store (#2348)
- Gate decisions read live and apply the read to the Store. Dispatch re-reads the candidate first (#2350)
- Merge-train ejection counts, trial-rate window, auto-repair attempts and the usage-limit hold survive a restart (#2349)
- Documentation updated for v0.0.88 (#2381)

## Upgrading

- **New dispatch bound** (#2395): an item whose stage is dispatched 25 times in one episode
  is paused with `fabrik:paused` + `fabrik:awaiting-input`. Raise it with
  `--max-stage-dispatches` / `FABRIK_MAX_STAGE_DISPATCHES` / `max_stage_dispatches`, or set
  `0` to disable. A negative or non-integer value is refused at startup.
- **Webhook events** (#2352): `gh webhook forward` (`--webhooks`) picks up the new events on
  restart. A hook you created yourself keeps its own event list: to get these events, add
  `sub_issues`, `pull_request_review_thread`, `label` and `milestone` to the organisation
  hook, repository hook, GitHub App or Hookdeck source. Until you do, Fabrik learns those
  facts from its normal fetches as before.

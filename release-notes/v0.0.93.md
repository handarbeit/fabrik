# Fabrik v0.0.93

## Summary

**Review verdicts your CI can wait on.** With the new opt-in `review_status` setting, Fabrik
publishes a `fabrik/review` commit status on each PR head: pending while expected reviewers
have not cleared the head, then success or failure. Branch protection and other CI can wait
on it, and a wait for review is reported as a review wait rather than a CI timeout.

**Fewer needless re-checks with webhooks.** Admission cooldowns are now scheduled by kind.
While webhook delivery is healthy for a repo, the periodic safety-net re-evaluation runs
every 30 minutes instead of every ten poll intervals, and deadline timers wake the poll exactly when they
are due.

**Workspace on another disk.** A new `workspace_root` setting puts worktrees, clones,
sessions and logs anywhere you like, while config and state stay in the Fabrik directory.

**Steadier review gate and merge train.** A dismissed review no longer hides the same bot's
later review, so the gate stops timing out on a head that was already reviewed. The merge
train no longer lands a trial before GitHub Actions has started its CI, and it writes a
multi-member trial's conflict resolution back to the member branch.

## Features
- `fabrik/review` commit status: opt in with `review_status` (stage or config key). Fabrik publishes `pending`/`success`/`failure` on the PR head from the per-reviewer verdict at that head. It needs the App's `statuses: write` permission only when enabled. While it is pending, the CI wait clocks are attributed to the review wait, and the backstop pause says "review wait timeout" (#2471)
- Configurable workspace root: `workspace_root` / `--workspace-root` / `FABRIK_WORKSPACE_ROOT` relocates worktrees, bare clones, sessions, logs and debug output. The root must already exist and is never created. Changing it while the previous root still holds worktrees is refused, not migrated (#2470)
- Merge train: a conflict resolved while assembling a multi-member trial is written back to the member's own branch, so the next trial does not need to resolve it again (#2572)

## Fixes
- Review gate: a dismissed review no longer hides the same author's later `COMMENTED` review, which made the gate time out on a head the expected bot had already reviewed. Reported in #2582 (#2588)
- Merge train: a trial or landing with zero check runs is held while the member PRs show the repository runs CI, instead of being landed before GitHub Actions has started (#2593)
- Board cache: a webhook receipt time is no longer written back as GitHub's `updatedAt`, which caused a self-inflicted reconcile drift loop on busy PRs (#2573)
- Every engine log line ends with exactly one line ending, so lines no longer run together (#2583)
- The PM plugin's version-check hook names the side that is behind and gives only that side's remedy (#2584)

## Improvements
- Admission cooldowns are classified (short retry, timer, event-replaceable, safety net). While webhook ingestion is reliable for a repo, event-replaceable holds wait for their event and the periodic re-evaluation runs every 30 minutes instead of every ten poll intervals (5 minutes at a 30-second poll) (`periodic_reeval_interval`, `0` = auto). When ingestion stops being reliable, it falls back to the poll-based interval at once. Deadline timers (review wait, CI backstop, merge-queue stall and others) wake the poll exactly when due (#2532)
- A CI check fails a PR whose title, body or commits would auto-close a community report (#2576)
- Documentation updated for v0.0.92, including delivery replay and the Hookdeck migration (#2570)

## Upgrading

```bash
# Auto-upgrade from a running Fabrik instance
# Fabrik checks for new releases each poll cycle and upgrades automatically with --auto-upgrade

# Or download directly (auto-detects OS and architecture)
gh release download --repo handarbeit/fabrik \
  --pattern "fabrik_*_$(uname -s | tr A-Z a-z)_$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/').tar.gz" \
  -O - | tar xz
```

**Periodic re-evaluation is now 30 minutes with webhooks.** If your instance receives webhooks (`event_source: tailscale` or `direct`), the safety-net re-evaluation of idle items runs every 30 minutes while delivery is healthy, instead of every ten poll intervals. To choose your own cadence, set `periodic_reeval_interval` (minutes). Poll-only instances are unchanged.

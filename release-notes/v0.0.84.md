# Fabrik v0.0.84

## Summary

**A Claude Code session can now oversee a running Fabrik daemon directly.** This is the
release's headline. The daemon serves a local API on a private per-project socket, and the
new `fabrik mcp` stdio server exposes it to Claude Code as tools. The tools answer "what
needs me?" from state the daemon already holds, at no GitHub API cost. A small set of
audited actions can promote, advance, park, change autonomy, revalidate, or clear a Claude
usage-limit hold. Events (a settled Validate, a pending decision, a pause, an arrival, a
column move, a merge, a stalled poll loop) are pushed into the session as they happen. The
`fabrik` PM plugin is rebuilt around this and now ships pinned to each release, so
installing it is the easy way to turn the feature on.

**Stage skills are addressed by their real names, and customising them no longer strands
a project.** Claude Code registers plugin skills under their plugin's namespace. Fabrik
prompted bare names, which Claude models quietly bridged and other models did not (#1373).
Every skill key now accepts `plugin:skill`. The base stage plugin is renamed
`fabrik-stages`, and the `fabrik` name passes to the PM plugin. `fabrik upgrade` moves
edits to `.fabrik/plugin/` into a `local-workflows` plugin and rewrites stage YAML to
qualified names. A skill reference that does not resolve, or a skill that fails to load in
the worker, is now always reported. Before, the stage could complete without its
instructions. **This needs an explicit `fabrik upgrade`; see "Upgrading".**

**The merge train was reworked around the early-October incidents.** Those incidents had
finished work paused overnight, throwaway trial PRs for every behind singleton, flakes
ejecting unrelated members, and a CI run that never started holding a slot for two hours.
A behind singleton now catches up on its own branch and lands without a trial. A red
singleton is repaired through Validate once before anyone is paged. Batches avoid members
that touch the same files. A run that never starts and a single flake are treated as
infrastructure. Trial state is persisted, so a restart resumes a trial or bisection. The
train has a reserved worker slot and holds a slot only while Claude is resolving a
conflict. Several of these change default behaviour; read the merge-train section before
upgrading a train-enabled project.

**The board shows what Fabrik is doing, and operator faults have one place to land.**
Three optional display-only project fields are written: `Fabrik` (a one-line status),
`Last activity` and `Last run`. `fabrik init --create-board` and `fabrik repair-board
--apply` create them. The TUI warnings panel now collects operator-level faults that used
to scroll past as log lines, from unrecognised config keys to missing display fields.

**The engine's view of an item is harder to corrupt.** A stale board listing or probe could
revert the engine's own label, Status and close writes (#2159, #2178). An engine self-write
could hide a human comment, a review thread or a CI result from the cache (#2180). Every
reinvoke left a phantom lock behind (#2179). A catch-up landing stripped Validate
completion from landed items (#2158). The feedback gate could hold on a review the
dispatcher could not see, until someone restarted the daemon (#2160). All six are
addressed.

**Running a daemon is safer.** Two engines can no longer serve one board, and an engine
that loses its lock stops itself. A stale local branch can no longer be force-pushed over
an open PR. `fabrik.log` is rotated rather than truncated on restart. Workers no longer
inherit the daemon's own credentials. Orphaned test processes are reaped by ownership.
**Under GitHub App auth, the installation must now grant `actions: write`, or the daemon
refuses to start.**

## Upgrading

**Before you install the binary (GitHub App auth only): grant `actions: write`** (#2105).
Startup and `fabrik init --github-app` now refuse an installation that lacks it (`read` is
refused too). That includes the next self-upgrade re-exec, so an `--auto-upgrade` daemon
whose App lacks the grant will not come back up. Two manual steps are needed:

1. An App owner sets the permission at
   `https://github.com/organizations/<owner>/settings/apps/<slug>/permissions`.
2. An org admin accepts the request at
   `https://github.com/organizations/<owner>/settings/installations/<id>`.

Then restart Fabrik. The refusal message prints both URLs with your values filled in. PAT
mode is unaffected. Workers use the permission to read CI job logs and re-run failed jobs,
and the merge train and the `wait_for_ci` gate use it to re-run flakes and retrigger CI that
never started. Earlier in this cycle the permission was optional, with an advisory notice
(#2071); the notice did not lead anyone to grant it, so it is now required.

**Then, for each project:**

1. **Stop the daemon.** `fabrik upgrade` does not check for one, and changing the plugin
   under a live daemon broke a worker's skill load in testing. Note which items the stop
   pauses.
2. **Install v0.0.84 and run `fabrik upgrade`** in the Fabrik directory. It decides from
   what is on disk, not from version numbers, so skipping releases is fine, and a second run
   changes nothing. It never commits.
   - **Uncustomised `.fabrik/plugin/`:** the plugin is refreshed to `fabrik-stages`, unedited
     `skills/fabrik-*` directories from old releases are pruned, and stage skill keys are
     rewritten (`fabrik-review` and `fabrik:fabrik-review` both become
     `fabrik-stages:review`).
   - **Customised `.fabrik/plugin/`:** the whole tree moves to
     `.fabrik/plugins/local-workflows/`. Its manifest name becomes `local-workflows`, and a
     clean base plugin is restored. Stages whose skill you edited point at
     `local-workflows:<old name>`, and the rest at `fabrik-stages:<skill>`.
   - **Your own `plugin_dirs` plugins:** a bare name that one of them provides is qualified
     to that plugin, not switched to Fabrik's skill.
   - Only the four skill keys in `.fabrik/stages/*.yaml` are edited. Comments and quoting
     are preserved.
3. **Review the diff and commit it.**
4. **Run `fabrik repair-board`, then `fabrik repair-board --apply`**, to add the three
   display fields. Otherwise each start shows a "Display fields missing" warnings-panel
   entry. Set `project_fields.status_line` / `last_activity` / `last_run` to `off` in
   `.fabrik/config.yaml` if you don't want them.
5. **Restart the daemon and check the warnings panel.** Then unpause the items the stop
   paused by removing `fabrik:paused` and `fabrik:awaiting-input`.

Replacing only the binary does not break anything. Old skill references keep resolving,
with a `skill_reference_deprecated` panel notice. A customised install also shows "Workflow
migration pending — run 'fabrik upgrade'". The daemon never migrates on its own; the
dev-build auto-upgrade runs `fabrik upgrade --no-migrate`. `--no-migrate` keeps the old
behaviour. To undo a migration, restore `.fabrik/plugin`, `.fabrik/plugins/local-workflows`
and `.fabrik/stages` from git.

**From now on, customise only `.fabrik/plugins/local-workflows/`.** An edit to
`.fabrik/plugin/` blocks the next `fabrik upgrade` ("workflow migration refused"). To keep
the edit, move it into `local-workflows`, point the stage at `local-workflows:<skill>` and
run `fabrik upgrade --force`. To drop it, just run `--force`.

**Other changes to check:**

- **Worker environment** (#2027). Workers now receive only six engine-set `FABRIK_*`
  variables: `FABRIK_ISSUE`, `FABRIK_REPO`, `FABRIK_WORKTREE`, `FABRIK_ROOT`, `FABRIK_PR`
  and `FABRIK_WORKER_OWNER`. A custom skill or script that reads any other must name it in
  `FABRIK_WORKER_ENV_PASSTHROUGH`.
- **Merge-train defaults.** These are on by default when `merge_train` is on:
  - The singleton catch-up pushes merge commits onto PR branches (`singleton_catch_up: off`
    to disable).
  - Red singletons get one auto-repair before pausing (`max_train_auto_repair_attempts: 0`
    restores the pause).
  - Members touching the same path are never batched together. List lockfiles, changelogs
    and similar in `merge_train_overlap_ignore`.
  - The host can run `max_concurrent + 1` Claude processes, because of the reserved train
    slot.
- **Spec persistence is opt-in for existing stage files** (#2034). An existing
  `specify.yaml` lacks `persist_spec: true`. The drift warning names it, and `fabrik
  refresh-stages --apply` adds it.
- **Log files.** Add `.fabrik/fabrik.log.*` to `.gitignore` (#2094).
- **PM plugin users:** run `/plugin marketplace update fabrik`, `/plugin install
  fabrik@fabrik` and `/reload-plugins`. If you registered `fabrik mcp` by hand, remove that
  registration (`claude mcp remove fabrik`) or you will run two servers. `entwurf@fabrik` is
  no longer served from this marketplace; Entwurf has its own.
- **Pruefer operators:** if `claude` authenticates through an environment variable (for
  example `CLAUDE_CODE_OAUTH_TOKEN`), name it in `PRUEFER_REVIEW_ENV_PASSTHROUGH` (#2192).
- **Plan comments damaged under v0.0.83** (PR #2216). v0.0.83's Implement skill replaced
  the whole Plan comment with the literal text `@/tmp/…` each time it ticked a task. Look
  for Plan comments whose body is a bare `@/…` path, and restore each from the comment's
  GitHub edit history; the previous revision holds the original Plan.

```bash
# Auto-upgrade from a running Fabrik instance
# Fabrik checks for new releases each poll cycle and upgrades automatically with --auto-upgrade
# (App auth: grant actions: write first — see above)

# Or download directly (auto-detects OS and architecture)
gh release download --repo handarbeit/fabrik \
  --pattern "fabrik_*_$(uname -s | tr A-Z a-z)_$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/').tar.gz" \
  -O - | tar xz
```

## MCP overseer

To turn it on, install the PM plugin (`/plugin marketplace add handarbeit/fabrik`, then
`/plugin install fabrik@fabrik`), which registers the server. Alternatively, register the
server by hand with `claude mcp add fabrik -- fabrik mcp --dir /path/to/fabrik-dir`; do
not do both. The socket is `.fabrik/state/fabrik.sock` (mode `0600`), with a fallback under
`/tmp/fabrik-<uid>/` when that path is too long. Actions and pushes need a subscriber name
(`--subscriber` / `FABRIK_SUBSCRIBER`, or the plugin's setting). Pushes use Claude Code
Channels (research preview), so start the session with
`claude --dangerously-load-development-channels server:fabrik`, or with
`plugin:fabrik@fabrik` when the server comes from the plugin. Without that flag, events
are silently dropped.

Tools: `fabrik_status`, `fabrik_board`, `fabrik_health` and `fabrik_situation` (read);
`fabrik_promote`, `fabrik_advance`, `fabrik_move_parked`, `fabrik_set_autonomy`,
`fabrik_revalidate` and `fabrik_clear_claude_limit` (actions); `fabrik_subscribe` and
`fabrik_unsubscribe`.

- **Read tools over a per-daemon socket** (#1967). `fabrik_status(issue)` reports an item's
  place, cycle counts as `n of max`, worker, last invocation, PR/CI/merge-train position,
  blockers, and an `attention` verdict (`needs-human`, `suspended`, `escalated`, `waiting`,
  `working`, `stalled`, `idle`) that says whether the item is stuck or correctly waiting.
  `fabrik_board` has `attention` and `flow` views, filterable by milestone, label, repo,
  column and open blockers. `fabrik_health` reports poll, webhook and reconcile freshness,
  the usage-limit hold, GraphQL backoff, worker slots and merge-train partitions. Every
  response carries `as_of`, and anything the daemon cannot vouch for is the string
  `"unknown"`, never a healthy-looking default. With no daemon running, a tool returns
  "Fabrik daemon not running at <path>" instead of hanging. New reporting-only flag:
  `--stall-threshold` / `FABRIK_STALL_THRESHOLD` (default 30m).
- **Push events** (#1968). The headline event is `validate-settled`. It fires once per
  settle episode, when Validate is gate-complete (CI green, review gate clear, no
  unprocessed feedback), and says what happens next: auto-merge, the merge train, or a
  human. Pause, stall, timeout, merge-train, merge and usage-limit events are also pushed.
  Subscriptions and per-subscriber held queues persist under `.fabrik/state/`. The stream
  survives daemon restarts, and the shim itself reports `daemon-unreachable` /
  `daemon-reachable`.
- **Overseer actions** (#1969, #2126, #2188). Each action is guarded. A refusal returns the
  item's current state and writes nothing. A successful action posts one `🏭 **Fabrik —
  overseer action: <action>**` audit comment naming the subscriber.
  - `fabrik_promote` moves an item out of a parking column.
  - `fabrik_advance` moves a completed stage one column forward, through the engine's own
    advance, and refuses while anything a gate would hold on is outstanding. For Validate it
    refuses and points to the PR merge.
  - `fabrik_move_parked` moves an item between parking columns (for example Triage →
    Backlog) without starting work.
  - `fabrik_set_autonomy` sets `cruise`, `yolo` or none.
  - `fabrik_revalidate` re-enters Validate, and refuses a paused item.
  - `fabrik_clear_claude_limit` clears the usage-limit hold.

  No tool lifts a pause or posts a free-form comment. The socket is unauthenticated: any
  process running as your user can invoke these actions under the daemon's GitHub
  identity, and the subscriber name is an audit aid, not access control.
- **`fabrik_situation`** (#2171) returns the rolled-up "what needs you" view: PRs awaiting a
  merge decision under cruise, gate holds and how long they have lasted, items awaiting
  input, pending decisions, stalled items, merge-train state, poll and worker health, and
  active anomalies. Each entry names the tool that acts on it. It can also be pushed as a
  `situation` digest on a cadence (`situation_seconds`, off by default).
- **Pending decisions get their own state, with an honest age** (#2120). A completed stage
  that does not auto-advance, or an item blocked only by parked work, is now `suspended`
  (`decision-pending` / `parked-blocker`). It shows from the first poll after a restart,
  instead of surfacing 30 minutes later as `stalled`. Its age is anchored on GitHub's label
  time: in the reported case, items that had waited 68 days showed as "31m". A
  `settlement-withdrawn` event fires when a settled item stops being ready before a human
  acts.
- **Attention recognises every kind of worker and queued work** (#2121). Comment reviews
  and review, CI-fix and rebase reinvokes are reported as such, with `kind`, `trigger` and
  live turns. Work waiting for a slot shows as queued (`queued-for-slot`,
  `waiting-for-dispatch`, `retry-pending`, `gate-hold`) rather than running or idle.
  `fabrik_health.workers.in_use` can no longer exceed `max_concurrent`. A running CI-fix
  reinvoke now reads `working` even while `fabrik:awaiting-ci` is present.
- **PR state and CI verdict for every linked open PR** (#2122). Before, these read
  `"unknown"` outside CI-gated waits, which once hid a failing "Test and vet" check. A red CI
  that nothing is addressing now surfaces in attention, with the failing check named. The
  REST refresh is capped per poll, and GraphQL cost is unchanged.
- **Pipeline liveness** (#2124). `fabrik_health` now shows whether a poll is in progress,
  its current step, its next due time, any back-off and an `overdue` verdict (2× the
  interval, measured from the engine's own due time, so idle back-off is not a stall). It
  also shows gauge ages and each merge-train partition's oldest queued time, phase and idle
  reason. `pipeline-stalled` / `pipeline-resumed` are pushed once per episode. Items held up
  by a stalled poll read `waiting-for-poll` instead of `stalled`.
- **Lifecycle events** (#2123, #2187). `item-added` fires for an item arriving after startup
  in a configured column, including parking columns. `column-changed` carries from/to and
  the actor. `closed` carries `landing=true` for a Fabrik landing. The
  `progress_via_column` subscription option drops the stage-label stream. A restart no longer
  emits a flood of label events: an item's first observation is a silent baseline.
- **Events say who made a change** (#2125). Overseer actions carry `actor=overseer` and
  `via=<subscriber>`, and webhook-seen human or bot changes carry `actor_login`. Changes
  first seen by a poll or reconcile are still `unknown`; no extra GitHub read was added.
- **Restarts deliver catch-up plus downtime deltas, not replays** (#2169). After a restart a
  subscriber gets one catch-up snapshot, then the changes made while the daemon was down,
  marked `origin=downtime-delta` and `unverified=true`. A repeat `validate-settled` carries a
  `cause`. A new subscription without an `events` list now receives the semantic event
  family; raw `label-applied` / `label-removed` must be named explicitly.
- **Anomaly events** (#2170): `retry-starved` / `retry-resumed`, `item-wedged` /
  `item-unwedged` (a gate holding an item with no worker), and `cache-divergence`. Thresholds:
  `--retry-starved-threshold` (default 5m), `--item-wedged-threshold` (10m) and
  `--cache-divergence-window` (5m), each with a `FABRIK_*` env equivalent. They affect
  reporting only.
- **Shim/daemon version skew no longer empties a subscription, and unsubscribe stops
  delivery** (#2168). The daemon self-upgrades while `fabrik mcp` lives as long as the
  session. Renamed event names are now mapped and unknown ones dropped, and both are
  reported. The shim says once when its version differs from the daemon's; restart the
  Claude session to pick up the matching one. In a live test, about 250 pushes had followed
  an unsubscribe; once `fabrik_unsubscribe` returns, nothing more is delivered.
- **Issue references** (#2112): a bare `N`, `#N` or a JSON number now resolves on a
  multi-repo daemon when the cached issues are all in one repo. With several repos, the
  error lists the real `owner/repo` choices instead of a phantom `handarbeit/`.
- **`fabrik_promote` works on installs without `backlog.yaml`** (#2113). A bare `Backlog`
  column is a parking column everywhere, as the rest of the engine already assumed.
- **`fabrik mcp` finds the project from a subdirectory** (#2207). It walks up to the nearest
  `.fabrik/` (never above `$HOME`), and starts no channel stream outside a Fabrik project.
  `--dir` / `FABRIK_MCP_DIR` are used as given.
- **"Suspension" is now "usage limited"** (#2129) across health fields, events
  (`claude-usage-limited`, `claude-usage-limit-lifted`) and the TUI banner ("Claude usage
  limit hit — dispatch held."). The labels and `fabrik_clear_claude_limit` are unchanged.
- **Read-surface polish** (#2127). The flow view counts the closed items it omits.
  `fabrik_status` adds `other_labels`. Invocation figures say which ones are per-invocation
  and which are session-cumulative. Reviewer verdicts are evaluated at the PR head, so a
  clean Pruefer pass and one with findings no longer both read `COMMENTED`. Item-scoped
  pushes carry the issue title.

## Workflow plugins and skills

- **Stage skills are addressed by fully-qualified `plugin:skill` name** (#2137; community
  report #1373 by @bdueck). With a non-Claude model behind LiteLLM, the reporter measured 25
  of 26 `Skill` calls failing with "Unknown skill", and some Implement runs went to 292 turns
  without ever loading their skill. `skill`, `comment_skill`, `ci_fix_skill` and
  `rebase_skill` now accept `<plugin>:<skill>`, and the prompt carries that exact name.
  References are resolved against the plugins actually loaded for the worker. Bare names
  still work, with a deprecation notice.
- **An unresolvable skill reference stops the stage before a worker starts** (#2137).
  Fabrik posts one "🏭 **Fabrik — skill reference unresolved**" comment naming the
  reference, the plugins searched and their paths. It applies `fabrik:skill-unresolved` and
  records a warnings-panel entry. This is not a failure: no retry charge, no pause, and
  cycles are refunded. The label clears itself once the reference resolves.
- **A stage whose skill failed to load is paused, never completed** (#2138). Before, a
  worker whose `Skill` call failed could still print `FABRIK_STAGE_COMPLETE` and advance,
  having run without its instructions. The failure is now read from the worker's structured
  tool-call record, never from prose. The item is paused (`fabrik:paused` +
  `fabrik:awaiting-input`) with a "🏭 **Fabrik — skill failed to load**" comment and a
  `skill_load` panel entry. No retry is charged and no `stage:<name>:failed` is applied.
  Check the plugin registration, then unpause.
- **Workers can load several workflow plugins** (#2136). `plugin_dirs` (YAML list),
  `--plugin-dirs` or `FABRIK_PLUGIN_DIRS` (comma-separated) add plugins after the base stage
  plugin. `--plugin-dir` still replaces the base plugin. Startup fails, naming the path, on
  a missing directory or two plugins with the same manifest name.
- **The base stage plugin is renamed `fabrik-stages`** (#2140). Its twelve skills drop the
  `fabrik-` prefix (`fabrik:fabrik-review` → `fabrik-stages:review`). Every worker now runs
  with `fabrik@fabrik` disabled, so the PM plugin and its MCP server never load inside a
  worker.
- **`fabrik upgrade` migrates workflows** (#2139, #2203, #2198). See "Upgrading" for what it
  does. Customisation is judged per file against every version Fabrik has shipped, so a
  copy that is merely old is refreshed, not moved. A bare name that a project plugin
  provides stays on that plugin's skill (#2203). The migration is tested against
  deployments from v0.0.64, v0.0.70 and v0.0.77 that have no `.installed-version` file
  (#2198).
- **`fabrik upgrade` reports what it changed** (#2219). On an up-to-date install it used to
  claim `refreshed 15 plugin file(s)` and re-timestamp every file. Byte-identical files are
  now skipped, and an up-to-date install prints `fabrik upgrade: plugin already up to
  date`.
- **The `fabrik` PM plugin is rebuilt on the local API and released with each version**
  (#2141, PR #2222). It bundles `fabrik mcp` and drops its GraphQL and `ps` scraping. Its
  version follows the binary's, and a SessionStart hook prints one line when they differ
  (`FABRIK_PLUGIN_VERSION_CHECK=off` silences it). Its guidance now starts from
  `fabrik_situation`, describes customising through `local-workflows`, and gives the
  ordered project-upgrade procedure above.
- **`entwurf@fabrik` removed from the Fabrik marketplace** (PR #2095). It was a stale frozen
  copy; Entwurf lives in its own repository and marketplace. An installed copy keeps
  working but no longer updates from here.

## Stage skills and worker context

- **Implement no longer wipes Plan comments** (PR #2216). The skill ticked tasks with
  `gh api … -f body=@file`, and `-f` sends the value literally. It now uses `-F`, and a test
  rejects `-f key=@…` anywhere in the shipped plugins. See "Upgrading" for recovering
  comments damaged under v0.0.83.
- **Specify commits its spec to the repository** (#2034). With the new stage key
  `persist_spec: true` (set in the shipped `specify.yaml`), the engine writes the updated
  issue body to `specs/<issue>-<slug>/spec.md` after each round and commits only that file,
  so the spec appears in the PR diff beside the code. `## Open Questions` is stripped, an
  unchanged spec makes no commit, and errors never fail the stage. The skills now author
  Spec Kit-structured specs (prioritised user stories, `FR-NNN`/`SC-NNN`, edge cases)
  without needing `.specify/` or `uv` in your repo.
- **Specify keeps sections a human added to the issue body** (#2088). A non-template section
  such as `## Human Decisions` used to be dropped by the next Specify round (report #2056).
  It is now carried forward verbatim.
- **Workers know the CI verdict for the PR head** (#1997, #2116, #2130). Each run on an item
  with an open PR gets `.fabrik-context/ci-status.md`: the head SHA, Fabrik's verdict
  (`green`/`red`/`pending`/`none`/`unknown`), `ci_gated` and `ci_gate_ahead`, plus a
  `## Failing checks` section for a red verdict. Skills skip the local full suite when CI is
  green on the exact clean head, and reproduce only the failing checks when it is red. On a
  CI-gated stage they never run the full suite locally: they run targeted tests, with a
  5-minute timeout that is never raised and no background polling. On #2097 a Validate
  worker had run about seven overlapping full suites into its 60-minute wall time, while CI
  ran the same suite in 7–8 minutes. The test-running skills no longer name any one
  toolchain's commands.
- **CI-fix prompts carry the failure itself** (#1991). For each newly failing check, the
  CI-fix reinvoke prompt now includes up to 5 check-run annotations plus the check's output
  summary and text. The prompt is logged as `[#N ci-fix-reinvoke] prompt (…)`, since it is
  never posted to GitHub.
- **Marker headers are parsed case-insensitively, and failures show what was found** (#2091;
  community report #2055 by @bdueck). A model writing `title:` instead of `TITLE:` in
  `FABRIK_PR_CREATE` paused a finished Implement stage before its work was pushed, with an
  error that did not show the line it found. Keys now match regardless of case and
  surrounding whitespace, errors quote the offending line, and the work is committed and
  pushed before any pause. A malformed `FABRIK_SPAWN_CHILD` block now pauses with a comment
  naming the block, instead of being skipped silently.

## Merge train

- **A behind singleton catches up on its own branch and lands through the fast path**
  (#2044). Before, every behind singleton built a trial branch and draft PR, ran 10–25
  minutes of CI, and was then discarded, leaving the member stale. Now the engine merges the
  pinned base into `fabrik/issue-N` as a merge commit (lease-protected, no force-push), waits
  for the PR's own CI, and lands it. It defers, uncharged, while a stage is running, while
  `fabrik:editing` is set or while the worktree is dirty. A rejected push or CI that never
  starts falls back to a trial, also uncharged. Bot review findings on a pure catch-up head
  are ignored, using the engine's own marker comment, never the commit trailer; human
  comments still count. Config: `singleton_catch_up: merge | off` (`--singleton-catch-up`,
  `FABRIK_SINGLETON_CATCH_UP`), default `merge`.
- **Repos that reject catch-up pushes by policy are remembered for 24 hours** (#2065). On a
  `GH006`/`GH013` rejection (protected branch, repository rule), singletons in that repo go
  straight to the trial, with one log line naming the repo and the `singleton_catch_up: off`
  switch. The memo is held in memory and cleared on restart.
- **A no-commit comment pass no longer forces a full trial** (#2150). A comment, review or
  CI-fix pass rebases the worktree before Claude runs. When nothing was committed, that
  rebase was left unpushed, and the catch-up read the divergence as local work. The rebase
  is now undone when that is provably safe, and the catch-up accepts a branch that differs
  from its remote only by a pure rebase.
- **A red singleton is repaired through Validate instead of paused** (#2045). On
  liminis-models (2026-10-04/05), five members sat paused overnight with semantic conflicts
  against just-landed work. Each needed the same human fix. The engine now re-enters
  Validate itself and posts `🏭 **Fabrik merge-train — auto-repair started**`. The worker
  gets the train's diagnostic in `.fabrik-context/merge-train-repair.md`, with an
  instruction never to revert what landed. Only at the cap does the member pause, and the
  pause comment lists the attempts. Config: `max_train_auto_repair_attempts`
  (`--max-train-auto-repair-attempts`, `FABRIK_MAX_TRAIN_AUTO_REPAIR_ATTEMPTS`), per member
  per base SHA, default `1`; `0` restores the old pause exactly.
- **Batches no longer combine members that edit the same files** (#2047). A fresh batch never
  admits two members that change the same path, and the deferral is logged as `deferred #B:
  overlaps #A on <path>`. A member deferred three formations in a row goes first. An
  unreadable or truncated file list is admitted as before. After a landing, a local
  `git merge-tree` check sends any still-Queued member that now really conflicts back to
  Validate, with `fabrik:rebase-needed` and one comment. This is not an ejection and does
  not pause. Config: `merge_train_overlap_ignore` (`--merge-train-overlap-ignore`,
  `FABRIK_MERGE_TRAIN_OVERLAP_IGNORE`), a glob list, empty by default.
- **A CI run that never starts, or a single flake, is treated as infrastructure** (#2052). A
  GitHub Actions `startup_failure` leaves no check runs, so a trial waited up to the 4-hour
  backstop. One held a worker slot for 2 hours, and on a repo with no required checks, zero
  checks could even read as green. The trial PR is now closed and reopened to retrigger CI
  (at most twice). If CI still does not start, the trial is abandoned uncharged, and the
  partition waits 5 minutes. A first confirmed check failure re-runs the failed jobs once
  before the batch is called red, so a single flake no longer gets an unrelated member
  ejected. The stage `wait_for_ci` gate handles a run that never starts the same way, then
  pauses naming the run. The trade-offs: a genuinely red trial is detected one CI cycle
  later, and the reopen re-triggers review bots.
- **Merge-train runs survive a restart** (#2051). Each (repo, base) run is persisted under
  `.fabrik/state/merge-train/` and evaluated on every poll. After a restart, the engine
  resumes the same trial PR or bisection step if GitHub still agrees. A trial past its CI
  deadline is surfaced within one poll, and a trial that is only waiting on CI no longer
  blocks an auto-upgrade restart.
- **The train has a reserved worker slot, and holds a slot only while Claude resolves a
  conflict** (#2046, #2115). The train used to hold a `max_concurrent` slot through its whole
  10–25 minute trial-CI wait, and landing queued behind long Implement sessions. It now
  takes a slot only around each conflict-resolution call, and gets one slot on top of
  `max_concurrent` that stage work can never take. The startup banner reads `workers: N (+1
  reserved merge-train slot)`, and the TUI shows e.g. `slots 5/5 + train 1/1`.
- **The poll loop no longer blocks when every worker slot is busy** (#2114). On the dev
  daemon a poll stalled for over 10 minutes against `poll: 180`, and merge-train
  evaluation and settle scans stalled with it. A candidate with no free slot is now deferred
  with nothing recorded against it, and picked up next poll: `[poll] deferred dispatch of N
  candidate(s) …: all worker slots busy`.
- **The one-at-a-time fallback can land a green singleton again** (PR #2032). Every green
  singleton failed with a 422 ("A pull request already exists"), because the engine opened a
  second PR on a trial branch that already had one. Green trials on concept-maps were
  discarded this way. The existing trial PR is now reused.
- **The stage `wait_for_ci` gate re-runs failed jobs once before dispatching a CI-fix
  worker** (#2072), and once more after a CI-fix run that pushed nothing. Before, a flaky
  failure the worker could not fix left the item red until the CI timeout paused it. The
  re-run posts no comment and does not count against CI-fix cycles.
- **The TUI merge-train row shows live membership and phase** (#2050), for example `3 of 5:
  #1555 #1562 #1576 (ejected #1549 #1560)`, followed by the phase (`assembling`, `waiting for
  slot`, `trial CI #NNNN`, `bisecting (step n)`, `landing`, `catching up #N`, …) and the time
  spent in it. Each run leaves one History entry with its real outcome (`landed`, `red →
  bisected`, `ejected`, `abandoned`, …) instead of "skipped".
- **A `base:<branch>` member waiting in Queued now batches after a daemon restart** (#2250).
  Present since v0.0.81 (#1648). A Queued member labelled `base:<branch>` needs its repo's
  worktree manager to resolve its base, and only a stage run registered that manager. After
  a restart, if nothing else in the repo ran a stage, every such member was skipped on every
  poll, indefinitely. The train now registers the repo itself before it groups Queued
  members. Members on the default base were not affected. The release gate found this.

## Board display fields and the warnings panel

- **A `Fabrik` status-line field on every card** (#2048). Fabrik writes one line of up to 60
  characters into a **Text** project field saying what it is doing with the item. Examples:
  `trial #1692 · CI running`, `bisecting · step 2 of 3`, `Implement · running`, `blocked by
  #1568`, `paused: <reason>`, `awaiting CI on PR #N`. The field is display-only: nothing
  reads it back, it is written only on change, and it is cleared at Done. Config:
  `project_fields.status_line` (YAML only; default `Fabrik`; `off` disables).
- **`Last activity` and `Last run` fields** (#2049) let you sort and group the board by
  recency and outcome. `Last activity` is a **Date** (UTC date of the latest job start or
  finish). `Last run` is **Text**, for example `Validate · completed · 42/250 turns · 18m`.
  Config: `project_fields.last_activity`, `project_fields.last_run` (YAML only, on by
  default, `off` disables).
- **`init --create-board` and `repair-board --apply` create the display fields** (#2110).
  `fabrik repair-board` reports missing fields alongside missing Status columns. Repair only
  ever creates fields: a same-named field of the wrong type is reported and left alone. If
  creating a field fails, `--create-board` keeps the board and its config and exits
  non-zero, naming the field. The engine never creates fields at runtime.
- **A board without the fields gets one clear panel entry** (#2218). Before, every start
  logged three misleading `could not look up … field` warnings and then retried the lookups
  for the life of the daemon. Missing fields are now reported once as **Display fields
  missing**, with `fabrik repair-board --apply` as the fix action.
- **Operator-level failures reach the TUI warnings panel** (#2135). New entries cover
  unrecognised config keys, invalid settings that fell back to defaults (one entry instead of
  about 60 log lines), a gitignored config file, a fine-grained PAT, local plugin
  customisations, a missing git credential helper, an unreadable Claude settings file,
  badly ordered timeouts, a failed log rotation, and repos receiving no webhooks. Each entry
  names its fix where there is one and clears when the condition clears. A dismissed entry
  returns only if the condition changes materially.
- **A local API that fails to start is a warnings-panel entry** (#2223). Before, the only
  trace was one log line, and the MCP tools then reported the daemon as not running. The
  entry clears on the next successful start.

## State and cache correctness

- **A stale board listing no longer reverts the engine's own writes** (#2159). GitHub's
  listing lags writes by seconds. A reconcile 1–2 s after a write restored the old value and
  left the cache wrong for about 3 minutes. A removed `fabrik:awaiting-ci` came back, gate
  labels went missing, and shutdown tried to remove lock labels already gone, in a burst of
  404s. The engine's own writes now win against any listing fetched within 30 s of them.
  Later listings still correct real drift.
- **The board probe follows the same rule for Status and close** (#2178). A reverted Status
  could re-dispatch a stage that had just completed, and a reverted close could re-admit a
  landed item.
- **Engine self-writes no longer hide external changes** (#2180). Each engine write moved the
  cache's "fresh as of" mark to the local clock. A human comment, a review-thread comment or
  a CI result with an earlier GitHub timestamp was then never seen as new, and the item
  stalled until something unrelated changed or the daemon restarted. A cached copy is now
  served only when the issue/item timestamp, the linked PR's own timestamp and GitHub's
  issue-comment count all agree. Pending or failed CI is always confirmed live. This
  replaces the #1944 paused-item backstop.
- **The feedback gate no longer deadlocks on a review the dispatcher cannot see** (#2160). On
  #2125 the gate logged `holding advance — 1 unprocessed review body` every poll for over an
  hour, with nothing dispatched, until a restart. When the gate holds on feedback the
  dispatcher's view lacks, Fabrik now refreshes the item and dispatches on the next poll.
- **Reinvokes no longer leave a phantom lock** (#2179). Every review, CI-fix and rebase
  reinvoke marked the item locked internally and never released it, so attention, the local
  API and channel events showed a stale "held by this instance" lock.
- **A catch-up landing no longer strips `stage:Validate:complete`** (#2158). The
  SHA-invalidation scan saw the catch-up's moved head and cleared Validate completion. This
  happened on 4 of 4 catch-up landings on the dev daemon. The scan now skips landed items,
  and treats the engine's own pure catch-up as the new baseline. A real external force-push
  after Validate still invalidates it.

## GitHub budget, admission and timeouts

- **One closed item could hot-loop the poll and drain the GraphQL budget** (#2080). When the
  probe and the deep fetch disagreed about an item's linked PR, the probe invalidated it on
  every poll, and forced an immediate re-poll each time. One closed Done item did this 8,767
  times in about 25 hours, and once took the budget from 4988 to 1945 in eight minutes. A
  disagreement now invalidates once. Closed Done items with no worktree skip the check, and
  probe writes no longer wake the poll. Archiving the item is no longer needed as a
  workaround.
- **PR comments no longer trigger a failing board lookup on every webhook** (#2093). These
  payloads are skipped (about 546 wasted lookups in 20 hours in report #1910), and an
  off-board issue is remembered for 10 minutes.
- **A green yolo item no longer waits up to 30 minutes after CI finishes** (#2096; community
  reports #1943 and #2062 by @verveguy). An item the merge gate held on pending CI without
  `fabrik:awaiting-ci` was re-checked only at the periodic re-evaluation, 10× the poll
  interval. It is now re-checked within half a poll. An expired cooldown now admits an item
  once rather than on every later poll, which had made the paused-item backstop re-fetch up
  to twice a minute (116 fetches in 54 minutes on one item); #2180 later removed that
  backstop altogether.
- **CI timeouts no longer count paused time** (#2059, #2064). On #2052 the 4-hour
  `CIBackstopTimeout` re-paused an item three seconds after a human resumed it, and the item
  then sat paused for about 13 hours with CI green. The backstop, both `CIWaitTimeout` dwells,
  the merge-queue stall dwell and `ConvergenceBudget` now measure from the later of their
  label and the item's last resume. The backstop also never escalates while a worker for the
  item is running, nor before it has checked live CI once after a daemon start.
- **An incomplete stage is retried when it said it would be** (#2232). A stage that ended
  without completing logged `will retry after 1m0s` but recorded nothing to bring it back.
  Its own commits and pushes are self-writes, so the next polls saw nothing to do. The item
  waited for the periodic re-evaluation, 10× the poll interval (30 minutes at `poll: 180`),
  or for a restart. Every engine-scheduled retry now records its own admission cooldown, and
  the idle poll interval never sleeps past the earliest one. A turn-cap or `max_wall_time`
  stop is a time slice, not a failure. It is retried on the next poll with no backoff, and
  dispatch takes the candidate that has waited longest without a worker first, so a sliced
  item cannot keep its own slot while others are waiting. A comment that arrives during a
  run now admits the item as soon as the run ends.

## Operations and safety

- **Two engines can no longer serve one board** (#2097; community report #1980 by
  @verveguy). In the report, two engines processed one board for about 56 hours, posting 18
  comments an hour in pause ping-pong. Each engine now also takes a per-user board lock keyed
  on host, owner and project number, in `$FABRIK_LOCK_DIR` or the user cache directory
  (`~/Library/Caches/fabrik/locks/` on macOS). A second engine for the same board, started
  from any directory, is refused. Fabrik refuses to start inside `.fabrik/worktrees/`. Before
  every poll, the engine checks that it still holds both locks; if not, it logs `lost the
  instance lock; another Fabrik may own this board` and exits. Not covered: older binaries,
  and two hosts serving one board.
- **A stale local branch can no longer be force-pushed over an open PR** (#2089; community
  report #2058 by @bdueck, partly addressed). A human resolved a conflict on the issue branch
  and pushed it, but the worktree's local branch was never synced. Validate rebased the stale
  branch to the base tip and pushed it, and GitHub closed the PR as having no diff. Before any
  push to a branch with an open PR, Fabrik now checks whether the branch is zero commits ahead
  of its base. If it is, Fabrik does not push, and pauses with `🏭 **Fabrik — push refused:
  local branch has no commits**`. This is a safety net, not a resync. A stale branch that
  carries commits of its own is still unprotected, and syncing from origin before the rebase
  is a follow-up.
- **Same-repo spawned children inherit the parent's `base:<branch>`** (#2090; community
  report #2057 by @bdueck). In the report, four children of a `base:develop` parent were cut
  from `main`, 482 commits behind. The label, and the existing yolo/cruise copy, are applied
  before the child is placed on the board. Cross-repo children still do not inherit `base:`.
- **`fabrik.log` is rotated on start, and each run opens with a version banner** (#2094).
  Restarts, SIGHUP and auto-upgrade re-execs used to truncate the log, destroying the
  evidence needed around an upgrade. The old log now moves to `fabrik.log.1`, and five
  backups are kept. The first line reads `[startup] fabrik <version> pid=<n> reason=<fresh
  start | SIGHUP restart | self-upgrade re-exec | …>`. A rotation failure never blocks
  startup.
- **Fabrik's own secrets no longer reach Claude workers** (#2027). Workers inherited the
  daemon's environment, `.env` included: `FABRIK_TOKEN`, the App ID and private-key path
  (enough to mint installation tokens), the webhook secret, and any reviewer or Hookdeck
  keys. These, and every other engine-read `FABRIK_*` variable, are now removed. `GH_TOKEN`,
  `GITHUB_TOKEN`, `GH_HOST` and the App git credential helper are kept, so `gh` and git still
  work. The opt-in is `FABRIK_WORKER_ENV_PASSTHROUGH` (exact names, logged at startup).
- **A stopped worker's processes are reaped, including the separate session each Bash
  command runs in** (#1989, #1957, #2128). Orphaned `go test` / `sim.test` trees from stopped
  workers were running for hours at about 94% CPU, 21 of them at once on one day, driving
  host load to about 30. Claude's Bash tool runs every command in its own session, which the
  old process-group kill never reached. Fabrik now tracks those sessions and applies the
  `kill_grace` escalation to all of them. Every group kill first confirms the group still
  belongs to the process Fabrik started, so a recycled PID can never signal an unrelated
  application (#1957). Every worker's descendants carry `FABRIK_WORKER_OWNER`. A marked
  process is reaped only once its owning worker is confirmed dead; unmarked processes are
  never killed for their process-tree shape (#2128).
- **macOS worktree cleanup can no longer hang on `lsof`** (#1805). The call now has a 10 s
  timeout, after which it logs, skips that reap and removes the worktree anyway.
- **TUI confirm prompts are always visible and cancel themselves** (#2092; report #1948).
  The `u` prompt was truncated in the header, and below about 60 columns it vanished, so a
  stray `1` could quit the TUI and stop the engine unseen. Every armed prompt now has its own
  wrapped banner. Any other key, or 10 s, cancels it, and `[1] Reconcile` with jobs running
  asks for the same confirmation as `q`.

## Pruefer

- **Path-scoped read-only review tools, subagents and a scrubbed environment** (#2192).
  Reviews tried to page the staged diff with denied shell commands, then reported "no
  findings" over code they had not read. Meanwhile the review process inherited the daemon's
  whole environment, tokens included, while reading untrusted PR content. Reviews can now
  read only the PR clone and the staged diff (`cat`, `head`, `tail`, `wc`, `ls`), may use
  `Task` subagents under the same rules, and run with an explicit variable allowlist. An
  env-based `claude` login must be named in `PRUEFER_REVIEW_ENV_PASSTHROUGH`.
- **Reviews say whether they read the whole diff** (#2190). The diff is staged as an index
  plus one chunk per path, and every review body ends with `PRUEFER_COVERAGE: complete` or
  `PRUEFER_COVERAGE: partial — <reason>`, listing up to 50 unread paths. A partial review
  still clears Fabrik's review gate, so check that line.
- **Pure merge-train catch-up pushes can skip review** (#2066). A catch-up push only brings
  in already-reviewed base commits. Pruefer skips such a head when a trusted login's marker
  comment names it, it is a two-parent merge of the previous head and the base, and the
  previous head was already reviewed. To enable it, set the new `catch_up_marker_authors`
  (`--catch-up-marker-authors`, `PRUEFER_CATCH_UP_MARKER_AUTHORS`; empty by default, which
  keeps the skip off) to the engine's login, then reload with SIGHUP.

# Fabrik v0.0.94

## Summary

**A steadier merge train.** A singleton catch-up no longer waits for ever on a worktree
that holds only Fabrik's own scratch files or a stale `REBASE_HEAD`; a deferral that does
not clear is bounded and named. A check run cancelled by fail-fast after a real failed step
now reads as red, not as infrastructure, so the train re-runs or ejects correctly instead of
abandoning the batch.

**Fewer stuck items.** `fabrik:rebase-needed` clears once the rebased head is conflict-free,
while CI is still running. A hand-created cross-repo child resumes its parent's spawn. A
closed item with a merged PR finishes its Done cleanup with every completion label in place,
even when it was paused.

**Safer board repair on GHES.** `repair-board --apply` and `init --create-board` no longer
risk clearing every item's Status on servers whose option input has no `id`; they refuse
with a remedy when a populated board cannot be repaired safely.

**Pruefer hardening.** The review clone's installation token no longer appears on git's
command line.

## Fixes
- Merge train: the singleton catch-up's busy check ignores Fabrik's scratch files and removes stale `MERGE_HEAD`/`REBASE_HEAD`/`CHERRY_PICK_HEAD` refs; a worktree deferral is bounded (pause after two consecutive with no worker) and shown in the partition's `idle_reason`. Reported in #2607 (#2615)
- CI classification: a check run cancelled by fail-fast whose Actions run has a failed step is treated as a failure everywhere CI is judged (trial, landing, catch-up, stage CI gate, CI-fix comment). Reported in #2609 (#2614)
- Merge gate: `fabrik:rebase-needed` is cleared while CI is pending on a head whose mergeability is computed and conflict-free, and the wait reason says the rebase was pushed. Reported in #2608 (#2613)
- Spawn: spawned-child markers are read before the servability guard, so a child created by hand in a repo this instance does not serve resumes the parent instead of pausing it. Reported in #2601 (#2612)
- `repair-board` / `init --create-board`: Status options are replaced without option IDs where the server does not accept them, only when no item has a Status; otherwise the command refuses, names the missing columns and the UI remedy. Reported in #2610 (#2616)
- Done cleanup of a closed item whose linked PR merged fills the missing gate-checked completion labels before the worktree is removed (#2628)
- Attention: live worker turns count as progress, so a long, healthy run is no longer reported stalled; the stalled summary names the time since the last turn (#2604)

## Improvements
- Pruefer: the review clone authenticates through the git environment (an origin-scoped `extraHeader`), never a token-bearing URL, and every git log line redacts the credential (#2622)
- Documentation updated for v0.0.93 (#2598)

## Upgrading

```bash
# Auto-upgrade from a running Fabrik instance
# Fabrik checks for new releases each poll cycle and upgrades automatically with --auto-upgrade

# Or download directly (auto-detects OS and architecture)
gh release download --repo handarbeit/fabrik \
  --pattern "fabrik_*_$(uname -s | tr A-Z a-z)_$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/').tar.gz" \
  -O - | tar xz
```

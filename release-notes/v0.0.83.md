# Fabrik v0.0.83

## Summary

**Fabrik can now run as a GitHub App.** This is the release's headline and its largest
change: the engine authenticates as an App installation rather than a personal access
token, which buys it a stable `<slug>[bot]` identity and — the part that matters
operationally — its own rate-limit bucket. Every PAT a user holds draws on one shared
5,000-point GraphQL budget; an installation gets its own, larger allowance that scales
with the account. By the end of the cycle App mode is self-contained: no `user:`, no PAT,
commits authored as the bot, HTTPS git pushing as the installation, and event-driven
ingestion via Hookdeck where `gh webhook forward` cannot follow. PAT mode is **not**
deprecated and never will be: a user-owned project board cannot use App auth at all,
because GitHub strips organization permissions from user-account installations. The two
modes are co-equal.

**Getting onto a board is no longer a manual setup chore.** `fabrik init --github-app`
creates the App under your organization, waits for you to install it, and verifies its
grants; `fabrik init --create-board` builds a fully-configured Projects v2 board straight
from your stage configs; and the new `fabrik repair-board` diagnoses and — only when you
ask it to — repairs a board whose columns have drifted from your stages.

**Fabrik no longer advances or lands past feedback it has not processed.** A review that
arrived while a stage was running, or while it waited on CI, was invisible to the review
gate — and on 2026-09-29 a real defect in a bot review was fixed only because a human
copied it into a comment. Every advance and landing decision now consults one live
predicate covering comments, unresolved review threads and unaddressed review bodies, and
holds while anything is outstanding. A Queued merge-train member that receives a human
comment is ejected back to have it addressed, and a comment that arrives after the work
has merged gets an explicit "not applied" reply instead of being processed onto a dead
branch.

**The merge train got correct and cheaper.** It could land the same member twice, admit
members whose own CI was already red and then bisect for hours to rediscover it, clear on a
partial check set while a queued job had not yet started, and pick a different random batch
every poll once the queue outgrew `max_batch_size`. All four are fixed. Conflict
resolutions are now replayed across trials with `git rerere`, and a trial's still-valid
prefix is reused instead of rebuilt from base.

**The autonomous loop got meaningfully harder to wedge.** A wake signal walked straight
through GraphQL rate-limit backoff, turning an ordinary throttle into a self-sustaining
outage that starved *every* project sharing the account's token. Claude session limits
arriving as an `api_error` 429 were treated as transient, so nothing backed off; the
suspension now recognises them and runs until the reset time the CLI reports. And when
GitHub silently stopped creating closing-keyword links on 2026-09-30, Fabrik paused items
for "broken linkage" and left landed issues open — it now confirms linkage from the PR body
and closes landed issues itself.

## Features

- **The engine can authenticate as a GitHub App installation** (#1713). When App
  credentials are configured (`github_app_id`, `github_app_private_key_path`,
  `github_app_installation_id` — all or none), the engine builds its GitHub client from a
  `githubauth.Reconciler` and keeps a token-refresh loop alive for its lifetime. Two
  concrete wins: a **separate, larger rate-limit bucket** instead of a share of the one
  5,000-point GraphQL budget every one of your PATs competes for, and a stable bot
  identity distinct from the operator's account. Startup reads the *installation's*
  granted permissions — not the App's requested ones, which diverge silently — and
  refuses to start with a message naming each missing grant. **PAT mode is permanent and
  co-equal, not legacy**: a user-owned board can never use App auth, so the PAT path
  remains the only option there, by GitHub's design rather than ours.
- **App mode needs no operator identity** (#1893). Under App auth there is no `user:` and
  no PAT: `user is required` is skipped (a leftover `user:` is tolerated, ignored and
  logged), and the engine's token is zeroed. Commits are authored as `<slug>[bot]` with
  the bot's noreply address — an operator-chosen git identity on an existing clone is
  never overwritten. Lock labels become `fabrik:locked:<slug>-<hash>`, unique per host and
  directory, so two local instances of one App never share a lock; a leftover
  `fabrik:locked:<user>` from a PAT-era run is swept once at startup. "Awaiting input"
  mentions go to the issue's human assignees, else its human author, else nobody — never
  a bot. PAT mode is unchanged by construction.
- **HTTPS git authenticates as the App installation** (#1846). Previously HTTPS git was
  refused at startup under App auth and the only workaround pushed with the operator's SSH
  key. The engine now injects a git credential helper into its own environment that
  overrides any host helper and serves the installation token from a file rewritten on
  every token rotation — so engine and worker pushes go out as the App, and a worker
  running past the token's ~1h lifetime still pushes. Requires `contents: write`, checked
  at startup only in HTTPS mode; SSH setups (`git_ssh: true`) are unaffected.
- **Real-time events on multi-repo boards, in both auth modes** (#1142). `gh webhook
  forward` honours only one `--repo`, so on a multi-repo board without org mode Fabrik
  silently received webhooks for one repo and polled the rest — while reporting the stream
  healthy. In PAT mode the limitation remains, but it is no longer silent: the effective
  subscription is logged on every (re)start, a periodic check warns on any managed repo
  without a forwarding hook, and the TUI shows partial coverage. For App auth, where
  `gh webhook forward` refuses installation tokens entirely, the new `event_source:
  hookdeck` ingests the App's single webhook via Hookdeck — the transport Pruefer already
  used, now shared — covering every repo the installation is granted.
- **`fabrik init --github-app`** (#1715) — an end-to-end App setup flow with grant
  verification and an explicit org-only guard, so the user-owned-board dead end is caught
  at setup time rather than at first poll. When no installation exists yet for `--owner`,
  an interactive run now waits (up to 10 minutes) for you to install the App and then
  carries on, instead of exiting with "install, then re-run" (#1889); scripted runs still
  fail fast. The username prompt is gone under App auth (#1893).
- **`fabrik init --create-board`** (#1714) — creates a fully-configured Projects v2 board
  from the stage configs `init` just extracted: Status options in stage order (including
  Done), described, and written into `.fabrik/config.yaml`. Previously the board had to be
  built by hand, with column names matching stage names exactly or startup would refuse.
  `--repo` is now optional (#1889): without it the board is created unlinked and the
  config left multi-repo, since the engine discovers repos from board items. Under App
  auth, a `--repo` the installation was never granted is caught before anything is
  created, with an error naming the repos it does cover.
- **`fabrik repair-board`** (#1714) — diagnoses a board whose Status columns no longer
  cover your configured stages, and adds the missing ones. Dry-run by default; it only
  mutates under `--apply`, and it never deletes a column. Both entry points refuse
  explicitly on a user-owned board. Under App auth it builds its client from the
  `github_app_*` settings when no `--token` is given (#1893).
- **`--no-browser` / `FABRIK_NO_BROWSER` / `no_browser`** (#1763) — suppresses browser
  opening during App reconciliation. Defaulted to suppressed, on the reasoning that a
  long-running daemon is a bad place for an unconditional browser-open.
- **`--retry-backoff` / `FABRIK_RETRY_BACKOFF` / `retry_backoff`** (#1831) — stage retry
  backoff is now its own setting (default 60s, minimum 1s) instead of `10 × poll`. Raising
  `poll` to protect a shared rate limit silently multiplied retry latency: at a 180s poll,
  a stage that ran out of turns while making progress waited 30 minutes before each retry.
  GitHub re-check cadences stay tied to `poll`, since those genuinely are about API cost.
- **`fabrik:toolchain-stale`** (#1786) — workers inherit `PATH` from the shell that
  launched the daemon, so a long-lived daemon silently pins every worker to that shell's
  toolchain; in the reported case workers kept running Node 20 for weeks after the repo
  moved to Node 24. Before each invocation Fabrik now compares `.nvmrc`, `engines.node`,
  `go.mod` and `.tool-versions` against the version actually on `PATH`, and posts one
  warning naming both when they disagree. Warn-only — it never skips an invocation — and it
  stays silent on anything it cannot compare.
- **Plugin staleness is reported even when the plugin is customized** (#1787). A
  customized `.fabrik/plugin/` used to hide the fact that it was also behind the embedded
  skills. Startup, `fabrik upgrade` and the TUI badge (`[u] custom workflow (N stale)`) now
  report both, and point at `fabrik upgrade --reconcile`. Upgrade refusal behaviour is
  unchanged.
- **`fabrik:reworking`** (#1802) — while a stage is re-entered to process a steering
  comment, its stale `stage:<Stage>:complete` is now cleared and restored afterwards, with
  `fabrik:reworking` marking the window, so the board no longer shows a stage as complete
  while it is being reworked. Gating is unaffected; a crash mid-rework is repaired at
  startup.
- **Pruefer gains operator configuration.** Review **cadence** and per-repo
  `repo_cadence` gate how often the bot reviews a given PR (#1610); `review_guidance` /
  `review_guidance_mode` let an operator compose review instructions from default,
  operator, and per-repo skill layers, the repo skill (`.pruefer/skills/review/SKILL.md`)
  read at the PR's **base** ref so a PR cannot change how it is itself reviewed (#1446); a
  local `ReviewTracker` backstops against re-review loops (#1631); and `served_accounts`
  bounds which accounts an installation will serve (#1722). App name and homepage are now
  configurable, since App names are globally unique (#1725), and
  `github_app_organization` lets first-run setup create an org-owned private App — before
  it, an organization could not be served by a private Pruefer App at all (#1950).
- **`pruefer:ignore`** (#1930) — a built-in label that opts a PR out of Pruefer review
  regardless of other configuration; `/pruefer review` does not override it.

## Fixes

- **GitHub stopped creating closing-keyword links, and Fabrik depended on them** (#1962).
  From about 05:40Z on 2026-09-30, GitHub silently stopped linking new PRs to the issues
  their `Closes #N` names, and dropped the auto-close even for PRs it had linked. Fabrik
  paused items for "broken linkage" and landed items reached Done with their issues still
  open. The broken-linkage check now confirms the closing keyword from the PR body on every
  path before pausing (a read error never pauses), and a default-base landing whose issue
  is still open after merge is closed by Fabrik itself on a later poll, with a "closed
  after merge" comment naming the PR — reusing the `fabrik:awaiting-close` retry and
  escalation path that previously served only `base:<branch>` items. A late GitHub
  auto-close clears the marker silently.
- **A wake signal bypassed GraphQL rate-limit backoff, turning a throttle into a
  self-sustaining outage** (#1716). The log line `rate limited — polling suspended` named
  a mechanism that did not exist: the detector logged, emitted a TUI alert, and returned
  without arming any gate. The only real backoff was the poll ticker's interval — and the
  wake path polls immediately regardless of it. Under `--webhooks`, inbound GitHub events
  are not rate-limited and kept arriving while the API refused every call, so the loop fed
  itself: **39 log lines per second sustained**, 1,448 wake-requests and 4,372 rate-limit
  errors in a single 20,000-line sample, a 42 MB log growing at 14 MB/hour. Because every
  PAT a user holds shares one 5,000-point bucket, the blast radius was not the looping
  daemon but *every project on that token*. Wake signals are now gated by the backoff
  state, with a minimum poll-interval floor — while still letting through the legitimate
  self-wake that fires when the budget has actually recovered.
- **A failed `MarkPRReady` could permanently strand a draft PR** (#1582). The call had an
  in-process retry and nothing beyond it, so a stage could complete with its PR stuck in
  draft and no review bot ever triggered. It is now a durable marker retried every poll,
  escalating to a paused issue naming the manual `gh pr ready` fix if it never succeeds.
- **`spawnChildren` duplicated already-created children after an operator un-pause**
  (#1583). The only record that a spawn block's child existed was in-memory, so a retry
  after a restart re-created it. Each created child is now recorded durably on the parent,
  and a retry resumes rather than duplicates.
- **A parent that decomposed into sub-issues still built the whole epic** (#1783). The
  `blockedBy` edges `spawnChildren` created were not reflected in the engine's own state
  until a later deep-fetch, so a dispatch in that window saw the parent as unblocked and
  Implement built the epic as a monolith, competing with its own children. The edges are
  now recorded synchronously, so the parent is blocked from the next board read.
- **Autonomy-label removal mid-stage was not observed** (#1769). Advance and merge
  decisions read a snapshot taken before the stage ran, so removing `fabrik:yolo` or
  `fabrik:cruise` while a stage was in flight did not take effect. Both decision points
  now re-read the labels live.
- **The `fabrik-setup` skill was wrong in five places, each of which bit a real
  first-time setup** (#1788) — among them the working directory, a nonexistent `--once`
  flag, and token guidance. Corrected and reconciled with `--create-board`/`repair-board`.

### Review feedback and comments

- **Review feedback arriving mid-run or during the CI wait was never dispatched, and the
  item could land past it** (#1953). The guard that kept `fabrik:awaiting-review` from
  stale writes also switched off feedback detection from stage start through the CI wait,
  and stages without `wait_for_reviews` never dispatched review bodies at all. Detection
  now runs in every state, and a single live predicate — unprocessed comments, unresolved
  review threads, unaddressed review bodies — holds every stage advance, merge and enqueue
  while anything is outstanding, logging `[#N feedback-gate] holding …` with the IDs. A
  failed read holds rather than merges. Queued members are now ejected for unaddressed
  review bodies as well as threads. Review bodies also get 👀/🚀 reactions, so their
  progress is visible on the PR.
- **An unprocessed comment could be merged past, then processed onto the merged branch**
  (#1862). Landing now holds while any comment is unprocessed, and once an item's work has
  landed, a new comment runs no worker and pushes nothing; it gets one "not applied, open a
  new issue" reply instead.
- **A steering comment on a Queued merge-train member was ignored until it landed**
  (#1863). A human comment on a Queued member now ejects it back to the stage before
  Queued to be addressed, and it re-queues once Validate completes again. The eject never
  pauses the member and never counts toward `MaxMergeTrainEjections`; bot comments never
  eject.
- **Landed work could be re-invoked forever, starving its own Done advance** (#1934).
  After a merge, a review body kept triggering a review-reinvoke that the post-merge guard
  then skipped, and each dispatch blocked the merged-PR advance to Done — an item stayed at
  Validate for 30 minutes after its PR merged. Landed work is now never re-invoked or
  cycle-paused, on the review, CI-fix and rebase paths.
- **Workers could dismiss a security finding on spec-conformance grounds alone** (#1785).
  The review and validate skills now require a stated exposure assessment before a
  security-relevant finding is dismissed, and a genuine spec/security tension is left
  unresolved and stated plainly rather than arbitrated by the worker.

### Merge train

- **A member could be landed twice** (#1871). A fresh worker could start from a board
  snapshot taken just before the previous worker landed the member, and re-run the whole
  landing — a second Done move, close and "Landed via…" comment. Both resume-landing paths
  now read the member's Status live first, and skip it if the landing has already
  completed.
- **The train admitted members whose own CI was already red** (#1821), then spent trial
  CI, conflict resolution and bisection rediscovering it — zero landings in a 93-minute
  window in the reported incident. Fresh batch formation now reads each member's own check
  runs and defers a confirmed-red member off Queued with a comment. It is fail-open:
  anything short of confirmed red is admitted as before.
- **The CI gate cleared on a partial check set** (#1822, #1829). A job still queued for a
  runner has no check run yet, so an all-green prefix read as a complete pass — in the
  reported cases the gate cleared 66s and 11s after CI started, and the failing E2E job was
  created minutes later. Every "green and complete" judgement now also reads the head's
  check suites live and holds while one has outstanding work. A run-less suite from a
  third-party App is ignored once it ages out, so an idle App cannot deadlock the gate; a
  `github-actions` suite is never treated that way (#1829). The CI-timeout pause names the
  stuck suite.
- **Batch membership was random once Queued exceeded `max_batch_size`** (#1833). Under the
  in-memory board cache, item order came from Go map iteration, so each poll picked a
  different subset and abandoned the previous trial's CI — 9 refused merges and nothing
  landed for 3.5 hours in the reported case. Queued members are now ordered by when they
  entered Queued.
- **Conflict resolutions are replayed instead of re-paid** (#1834). An abandoned trial
  discarded its Claude-resolved conflicts, so the next assembly paid again for the
  identical conflict. `git rerere` now replays a recorded resolution for free; resolutions
  from a member isolated as the poisoner are forgotten so a bad one cannot be replayed.
  Replayed resolutions are validated by the same combined CI as fresh ones.
- **A trial's valid prefix is reused instead of rebuilt from base** (#1835). Bisection and
  re-forms after an eject now fork from the longest still-valid prefix of the previous
  trial rather than redoing its merges.
- **Conflict resolution was ejected on turn-limit exhaustion, discarding resolved work**
  (#1841). A member was ejected over a single conflicting line. A turn-capped resolution
  whose worktree is actually resolved is now committed; the resolution prompt no longer
  carries a Go-specific build/vet instruction that roughly doubled turn count on other
  stacks; and an ejection comment names the still-conflicted files and says whether Claude
  ran out of turns or judged the conflict unresolvable.
- **An unhydrated member was partitioned onto the default branch** (#1772), the cause of
  the v0.0.81 incident in which an integration PR was opened against a protected default
  branch while every member carried `base:develop`, and self-merged nine minutes later. A
  member whose cache entry is not yet hydrated is now excluded for that poll.
- **An integration PR whose base contradicts its members is refused** (#1773) — an
  independent outcome-level check, run immediately before either landing path opens or
  reuses a PR, against each member's live `base:` label. Members stay Queued and the
  refusal is logged.
- **Merge-train conflict resolution had no wall-clock cap** (#1500). A holding stage
  carries no `max_wall_time`, so a conflict-resolution invocation could run unbounded. It
  now falls back to a 30-minute deadline.

### Claude usage limits and pauses

- **Session limits reported as `api_error` 429 were treated as transient, so nothing
  backed off** (#1811). Every `api_error` exit recorded across three live daemons was in
  fact a session limit; one issue saw 139 invocations in 20 minutes, each dying at turn 1.
  That shape now gets the usage-limit handling: `fabrik:claude-limit`, the account-wide
  suspension, and no retry charge. Other `api_error` statuses keep their existing
  handling.
- **The usage-limit suspension always guessed one hour** (#1815). It now runs until the
  reset instant from the CLI's structured rate-limit event (clamped to 8 days), falling
  back to 1h with the reason logged when none is available. Detection and deadline never
  read output prose.
- **Reinvokes that never ran were charged a cycle** (#1812). A review, CI-fix or rebase
  reinvoke whose invocation provably never executed — a 429, usage limit, suspension or
  `apiKeyHelper` exit — consumed `MaxReviewCycles` budget; five such exits in under a minute
  paused a healthy issue with a message blaming the reviewer. They are now refunded, and a
  cycle-limit pause caused by them names the real cause.
- **A paused issue was resumed by a comment that predated the pause** (#1813). An
  unprocessable comment stayed "new" forever and lifted the pause every poll, zeroing the
  comment circuit breakers each time — ten overrides in ten minutes in the reported case. A
  pause is now lifted only by a human comment made at or after it; every indeterminate
  case still resumes.
- **A resume comment posted right after a pause could go unseen** (#1944). The engine's
  own pause write masked a reply posted a second later, and the paused-item fetch skip had
  no backstop. A recently paused item is now re-fetched on its periodic re-evaluation.
- **A quoted pause message suppressed a real pause comment** (#1937). Pause-comment dedupe
  matched the message text anywhere, so a stage output quoting an earlier pause meant the
  real one was never posted. Only the engine's own pause shape now matches.

### Workers and permissions

- **The tools-denied bound covered only the stage path, so reinvoke paths looped
  indefinitely on a mode denial** (#1704). A permission denial landing on a comment-review,
  CI-fix, or review-reinvoke dispatch accumulated against nothing and could retry forever.
  All paths now share one per-stage counter and one classification helper.
- **Tools-denied messaging named the tool, not the command, and called retry futile**
  (#1775). Workers read "Bash was denied, no retry can fix this" and abandoned stages that
  would have completed. Denials are scoped to one command; the comment and log now name
  that command, drop the futility claim, and put "re-run as simpler commands" and
  `allowed_tools` ahead of `fabrik:unrestricted`. All stage skills tell the worker the
  same.
- **Fabrik's own skills told workers to run commands `dontAsk` always denies** (#1777).
  Seventeen shell shapes (`x=$(…)`, `if`, herestrings) — most of them in `fabrik-validate`'s
  Pre-Completion Gate, and one as Validate's very first command — can never be allowlisted.
  All are rewritten as simple, allowlistable commands.
- **A stage's artifact was silently discarded when a tool call followed it** (#1782).
  Output was taken from the CLI's final result only, so a Plan that wrote its artifact and
  then made one more tool call completed with no Plan comment. The last substantive
  assistant turn is now recovered, and a completion with no artifact anywhere is treated as
  incomplete.
- **Worker-liveness cleared an unverifiable worker, letting two workers share a worktree**
  (#1779). A worker that had not yet reported a PID was cleared on a timeout alone; in one
  reported case it ran for another 1h36m alongside a second worker. The engine now probes
  for the worker's session sentinel first and adopts it if it is alive.
- **Detached worker subprocesses leaked as CPU-spinning orphans** (#1798, #1814). Workers
  now run as session leaders, their descendants are tracked durably and reaped at
  invocation end, and a periodic sweep reaps any process belonging to a dead worker's
  session — including ones the tracker never saw, and ones from a previous engine run. Every
  kill re-verifies the process's identity first.
- **The stall detector required a turn-capped predecessor, so it missed the cleanest
  backgrounding stalls** (#1767). A worker that launched a background run, said it would
  wait for it, and stopped — well under its turn budget — did not look like a stall. It is
  the quietest failure shape there is, and it burned all three Validate attempts on #1142
  before anyone noticed.
- **A worktree forked from base when its issue branch already existed on origin** (#1915),
  so it lacked the branch's commits and every push was rejected as stale. A missing local
  branch now starts from the one on origin.
- **Ambient `FABRIK_PR`/`FABRIK_WORKTREE`/`FABRIK_ROOT` leaked into worker environments**
  (#1844) when the engine had no value of its own to set.
- **In `-notui` mode, Claude invocation lines never reached `fabrik.log`** (#1939) —
  `invoking`, kill/reap, wall-time and idle-timeout notices went to stderr only. They now go
  to the log file and, like every other log line in plain-text mode, to **stdout** rather
  than stderr.
- **`fabrik-validate` asserted "All checks pass" without observing check state** (#1701).
  The completion summary now reports what it actually saw.

### GitHub App shakeout

Getting App auth from "implemented" to "actually works" took a tail of its own, all of it
fixed here:

- **App auth dispatched nothing** (#1750) — the installation token reported
  `permissions.push=false`, which gated out every item on the board.
- **App auth silently no-op'd `--webhooks`** (#1752) — the combination is now refused
  outright, and the webhooks permission key was wrong. `event_source: hookdeck` (#1142) is
  the App-mode alternative.
- **The engine had no self-identity under App auth** (#1754) — four separate
  self-recognition comparisons were testing the *operator's* login, not the bot's.
- **App-authored comments read as human** (#1898). GraphQL returns an App's login without
  the `[bot]` suffix, so in both auth modes App comments counted as human input (for
  example, to lift a pause), and under App auth Fabrik's own comments did not match its
  self-identity. Comment, thread and item authors are now normalized as reviews already
  were.
- **The `contents` permission was missing from the grant set** (#1755) — compares returned
  403 and a needed rebase was silently skipped.
- **The worker `gh`/git surface 403'd under App auth** (#1756) — the CI-fix path failed.
  Worker git over HTTPS, refused at startup as an interim measure, now authenticates as the
  installation (#1846).
- **`fabrik init --github-app` created the App under the signed-in user** (#1885). A
  private App can only be installed on its owner, so the org named by `--owner` could never
  install it. The App is now created under that organization.
- **`fabrik init --github-app` said "Pruefer setup received"** (#1881) — the shared
  manifest flow hard-coded Pruefer's name.
- **`--create-board` and `repair-board` omitted the Done column** (#1891), so a created
  board could never complete an item. Both now include it; `repair-board --apply` adds it to
  an existing board.
- **Reconciliation opened a 404 browser window every cycle** (#1763).
- **The App manifest was rejected by GitHub** (#1711) — `hook_attributes` without a `url`.
- **App identity and permissions are now parameterized** (#1712), accepting a Client ID as
  JWT issuer.
- **The App installation trust boundary is tightened** (#1722) — private by default,
  per-account Apps, and unauthorized installations are removed rather than served.
- **The App webhook is declared at creation** (#1758) rather than added later, which had
  cost a per-installation approval round-trip.
- **The sim bed could not exercise App-auth mode at all** (#1751), so App-only regressions
  shipped green. It can now.

### Pruefer

- **The reviewer never saw the diff** (#1855). The prompt told it to `git diff` against a
  base branch the shallow review clone never fetched, so the command failed on every review
  and the model reviewed whatever files it happened to open — on one 29-file PR, a single
  file. The diff Pruefer already fetches is now handed to the reviewer directly.
- **Reviews depended on the operator's Claude profile** (#1856). Pruefer loaded the user
  settings layer, so restarting the daemon under a different profile silently changed
  permission mode, hooks and effort. No settings layer is loaded now; everything that
  governs a review is passed explicitly.
- **The default review guidance was one sentence** (#1858). It now asks the reviewer to
  follow every changed symbol, check for docs the change falsifies, and ask what the tests
  would still pass without the fix — and to mark each finding "Confirmed:" or
  "Plausible:" with a concrete failure scenario.
- **A failed installation listing was treated as an empty grant** (#1951). Pruefer now
  keeps the last successful listing and marks it stale, classifies rate limits as their own
  error (no longer misreported as an authorization failure with a PAT hint), and does not
  re-list a rate-limited installation before its reset.
- **Idle polling cost scaled with open PRs, not changes** (#1952). Unchanged PRs that were
  already conclusively evaluated are skipped before any API call, and installation clients
  use conditional requests. Each poll logs its request and `304` counts.
- **Installations' granted permissions are now verified** (#1709) — a shortfall against
  what Pruefer needs is logged by name at startup and on re-derivation, rather than first
  surfacing as a 403.
- **The TUI fills the terminal** (#1674), counts skips instead of listing them in Completed
  Reviews, aligns its columns, and moves Watched Repos last.
- A migration runbook for moving from one public multi-account App to per-account private
  Apps is in `cmd/pruefer/README.md` (#1726).

# Auto-upgrade from a running Fabrik instance

# Or download directly (auto-detects OS and architecture)

  --pattern "fabrik_*_$(uname -s | tr A-Z a-z)_$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/').tar.gz" \

# Fabrik v0.0.78

## Summary

**A recovery-and-robustness release.** Fabrik's job is to keep long-running work moving
without a human watching it, and this release is almost entirely about the places where
it used to stop moving and not say why.

- **No more one-way doors.** Several engine pauses were unrecoverable in practice:
  clearing `fabrik:paused` left the counter that caused the pause untouched, so the item
  paused again immediately. Non-failure pauses now reset their own state on resume, and
  the pauses that strand an item with no owner — a CI wait that times out, a terminal
  advance that cannot resolve its board column — now retry and escalate instead of going
  quiet.
- **Stop charging the job for the machine's problems.** A transient `api_error`, a
  turn-cap preemption, and a Claude usage limit all used to count against `max_retries`
  and eventually mark a stage *failed* — even though the stage never ran. They no longer
  do.
- **The CI gate bounds liveness, not elapsed time.** A healthy, progressing CI suite is
  no longer paused for taking too long; the timeout now measures observable progress,
  with a separate absolute backstop.
- **The merge train no longer stalls on a poisoned batch.** A successful bisection used
  to trip the runaway guard on its own final trial, pausing the very members it had just
  proved clean — so any queue of three or more containing one bad change stalled. The
  survivors now land.
- **GitHub Enterprise Server support** — dual endpoints, a host-aware git layer, and
  `GH_HOST` propagated into stage workers.
- **Review feedback from bots is no longer silently dropped.** A reviewer that submits
  its entire finding set as a `COMMENTED` review — which is how most review bots work —
  is now picked up and addressed like any other feedback.

## Features

- GitHub Enterprise Server support: dual endpoints, host-aware git layer, `GH_HOST` propagation to stage workers (#1391)
- Clean-stop shutdown: in-flight issues are paused durably and the worker drain is bounded (#1393)
- Bot review feedback delivered as a plain review body is now gated on and auto-addressed (#1045)

## Fixes

- CI wait timeout is no longer unrecoverable — clearing `fabrik:paused` leaves an owner (#1408)
- CI gate bounds liveness rather than elapsed time; healthy CI is no longer paused (#1410)
- `mergeable_state=unstable` no longer clears `wait_for_ci`, so non-required checks gate advances correctly (#1441)
- Non-failure engine pauses reset the counter that caused them, instead of re-pausing on resume (#1460)
- A transient `api_error` exit no longer counts against `max_retries` (#1458)
- Turn-cap preemption no longer counts against `max_retries` (#1199)
- Comment-path setup failures respect the circuit breaker instead of re-invoking unbounded (#1413)
- A failing `--resume` session is no longer retried indefinitely (#1414)
- A terminal advance that cannot resolve its Status option now retries and escalates instead of stranding the issue (#1422)
- Startup validation no longer exempts the holding-stage column that terminal advance targets (#1421)
- Review-gate cycle-limit exhaustion now pauses with the cycle-limit reason, not the review-wait timeout (#1518)
- Cross-repo sub-issues are registered on a board that serves them, and are assigned (#1419)
- `fabrik:extend-turns` scales `max_wall_time` alongside the turn pre-grant (#1206)
- Merge-train: Queued members now process PR review feedback instead of ignoring it for a batch cycle (#1208)
- Merge-train: a successful bisection no longer trips the runaway guard and pauses the clean members it just vindicated — any poisoned batch of 3+ members previously stalled (#1528)
- Merge-train: a red singleton batch is reported as its own validation failure, not bisected and ejected (#1440)
- Merge-train: ejection comments retain the combined Validate output (#1420)
- Merge-train: the best-effort "landed via" comment post is retried (#1275)
- Merge-train: `extend-turns` derives its turn budget from the correct base (#1472)
- Cross-turn resumption tools (`ScheduleWakeup`, `Workflow`) are withheld from stage workers (#1365)
- The mandated Validate pre-completion rebase is conditional, so it no longer livelocks CI (#1364)
- Pruefer: re-review loop at an unchanged head — `COMMENTED` reviews now supersede correctly (#1496)
- Pruefer: the review prompt carries prior-thread context, so findings stop repeating (#1497)

## Improvements

- A source-checkout daemon running stale code now says so, whether or not the board is idle (#1464)
- The rate-limit banner names the bucket that is actually exhausted, and clears per-bucket (#1482)
- The TUI GraphQL budget indicator accounts for burn rate and time to reset, not percentage alone (#1510)
- `CLAUDE_CONFIG_DIR`'s resolved account is named at startup and shown in the TUI footer
- The never-wait-on-CI rule is stated as an imperative and propagated to the 10 skills that lacked it (#1366)

## Internal

- e2e bed hardening: a declared reviewer that cannot review is caught rather than costing a 45-minute opaque failure (#1396), and `TestExpectedReviewersPrecedenceGuard` no longer passes vacuously (#1307). AC7's review-reprocessing assertion is keyed off the review's own ID rather than dispatch count (#1519). Documentation corrected where it contradicted shipped behavior (#1520).

## Upgrading

```bash
# Auto-upgrade from a running Fabrik instance
# Fabrik checks for new releases each poll cycle and upgrades automatically with --auto-upgrade

# Or download directly (auto-detects OS and architecture)
gh release download --repo handarbeit/fabrik \
  --pattern "fabrik_*_$(uname -s | tr A-Z a-z)_$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/').tar.gz" \
  -O - | tar xz
```

# Fabrik v0.0.85

## Summary

**A stage now runs before any comment that was waiting when the item entered it** (#2220).
A comment posted while an item sat in an earlier column (Backlog, say) used to be handed
to the stage's comment skill on entry, and that pass could complete the stage on its own.
On #2218 the `specify` skill never ran and no Specify comment was posted; the same could
skip the Research comment, the Plan comment or Implement's draft PR. The stage now runs
first, and the comment pass follows once the stage has produced its output.

**SIGHUP is a real graceful restart** (#2259). The first SIGHUP (or `ctrl+r` in the TUI)
used to cancel every in-flight worker; on 2026-10-13 that threw away a comment pass 14
turns in, which then ran again from the start. The first SIGHUP now stops starting new work
and waits for running workers to finish before re-exec'ing. A second SIGHUP restarts now.

**Smaller engine fixes.** Merge-train Queued order follows GitHub's own move time (#2246). A
stale `fabrik:awaiting-input` is cleared once nothing is paused (#1970). A usage-limit exit
on a resumed session is classified as a usage limit, not a resume failure (#1949). An
already-landed origin issue branch is no longer adopted into a new worktree (#1917). A
`+dirty` dev build rebuilds when its checkout moves, for Fabrik and Pruefer (#2234).

**The TUI shows what Fabrik is waiting on** (#2238). The In Progress panel lists items held
on CI, reviews, a retry, a rebase, the merge train or a human reply, and the header no longer
says "nothing to do" while those waits are open.

**CI is cheaper and faster.** A PR that changes no Go build input skips the Go suites while
still reporting success (#2254), and Linux `-race` runs the sim at parallelism 16 (#2228).
This release's live gate is the first certified run on two test beds (#1990).

## Upgrading

No configuration changes are needed. Two behaviour changes to know about:

- **A SIGHUP restart can take as long as the longest running worker** (#2259). The first
  SIGHUP, or `ctrl+r`, stops polling and starts no new work of any kind, then waits, with no
  deadline of its own, until in-flight workers finish; each is still bounded by its stage's
  `max_wall_time` and the 15-minute inactivity timeout. To restart immediately, send SIGHUP
  again (or press `ctrl+r` again): the remaining workers are cancelled, the usual
  `--drain-deadline` drain runs, and Fabrik re-execs. A second SIGHUP no longer force-quits
  with exit status 1. SIGHUP never pauses an item. SIGINT and SIGTERM are unchanged, and
  during a SIGHUP drain they stop the daemon instead of restarting it. Scripts that send
  SIGHUP and expect a restart within seconds should send it twice.
- **A stage runs before a pending comment** (#2220). If you comment on an item before it
  reaches a stage, expect the stage's own run first and then one comment pass that applies
  your comment, instead of the comment pass alone. That is one more invocation than before.
  The advance waits for the comment pass, including a stage that reports
  `FABRIK_NO_WORK_NEEDED`: with a comment pending, it is marked complete but does not move
  to Done until the comment pass has run.

```bash
# Auto-upgrade from a running Fabrik instance
# Fabrik checks for new releases each poll cycle and upgrades automatically with --auto-upgrade

# Or download directly (auto-detects OS and architecture)
gh release download --repo handarbeit/fabrik \
  --pattern "fabrik_*_$(uname -s | tr A-Z a-z)_$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/').tar.gz" \
  -O - | tar xz
```

## Engine

- **A stage runs before any comment pending on entry** (#2220). Before, a pending comment
  sent the item to the comment skill ahead of the stage, and `FABRIK_STAGE_COMPLETE` from
  that pass completed the stage. Now a pending comment goes to the comment path only once the
  stage has run on this entry, judged from durable state: `stage:<S>:complete` or `failed`,
  `fabrik:reworking:<S>`, the stage's CI/review/done wait marker, an engine pause, the stage's
  own `🏭 **Fabrik — stage: <S>**` comment, or a resume from a pause. Anything undeterminable
  counts as "not run". The stage run no longer marks the pending comments as seen (no 🚀),
  so the comment pass still happens, and the existing feedback gate holds the advance until
  it has. `FABRIK_NO_WORK_NEEDED` now goes through the same gate. An incomplete stage run
  with a pending comment is retried as a stage run under its normal backoff. See ADR 2220.
- **SIGHUP drains in-flight workers before restarting** (#2259). Details are under
  "Upgrading". While draining, the in-flight set (`#issue stage kind elapsed`) is logged on
  the first SIGHUP and every minute, followed once by `send SIGHUP again to restart now`. The
  TUI title shows `draining for restart (N left)`, and `fabrik_health` gains a `draining`
  object. The poll is reported as not overdue while draining, so no `pipeline-stalled` event
  fires. A merge-train run waiting on a trial's CI does not hold the restart; its persisted
  run resumes after the exec. A reinvoke that was only queued for a slot is dropped and
  re-dispatched by the new process. See ADR 2259.
- **Merge-train Queued order uses GitHub's move time** (#2246). Members whose moves into
  Queued the engine saw in the same pass were ordered by board-listing order. In the v0.0.84
  gate, members moved as A, B, C, P formed the batch `[A, P, B, C]`. The board and probe
  queries now read the Status value's own `updatedAt` (one extra scalar), and the batch is
  sorted by that time, then by issue number. The time survives a restart, so a restart no
  longer reshuffles a batch. GitHub's times have one-second resolution, so moves in the same
  second still fall back to issue number. The engine's own moves use daemon time. The local
  API's merge-train position uses the same order. See ADR 2246.
- **A stale `fabrik:awaiting-input` is cleared** (#1970). Two routes left it behind after a
  comment-review run that did the work and never asked for input. Many pause messages tell
  you to remove only `fabrik:paused`, which left `fabrik:awaiting-input` on the item, and
  only a `FABRIK_STAGE_COMPLETE` run used to clear it. Fabrik now removes it after every
  comment pass and reinvoke, and when processing an item, whenever a live read shows
  `fabrik:paused` is absent. A real pause is never lifted this way. Also, if removing
  `fabrik:paused` on a resume failed, the comment was still processed, leaving the item
  paused with nothing to resume it. A failed removal now leaves the comment unprocessed, and
  the next poll retries.
- **A usage-limit exit on a resumed session is classified as a usage limit** (#1949). On
  `--resume`, Claude reports the session's cumulative turns and cost, and Fabrik read them as
  this invocation's work. A limit that rejected the invocation before it did anything then
  counted as a resume failure: in the v0.0.83 gate this abandoned a healthy session after two
  exits and delayed the account-wide usage-limit hold by two invocations. A resumed
  invocation whose own output has no user turn is now judged on zero usage, so the exit is a
  usage limit and the session and resume-failure counter are left alone. A limit hit after
  real work in the same invocation is still not detected, as before. See ADR 1949.
- **An already-landed origin issue branch is not adopted** (#1917). When the local
  `fabrik/issue-N` was missing, Fabrik recreated it from `origin/fabrik/issue-N`. After a
  `fabrik:revalidate`, a reopen or a landing-verification failure, that branch could be
  merged history, giving phantom diffs and conflicts. Fabrik now forks fresh from base, with
  one log line saying why, when the origin tip is already on base, or equals the head of a
  merged PR for the item (its linked PR or its `fabrik:credited-pr:<N>` PR, which covers
  squash and rebase merges). A branch with unmerged commits is still adopted, and so is one
  whose ancestry check fails. Adopting a branch whose open PR targets a different base now
  logs `warn: base mismatch`, naming both. See ADR 1917.
- **`+dirty` dev builds rebuild, and every upgrade check logs its outcome** (#2234). A dev
  build stamped `dev(<sha>)+dirty` was treated as unparseable, so once its checkout was
  pulled it compared as up to date and never rebuilt, with nothing logged. It is now
  compared like a clean build. A dirty build at the same commit as HEAD is still not
  rebuilt, since a rebuild would pick up nothing committed. Each check logs one outcome line,
  and the checkout's dirty paths are logged once per process (up to 10). The code is shared,
  so Pruefer dev builds get the same fix. See ADR 2234.

## TUI

- **The In Progress panel shows items Fabrik is waiting on** (#2238). Open items held on a
  known gate get a row beside the running and `🔒` blocked rows: CI, reviews, a retry or
  time slice, a rebase, a merge-train position, or a human reply. `⏳` marks an external wait
  and `✋` an item that needs you; `✋` rows sort first, and at most 5 rows show, then `+K
  more waiting`. Row text uses only facts the engine already holds, and unknown facts are left
  out. While such waits are open, the header reads `waiting on N item(s)[, M need you]`
  where it used to read `[poll] nothing to do`. Stalled items and red CI are not listed. The rows make
  no GitHub calls. See ADR 2238.

- **Release gate:** two beds, sparse matrix, engine `75ce7aa`, 72 of 72 runnable pairs passed (plus 3 structural skips) over 2 invocations, about 4h40m in total. The first invocation's two failures were harness bugs, fixed in #2282 and #2285 (test code only).

- **This release's gate certifies the second test bed** (#1990). Two beds now run cells
  concurrently in one gate invocation.
  - **Shared harness identity** (#2263). Both beds' harness token is the same user, so bed
    B used to wait for bed A's whole baseline leg. An identity's use is now either engine
    (exclusive) or harness (shared). A second harness holder starts only while the
    identity's remaining GraphQL budget is at least `E2E_SHARED_IDENTITY_FLOOR` of its
    limit (default 40%, `0` disables). Wait lines say whether exclusive use, a reservation
    or the floor is the blocker. See ADR 2263.
  - **The gate stops its bed engine on every exit** (#2245), including a failed suite, a
    watchdog kill, a cancel and a late precondition failure. During the v0.0.84 gate an
    orphaned bed engine kept polling for 13 hours. An engine that predates the invocation is
    left running, with the reason logged. See ADR 2245.
  - **Sim pre-gate diagnostics** (#2247). The sim step prints the running tests with
    elapsed times every 3 minutes and flags slow ones against their last passing duration. A
    test binary that bails writes a goroutine dump first. On failure the summary names the
    failed and still-running tests, and the stream, log and dump are archived under
    `.e2e-coverage/pregate/`. Engine log lines in the sim carry the test name. The gate
    SIGKILLs a sim test binary stuck past its ceiling plus 2 minutes. `cut-release.sh` now
    runs the sim through the new `gate sim` subcommand rather than calling `run.sh`
    directly. See ADR 2247.
  - **`gate report` reads every per-phase stream** (#2257). Since the two-phase legs
    (#1977) it read only `go-test.json` and reported `0s` for every test. It now merges the
    per-phase and retry streams and prints each phase's wall-clock.
- **CI skips the Go suites when a PR changes no Go build input** (#2254). A classifier
  checks the PR's merge diff against a rule table; when every path is skippable, the Go
  steps in the `test` and `worker-shaped` jobs are skipped and the jobs still report
  success, with a "Go tests skipped" job summary. Any doubt runs everything. Files that Go
  tests read (`CLAUDE.md`, the canonical docs, some ADRs) are never skippable, and a guard
  test fails if one is classified skippable. A docs-only merge-train member still lands
  through the singleton fast path. See ADR 2254, which amends ADR 1857.
- **Linux `-race` runs the sim at parallelism 16** (#2228). Measured on CI's 4-vCPU runners,
  `-parallel` 4, 8 and 16 were all crash-free, and sim wall time fell from about 405 s to
  about 182 s. The ceiling stays 4 on macOS, where the fork/exec crash was seen. Sharding the
  sim across CI jobs was measured and rejected: two shards cut wall time by 41% but cost 1.6×
  the runner-minutes. See ADR 2228.
- **Flaky tests fixed**: the local-API supersede tests now wait for the hub to bind the
  first session (#2260); Pruefer's same-session reap tests no longer race their own fixture
  and treat zombies as gone (#2261); and `testenv.IsolateGit` moves the test out of the
  repository, so a worktree's own `credential.helper` or `insteadOf` no longer leaks into
  the HTTPS-credentials tests (#2262).

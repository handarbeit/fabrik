# Fabrik v0.0.77

## Summary

**Review authority now does what it says.** `review_authority: authoritative` was meant to make Fabrik honour a reviewer's verdict — but enabling it was what stopped Fabrik acting on that verdict. A human requesting changes got a blocked gate and an eventual pause, never a fix attempt. Authoritative now governs *merging*, not *working*: Fabrik reinvokes the stage to address the feedback, bounded by `MaxReviewCycles`, and still refuses to merge past an unresolved `CHANGES_REQUESTED`. Review bodies are now read alongside inline threads, which matters because GitHub requires a body on every change request.

**Closed issues are never dispatched again.** An issue closed out-of-band while parked at a gate-checked stage could be re-invoked every poll, indefinitely — one case ran 87 Claude invocations over 14 hours after the issue was closed. Closed items now belong to board-sourced settle scans that reconcile them, never to dispatch.

**Your subscription stays your subscription.** Every stage invocation now runs with the Anthropic auth namespace scrubbed, so no ambient `ANTHROPIC_*` credential can silently redirect a stage from subscription billing to metered API billing. API billing is opt-in via `FABRIK_ANTHROPIC_API_KEY`, and an `apiKeyHelper` found anywhere in the settings chain is refused outright.

Plus meaningfully lower GraphQL cost on busy boards, and Fabrik no longer attempts writes on repos it lacks access to.

## Features

- Anthropic auth namespace scrub: `ANTHROPIC_*` and an enumerated `CLAUDE_CODE_*` auth-selector list are stripped from every worker invocation; `FABRIK_ANTHROPIC_API_KEY` is the sole opt-in for API billing, with `FABRIK_ANTHROPIC_ENV_PASSTHROUGH` as a narrow named allow-list. `apiKeyHelper` hard-fails at startup and per-invocation, with a `fabrik:api-key-helper-detected` label (#1346)
- Repo write-access gating: Fabrik resolves access per repo and skips dispatch, label seeding, and `allow_auto_merge` checks on repos it cannot write to — board-derived upstream repos no longer produce failed (or worse, successful) label writes (#1347)
- `DEPENDS_ON` in `FABRIK_SPAWN_CHILD` blocks, so a decomposing Plan can express ordering between siblings rather than spawning them all unblocked (#1337)
- `LABELS.md` long-tail label reference shipped in the plugin embed, with per-stage hot-subset sections inlined into all 12 skills — consumer projects now receive Fabrik's label vocabulary instead of inheriting it by accident (#1339)
- Engine-side spawn receipt: a decomposing Plan comment is annotated with how many sub-issues were declared and that they do not exist yet (#1338)
- Automatic stale-warning sweep: `allow_auto_merge` and stage-config warnings clear when the repo leaves the board or the condition resolves, instead of persisting until restart (#1348)

## Fixes

- `review_authority: authoritative` reinvokes the stage to address actionable review feedback instead of blocking and pausing; a declared `expected_reviewers` bot no longer preempts a human escalation; review *bodies* are read alongside inline threads (#1375)
- Closed items are never dispatched to a Claude invocation — the Validate settle-owner is now board-sourced and independent of dispatch admission, and the closed-issue transient-label sweep no longer strips the gate label it was deferring (#1387)
- Dev builds no longer permanently disable plugin skill availability via the corrupted-state fingerprint guard (#1297)
- Per-stage token stats no longer report 0k input — cached-context tokens are collected and reported, broken out as cache-read vs cache-write (#1301)
- TUI warnings panel scrolls and windows its selection; the header count no longer exceeds the rendered rows (#1349)
- Review-gate log messaging updated for `expected_reviewers` — speculative lines that predated it no longer misdescribe the wait (#1334)
- `CLAUDE_CONFIG_DIR` is logged at startup and pinned into the subprocess environment; docs no longer claim Fabrik does not read it (#1350)

## Improvements

- `fabrik:paused` now suppresses deep-fetch admission, not just dispatch — a parked item costs no per-item GraphQL read while it sits, so setting work aside is genuinely cheap. Removing the label re-admits within one poll (#1379)
- The `CIWaitTimeout` backstop no longer duplicates `checkCIGate`'s `FetchLabels` call (#1314)
- Label-applied-at is recorded at write time and cached, removing repeated `FetchLabelAppliedAt` calls from the review-gate timers
- Review resolution is memoized per evaluation, eliminating redundant `FetchPRReviews` calls across the gate and landing paths

## Internal

- e2e suite hardening: removed a vacuous scenario, strengthened `TestNoWorkNeeded` to assert the engine's skip comment, added a discriminating-observable authoring rule, and added per-test wall-clock reporting (#1355)

## Upgrading

```bash
# Auto-upgrade from a running Fabrik instance
# Fabrik checks for new releases each poll cycle and upgrades automatically with --auto-upgrade

# Or download directly (auto-detects OS and architecture)
gh release download --repo handarbeit/fabrik \
  --pattern "fabrik_*_$(uname -s | tr A-Z a-z)_$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/').tar.gz" \
  -O - | tar xz
```

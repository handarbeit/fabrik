# Fabrik v0.0.92

## Summary

**Hookdeck is gone; webhooks come straight from your GitHub App.** The Hookdeck transport
has been removed from Fabrik and Pruefer. Use `event_source: tailscale` (an embedded Funnel
node) or `event_source: direct` (your own listener) with the GitHub App instead. A config
that still says `event_source: hookdeck` is refused at startup with a pointer to the
migration guide, and leftover `hookdeck_*` settings are ignored with a single notice.
**This is a breaking change: see "Upgrading" below before you upgrade.**

**Pruefer listens for webhooks too.** Pruefer now supports `event_source: direct` and
`tailscale` on the same shared receiver as the engine. It checks the installation, dedupes
deliveries and replays failed ones.

**Labels and locks that stick.** When an engine label write fails ambiguously, Fabrik now
checks the live labels and re-applies the write if it did not land. A lock left behind
with no worker is reclaimed at runtime. Bot comments are no longer treated as feedback
unless the bot is opted in, and a merge-train trial's CI result is acted on within one poll.

## Breaking changes
- **Hookdeck removed** (#2477). `event_source: hookdeck` is refused at startup by both Fabrik and Pruefer. To migrate:
  1. Set `event_source: tailscale` (set `tailscale_hostname` and an auth key in `FABRIK_TS_AUTHKEY`), or set `event_source: direct` with `direct_listen`. Both need GitHub App auth.
  2. Point the App's webhook URL at the new receiver. The webhook secret stays in `FABRIK_GITHUB_WEBHOOK_SECRET`.
  3. Remove the `hookdeck_*` keys and `FABRIK_HOOKDECK_*` / `PRUEFER_HOOKDECK_*` variables when convenient. Until then they are ignored and reported in one startup notice, and their secrets are still kept out of worker environments.

  See "Migrating from Hookdeck" in the User Guide and `cmd/pruefer/README.md`.

## Features
- Pruefer `event_source: direct` and `tailscale`: one shared App receiver with an installation ownership check, dedupe, replay and route liveness, plus a footer health segment (#2476)
- Stage key `feedback_bots`: a bot's PR conversation comments count as feedback only when the bot is opted in, either here or as an expected reviewer (#2552)
- `fabrik init` without `--create-board` lists the board columns your stages need and no longer claims Fabrik is ready (#2496)

## Fixes
- An engine lock or state label that GitHub reports written but that never lands is confirmed against live labels and re-applied once; a stage advance is refused while its completion label is in doubt (#2551)
- An ambiguous lock-label write is reconciled against live labels, and an orphaned lock with no worker is reclaimed after a grace period and reported as `lock-orphaned` (#2550)
- A merge-train trial's CI verdict is acted on within one poll instead of up to a full idle interval (#2542, a known issue in v0.0.91)
- A leftover `MERGE_RR.lock` no longer breaks the poisoner re-merge, and a new trial resets the claim's CI result (#2542)
- The Tailscale node listens on the public Funnel only, never on its tailnet address (#2553)
- App webhook server errors go to the engine log instead of stderr, and TLS handshake failures are counted in the transport health row instead of spamming the log (#2549)
- Under GitHub App auth, the HTTPS-vs-SSH git decision is made once at startup (#1860)
- First run: an empty board is concluded once and retried quietly, the multi-repo scope is worded correctly, and the shipped Review/Validate stages declare `expected_reviewers: []` (#1894)

## Improvements
- The App webhook receiver is a shared package used by both the engine and Pruefer (#2475)
- The live e2e gate guards the reviewer token's rate-limit budget before and during a run (#2536)
- Documentation updated for v0.0.91 (#2547)

## Known issues
- A Tailscale Funnel outage that does not drop the tailnet connection triggers no delivery replay, and route liveness may still report the route reachable. Deliveries lost during the outage are picked up by the next poll instead of at once.

## Upgrading

```bash
# Auto-upgrade from a running Fabrik instance
# Fabrik checks for new releases each poll cycle and upgrades automatically with --auto-upgrade

# Or download directly (auto-detects OS and architecture)
gh release download --repo handarbeit/fabrik \
  --pattern "fabrik_*_$(uname -s | tr A-Z a-z)_$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/').tar.gz" \
  -O - | tar xz
```

**If you use `event_source: hookdeck`, migrate before upgrading** (see Breaking changes). With `--auto-upgrade`, the new binary refuses to start on that config.

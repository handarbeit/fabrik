# Fabrik v0.0.80

## Summary

**A correctness release, and an urgent one.** Under merge-train mode, Fabrik could close an
issue as `COMPLETED` — board moved to Done, PR closed, a comment citing the batch that
landed it — when the work had never merged at all. Every signal read green, which is what
made it dangerous: nothing was red, so nothing revisited the item, and the branch survived
only because nothing had deleted it yet. If you run with `merge_train: on`, upgrade.

Two changes address it. The first removes the cause: the merge train now identifies its own
integration PR structurally, by the trial branch it created, instead of by a marker that
every merge-train PR carries in any state — so a different batch's already-merged PR can no
longer be mistaken for this one's. The second is cause-agnostic: after any Done transition
credited to a merge, Fabrik now verifies the credited PR actually merged, and reopens the
issue with an explanation if it didn't. The first fixes the bug we found; the second catches
the next one, whatever its cause.

Also in this release: **fabrik-project-onboarding**, an optional marketplace plugin that lets
a product manager or business owner author GitHub Spec Kit specifications with no terminal,
git, or engineering background.

## Features

- **`fabrik-project-onboarding` plugin** — three skills (`onboard`, `write-spec`, `clarify`)
  for authoring Spec Kit specifications in Claude Cowork or the desktop app, with no
  engineering background required. Output is a standard `specs/NNN-feature/` folder that
  stays byte-compatible with upstream Spec Kit, so it can be handed to Fabrik or to any
  development team. Optional and not installed with Fabrik; adapted from
  [github/spec-kit](https://github.com/github/spec-kit) (MIT), with full attribution in
  `NOTICE.md`.

## Fixes

- **Merge train could close an issue as `COMPLETED` with the work unmerged** (#1615).
  `findIntegrationPR` matched on a marker carried by every merge-train PR in every state, so
  it returned "the most recently updated merge-train PR in this repo" rather than this
  trial's. When the match was a *different* batch's already-merged PR, the merge was skipped
  as already done and the member's issue and PR were closed anyway, citing a batch containing
  none of their changes. The integration PR is now identified by the trial's own branch; a
  closed-unmerged trial fails loudly instead of landing; a batch that dropped a member can no
  longer claim it; and the "landed via batch #N" comment is only emitted once PR #N is
  observed merged. The same structural-identity rule now also governs the reconstruct sweep,
  which could close an unrelated PR whose description merely quoted the marker.

- **Nothing verified that work advanced to Done had actually landed** (#1616). A false
  `COMPLETED` was undetectable: no dispatch path revisits a Done item, so there was no signal
  to act on. Fabrik now runs a post-Done settle scan that confirms the credited PR really
  merged, honours `base:<branch>`, and — on a confirmed failure — reopens the issue, moves it
  off Done, labels it, and comments naming the branch, the base, and the PR that was
  credited. It is deliberately conservative: anything inconclusive retries rather than
  reversing a landing.

- **Two dead configuration keys removed, and two documents corrected** that described the
  opposite of the actual behaviour (PR #1606).

## Upgrading

```bash
# Auto-upgrade from a running Fabrik instance
# Fabrik checks for new releases each poll cycle and upgrades automatically with --auto-upgrade

# Or download directly (auto-detects OS and architecture)
gh release download --repo handarbeit/fabrik \
  --pattern "fabrik_*_$(uname -s | tr A-Z a-z)_$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/').tar.gz" \
  -O - | tar xz
```

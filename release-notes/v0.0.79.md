# Fabrik v0.0.79

## Summary

A stability release focused on the ways Fabrik could quietly stop making progress. Several
paths could pause a healthy issue, or spin without dispatching, for reasons that were correct
in isolation but wrong in combination — a PR that was linked fine but checked too early, a
worker blocked by a tool permission rather than a real failure, a merge-train member stranded
in a batch nobody would land. Each of those now either recovers on its own or says clearly
what happened.

The other half is honesty about configuration. `config.yaml` no longer discards keys it doesn't
recognise, so a knob set in the wrong place is reported at startup instead of silently doing
nothing; stage workers no longer stall on harness tools they were never meant to reach; and CI
now enforces formatting it had never checked.

## Fixes

- Issues are no longer paused after Implement because GitHub hadn't yet derived a PR's
  closing-issue link. The verification re-read an asynchronous field in the same moment it was
  written, then treated the stale answer as definitive; it now confirms against the PR body,
  the way the non-default-branch path already did (#1598)
- A worker blocked by the CLI's permission layer is no longer counted as a failed stage against
  `max_retries` — it never ran. Bounded separately by `--max-tools-denied-retries` (#1523)
- The merge-train runaway guard now always posts the alert explaining why it paused a member,
  instead of pausing with no stated reason (#1533)
- A merge-train member paused for its own validation failure is no longer stranded in the
  holding column, unreachable by any stage (#1545)
- `ensureRepoReady`'s clone retry no longer elects a second owner on failure, which duplicated
  the clone and its comment; a wedged repo now escalates once per episode instead of silently
  skipping forever (#1543)
- Successful-but-no-op comment re-invocations are now bounded by a success-agnostic circuit
  breaker, so a loop that makes no progress can't run indefinitely (#1555)

## Improvements

- `.fabrik/config.yaml` reports unrecognised keys at startup instead of discarding them
  silently, naming the CLI flag or environment variable to use when the key corresponds to a
  real knob (#1544)
- `Monitor` and `CronCreate` are refused for stage workers alongside `ScheduleWakeup` and
  `Workflow`. All four promise delivery to a future turn that a headless stage cannot provide;
  the list now has a stated membership test rather than a hand-maintained enumeration (#1558)
- Review and Validate rebase onto the branch an issue actually targets, and push the result
  rather than resetting it away — previously a `base:<branch>` issue could have its rebase
  discarded, or worse, published against the wrong base (#1554)
- CI now enforces `gofmt`, which it had never checked (#1573)

## Internal

- Test-bed and e2e-harness work: the release gate now verifies the bed runs the engine under
  test before starting, scenarios that exhaust a shared repo's state run in their own leg, and
  several scenarios were corrected where they asserted behaviour the engine never promised.
  Plus cache-freshness documentation (#1551) and GraphQL budget instrumentation for the
  validation gate (#1527).

## Upgrading

```bash
# Auto-upgrade from a running Fabrik instance
# Fabrik checks for new releases each poll cycle and upgrades automatically with --auto-upgrade

# Or download directly (auto-detects OS and architecture)
gh release download --repo handarbeit/fabrik \
  --pattern "fabrik_*_$(uname -s | tr A-Z a-z)_$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/').tar.gz" \
  -O - | tar xz
```

# Fabrik v0.0.82

## Summary

**A reliability release for Fabrik's own release process.** Cutting v0.0.81 took eleven
attempts, and the code being released was never once at fault — every failure was the test
harness: a run that hung silently for seventeen hours, a test bed whose accumulated state
outgrew a fixed timeout, a parallelism cap that missed the path CI actually uses, and a
duplicate pre-gate that made every release win the same flaky coin toss twice.

Those are fixed here, along with the discipline that found them. Three separate guards this
cycle turned out to be deletable without failing a single test — their logic was covered, the
wiring that invokes them was not — so neutralization (break the guard, prove the test goes red)
is now part of what the Review stage does by default.

Almost all of this is internal tooling. Two things users will see: Review now applies that
neutralization check to guards it reviews, and the merge train's new single-member fast path
finally says so on the PR it lands — it had been merging silently.

## Fixes

- **The merge train's single-member fast path landed silently** (#1692). v0.0.81 added it (#1644)
  as a fourth landing path and wired it into neither of the train's two observability channels:
  no `🏭 Fabrik merge-train — Landed …` comment on the member's PR, and no repo-scoped
  `landing complete` line. So it merged PRs correctly and invisibly — the PR carried no record
  of what merged it or what validated it, and from the log alone the train looked like it had
  started and never finished, with nothing on its TUI row. Both are now emitted. The comment's
  shape differs by design: the fast path cites the member's *own* PR, because under that path
  that PR is the merge vehicle — there is no separate integration PR to name.

## Improvements

- **The Review stage now verifies guards by neutralization** — when a change adds a guard,
  Review is asked to identify which mutation the new test catches and confirm it actually fails.
  Three guards this cycle were deletable with no test failing, in each case because the test
  asserted the *outcome* rather than the *reason*, so any rejection satisfied it (#1687).

## Internal
- ⚠️ Live e2e integration suite SKIPPED for this release: live e2e gate run in full against this exact ref (819c48e2) immediately before this cut, but across three invocations rather than one pass: every leg green, 0 test failures (off 47 tests; on 46 tests, package pass; isolated runaway-guard leg PASS rc=0). A clean single-shot run is blocked on this host by two release-gate defects found during this cut and filed as #1693 and #1694 — see this release notes file's Internal section for the full per-leg detail and caveats.

- **The e2e runner can no longer hang silently** (#1676). Its GitHub API budget probes had no
  timeout at all — `|| echo ""` guards a *failing* call, not a *hanging* one — so a stalled
  connection blocked the release script indefinitely. Probes are now bounded, a post-suite
  watchdog fires if the script stops progressing after `go test` exits, and a stall detector
  reports when output goes quiet. A gate that fails loudly costs an hour; one that hangs
  silently cost a night.
- **Four release-gate defects fixed together** (#1677): the release path now resets the test bed
  rather than letting state accumulate until startup outgrew the mode-switch's lock window;
  `-parallel` is capped on the repo-wide `-race` run in both the release script and CI, via a
  shared helper, closing the path that still crashed under ThreadSanitizer's fork handling; the
  measured parallelism band is recorded in an ADR; and the pre-gate SHA guard that was supposed
  to stop the suite running twice per release now actually engages.
- **The gate checks its own preconditions** (#1684). It detects another process competing for
  the same GitHub token before spending live budget, and verifies the review bot is reachable
  before starting a run whose scenarios depend on it — previously both were discovered only
  after an hour of work. The operational contract (what must be up, what must be down, and the
  measured budget cost of a leg) is now documented rather than folklore.
- Documentation refresh for v0.0.81 (#1680).
- ✅ Live e2e integration suite: **every leg green against this exact ref (`819c48e2`), 0 test
  failures**, but across three invocations rather than one pass — a clean single-shot run remains
  blocked on this host by two release-gate defects found during this cut, both filed. Coverage:
  sim + wire-contract pre-gate (295s); **off leg** 47 tests, 0 fail; **on leg** 46 tests, 0 fail,
  package `pass` (4620s) — all six merge-train scenarios green (HappyPathLanding,
  TwoBasesConcurrent, BisectionEjectsPoisoner, RestartSafety, RedSingletonReroutesOffQueued,
  YoloAutoMergeLabel); **isolated runaway-guard leg** PASS (362s, rc=0). The off leg's
  `RUN INVALID` fired on GraphQL backoff *after* every test had already passed — backoff can only
  manifest as a failure or timeout, and there were none. Newly filed, not fixed here: #1693
  (`E2E_BED_REF` unusable for any ref but `main`, since the bed is a single-branch clone — this
  caused one verification run to silently build the bed from the *unfixed* engine) and #1694 (a
  post-suite output-drain stall aborts the run before its remaining legs, which silently skipped
  the runaway-guard leg entirely). Both are the same family as #1676/#1677: the release gate's own
  failure modes being quieter than the failures it exists to catch.

## Upgrading

```bash
# Auto-upgrade from a running Fabrik instance
# Fabrik checks for new releases each poll cycle and upgrades automatically with --auto-upgrade

# Or download directly (auto-detects OS and architecture)
gh release download --repo handarbeit/fabrik \
  --pattern "fabrik_*_$(uname -s | tr A-Z a-z)_$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/').tar.gz" \
  -O - | tar xz
```

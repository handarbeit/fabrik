# Fabrik v0.0.90

## Summary

**Webhooks without a relay.** Under GitHub App auth the daemon can now receive App
webhooks itself, with no Hookdeck and no `gh webhook forward`:

- `event_source: direct` is a plain HTTP receiver you put behind your own tunnel or proxy.
- `event_source: tailscale` embeds a Tailscale node in the daemon. The daemon joins your
  tailnet as its own machine and serves its own Funnel endpoint, so each daemon's public
  exposure can be seen and revoked on its own.

Both share the delivery intake's dedupe and ordering.

**Nothing lost while the daemon is down.** On start and on every reconnect, the direct
and Tailscale receivers find deliveries GitHub failed to deliver in the App's delivery
log and ask GitHub to send them again. Duplicates are dropped by delivery ID.

**Health you can trust.** `fabrik_health` reports whether GitHub can actually reach the
receiver, judged from GitHub's own delivery log. It no longer guesses from public DNS,
which some networks block or intercept.

## Features
- `event_source: direct`: an App webhook receiver that runs behind any tunnel or proxy (#2142)
- `event_source: tailscale`: an embedded Tailscale Funnel receiver, one tailnet node per daemon via `tsnet`, included in every build (#2143)
- Failed App webhook deliveries are replayed on start and on reconnect for the direct and Tailscale receivers (`replay_failed_deliveries`, default on) (#2144)
- Webhook route liveness: `fabrik_health.webhook.transports[].route` is `reachable`, `unreachable` (with GitHub's reason) or `unknown`. It comes from the App's delivery log and, when nothing recent decides it, from a test redelivery that the dedupe never applies. An unreachable route held for 10 minutes raises `webhook_route_unreachable` (#2452, superseding #2425)
- `fabrik_health.webhook.intake` counts accepted, duplicate, dropped, echo-matched and applied deliveries (#2427)

## Fixes
- A review-thread resolution delivered by webhook now drops thread comments that arrived by webhook before the next deep fetch gave them a thread ID (#2444)
- Channel label announcements around a SIGHUP restart are sent exactly once and keep their attribution (#2450)

## Known issues
- With webhooks and the merge train both on, a delivery for the train's integration PR can be attached to one member, briefly overwriting that member's cached linked PR. Landings are unaffected (#2483)
- A label delivery the intake accepted just before a SIGHUP restart may not be applied until the next reconcile, and is then announced with `actor=unknown`. The live test for it is a known skip in this release (#2484)

## Upgrading

- **Direct App webhooks** need GitHub App auth. Set `event_source: direct` or
  `event_source: tailscale` and the webhook secret (`FABRIK_GITHUB_WEBHOOK_SECRET` by
  default), and point the App's webhook URL at the receiver. For Tailscale, also set
  `tailscale_hostname`, and set an auth key (`FABRIK_TS_AUTHKEY`) for the first start.
  The node logs the webhook URL once it is up. See the User Guide's "Direct App Webhook
  Receiver" and "Embedded Tailscale Funnel Receiver" sections.
- **Binary size:** every build now includes the Tailscale node, so the binary is about
  35 MB.

```bash
# Auto-upgrade from a running Fabrik instance
# Fabrik checks for new releases each poll cycle and upgrades automatically with --auto-upgrade

# Or download directly (auto-detects OS and architecture)
gh release download --repo handarbeit/fabrik \
  --pattern "fabrik_*_$(uname -s | tr A-Z a-z)_$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/').tar.gz" \
  -O - | tar xz
```

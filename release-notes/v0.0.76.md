# Fabrik v0.0.76

## Summary

This release makes **review authority a first-class control**, separate from autonomy. Until now `fabrik:yolo` meant "advance and merge" regardless of what reviewers said; a stage can now be marked `review_authority: authoritative`, and Fabrik will honour an outstanding `CHANGES_REQUESTED` or unmet required-approval count — yolo and cruise control *timing*, never whether the verdict is respected.

It also fixes a long-standing stall for anyone using a self-submitting review bot. Pruefer, Gemini and CodeRabbit never appear in GitHub's requested-reviewer list, so a `wait_for_reviews` gate could wait forever for a review that had, in fact, already arrived. Stages can now declare `expected_reviewers`, or declare `expected_reviewers: []` to advance immediately instead of waiting out a timeout that can never clear.

The rest is reliability work, much of it from real incidents: Claude usage limits are now detected structurally and no longer burn retry budget, a runaway comment-loop that once cost hundreds of wasted invocations is now broken by a circuit breaker plus bot-notice filtering, issues on a non-default `base:<branch>` finally close on merge, and several ways an issue could silently stall mid-pipeline — CI-gate convergence, stuck workers, orphaned state labels — now escalate visibly instead of sitting there.

## Features

- `review_authority: advisory | authoritative` — stages can require a genuine review verdict before advancing or merging; `yolo`/`cruise` never bypass it (#1250)
- `review-authority:<mode>` label — override review authority per issue without editing stage config (#1261)
- `expected_reviewers` — declare self-submitting review bots so the gate waits for them, or `expected_reviewers: []` to fast-advance when none are expected (#1283)
- `expected-reviewers:<mode>` label — per-issue override of the declared reviewer set (#1298)
- Stage agents now receive `FABRIK_ISSUE`, `FABRIK_REPO`, `FABRIK_WORKTREE`, `FABRIK_ROOT` and `FABRIK_PR` in their environment (#1288)
- Every worker is given a `--name` session sentinel, making concurrent Claude invocations identifiable in `ps` and in session logs (#1284)
- `required_status_contexts` — gate on classic commit statuses that produce no check runs, for repos whose CI is not check-run based (#933)
- Automatic plugin-version bumping, so deployed skills track the binary (#816)

## Fixes

- Claude account usage limits are detected structurally from the CLI's own exit reason rather than from output prose; the hit no longer counts against `max_retries`, and an account-wide suspension clears without an engine restart (#1119, #1183)
- Runaway comment loops are broken by a comment-processing circuit breaker, a bot service-notice filter, human-only pause/resume, and neutralised outbound bot mentions (#1089)
- Issues on a non-default `base:<branch>` now close when their PR merges, with a durable retry if the close fails (#1096, #1097)
- `fabrik:awaiting-ci` items no longer strand indefinitely: a dedicated settle scan evaluates them independently of the main admission path, with a `CIWaitTimeout` backstop that escalates regardless of which gate is claiming the item (#1270)
- Stalled stages are detected and correctively re-invoked instead of hanging (#1146)
- The review gate is now evaluated at the landing decision as well as the advance decision, closing a race where an item could merge a poll before its gate armed (#1216)
- Yolo auto-merge no longer proceeds past unresolved review threads on the current head (#1207)
- `MergePR` self-gates on `mergeable_state`, so a PR GitHub is still computing is retried rather than treated as unmergeable (#1094)
- Turn-limit exits are classified correctly and no longer conflated with genuine stage failures (#1178)
- A session janitor reaps orphaned worktrees, stale locks and abandoned sessions (#1136)
- Merge train: CI completeness is judged on required checks rather than `mergeable_state` alone, worker liveness detection is consolidated, and generated files are regenerated during trial assembly (#1153, #1222, #1235)
- Cache staleness at correctness-critical decision points is resolved with a live re-read rather than a possibly-stale snapshot (#957)

## Improvements

- Review-gate pause messages name the real reason — an outstanding verdict, or genuinely no reviewers — instead of a misleading "no reviews submitted yet", and offer actionable exits (#1216)
- Release artifacts are verified to carry the expected `vcs.revision`, so a published binary can be traced to its commit (#071)
- Self-upgrade logic is extracted into a reusable package shared by Fabrik and Pruefer (#1196)

## Internal

- Pruefer, the self-hosted PR-review daemon, gained multi-installation GitHub App auth, inline review comments, and severity-gated review verdicts; plus extensive e2e coverage additions, engine test hardening, and documentation regeneration across the board.

## Upgrading

```bash
# Auto-upgrade from a running Fabrik instance
# Fabrik checks for new releases each poll cycle and upgrades automatically with --auto-upgrade

# Or download directly (auto-detects OS and architecture)
gh release download --repo handarbeit/fabrik \
  --pattern "fabrik_*_$(uname -s | tr A-Z a-z)_$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/').tar.gz" \
  -O - | tar xz
```

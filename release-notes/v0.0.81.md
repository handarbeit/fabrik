# Fabrik v0.0.81

## Summary

**The merge train grew up.** Three changes reshape how it works. It now runs **one train per
base branch** rather than one per repo, so a maintenance release on `maint/1.2` batches and
lands onto `maint/1.2` — previously a `base:<branch>` member would have been forked from the
default branch and had its integration PR opened against it, landing release-line work in the
wrong place, silently. It now **skips the trial entirely** for a single member that is already
a fast-forward of the pinned base with its own CI green and complete, which removes a whole
redundant CI cycle from the common case. And it is finally **visible in the TUI**, as an
ordinary job row alongside the stages, instead of writing its progress into a status line the
next event overwrote.

Also here: Pruefer gains repo-resident configuration, installation-derived repo discovery, and
config reload without a restart.

## Features

- **Merge train: one train per resolved base branch** (#1648). Queued members are partitioned
  by `base:<branch>` and an independent train runs per `(repo, base)` — its own pinned base
  SHA, trial branch, integration PR and guards. Members without a `base:` label are bucketed
  under a sentinel that never touches git at grouping time, so the default path is unchanged
  and cannot fail closed on a transient git hiccup.

- **Merge train: single-member fast path** (#1644). When a batch is down to one member whose
  head already contains the pinned base (a fast-forward, so the trial's tree would be
  identical), whose PR is mergeable, and whose own CI is green *and complete*, Fabrik lands
  that PR directly instead of building and re-validating a trial. Gated strictly on positive
  evidence — any ambiguity falls through to the unchanged trial path.

- **The merge train appears in the TUI** (#1661). It emits a job row like a stage does, keyed
  by repo, showing the batch's members and updating as it moves through assembly, CI and
  landing. Repo-level log lines are now routed to that row instead of a single-line header
  that the next event overwrote.

- **A comment names the PR when `base:<branch>` suppresses GitHub's linkage** (#1649). GitHub
  creates *no* issue↔PR link at all for a PR targeting a non-default base — not merely no
  auto-close — so the issue's Development panel shows nothing. Fabrik now posts a one-time
  comment naming the PR. Informational only: it gates nothing and carries no retry.

- **Pruefer: repo-resident configuration** (#1642), resolved at the PR's base ref, so a
  repository can carry its own review settings.

- **Pruefer: installation-derived repo discovery** (#1641). The watched repo set is derived
  from GitHub App installations rather than hand-listed, with `max_derived_repos` and
  `repo_rederivation_interval` to bound it.

- **Pruefer: config reload without a restart** (#1640), via SIGHUP.

- **Pruefer: per-user GitHub App auth reconciler** (#1253) — manifest flow, no shared key.

## Fixes

- **The merge train ignored `base:<branch>`** (#1646, reported by the community; fixed by
  #1647 and #1648). It resolved its base once from the repository default and never consulted
  each member's label, so a `base:`-labelled member would fork its trial from the wrong base
  and open its integration PR against the wrong branch. The failure was silent and landed in
  the wrong place rather than erroring. #1647 shipped the immediate safety measure — exclude
  such members from batching, log it, and comment on the issue so the operator sees it —
  and #1648 replaced that exclusion with proper per-base batching.

## Upgrading

```bash
# Auto-upgrade from a running Fabrik instance
# Fabrik checks for new releases each poll cycle and upgrades automatically with --auto-upgrade

# Or download directly (auto-detects OS and architecture)
gh release download --repo handarbeit/fabrik \
  --pattern "fabrik_*_$(uname -s | tr A-Z a-z)_$(uname -m | sed 's/x86_64/amd64/' | sed 's/aarch64/arm64/').tar.gz" \
  -O - | tar xz
```
